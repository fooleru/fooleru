## 1. 概述（Overview）

> **⚠ 定位声明（R-25）**：本系统**只管两件事**——① **玩家自建的次级换图触发器（逃生绳索）**；② **基地电梯井枢纽（D2 小站式楼层传送）**。
> **本作没有"垂直交通系统"这个独立系统**——楼梯间（主通道）由 procedural-gen 定义，绳索与电梯井由本系统定义。**"三种垂直交通并存"的旧写法已作废**（见 §3.10.1）。

垂直通道系统把"楼层之间只有楼梯间一条通道"的单通道模型，扩展为**玩家可自建、可多处的次级换图触发器网络**。生成期由**存档级垂直骨架（VerticalSkeleton）**决定贯穿井位（shaft cell）；逐层填充时**以骨架为硬约束**生成井道结构，保证**跨层坐标契约**（§3.10.2）。玩家在**锚点瓦片**（地板裂缝 / 电梯井 / 破损外墙·窗 / 管道井）上**安装逃生绳索**，使用后切换到**下层同 (x,y) cell 坐标**；绳索**双向**可攀爬（上行 −50% 速度）。

本系统的设计价值有四：① 为下层探索提供**多个脱出口**，降低"主通道被堵/绕远"的挫败（P1 逃生感）；② 让"撤"从"必须沿楼梯间原路返回"变为"可自建逃生路线"，强化 P6「撤即经营」的空间维度；③ 绳索落点由生成器决定（可能安全、也可能直落敌群/Boss），构成新的**风险回报**决策；④ **（R-25 新增）基地电梯井枢纽**把"重复探索已解锁楼层"的**换图次数**从 O(层数) 压缩为 O(1)，直接服务于 §P1「单局 25–40 分钟」的时长预算（见 §3.9）。已安装绳索属 **② 存档级持久层**，跨死亡/**跨探索（run）** 永久保留。**R-20 后其价值进一步跃升为战略道具**（敌人随探索复活，绳索是唯一能绕过复活敌群的手段，见 §3.6/§3.8）。

> **R-25 换图触发器总览（取代"三种垂直交通"旧表）**：
> | 触发器 | 覆盖 | 方向 | 成本 |
> |---|---|---|---|
> | 🪜 楼梯间（主通道，procedural-gen 定义） | **相邻层** F↔F±1 | **双向**（可上可下） | 清敌 + 迷路 + 换图耗时（R-20：会被复活敌群重堵） |
> | 🧵 逃生绳索（本系统 · 自建次级） | **相邻层**（下层，落同 cell） | 双向，上行 −50% | `RopeCable ×1` / 次安装 |
> | 🚪 电梯井（本系统 · D2 小站式传送） | **基地 ↔ 任意已解锁层** | **两端各自单向（非对称）** | 首次 `RopeCable ×1`；乘坐 **免费**；**楼层端脱出需等倒计时 `(100−floor)×1.0 s`**（§3.9.5） |
>
> **⚠ 三者都是"换图触发器"（切图），不是"空间通道"**（本作单层载入，见 §3.9.0）。
> **⚠ 与其它两者的最大差异（R-25 三次新增）**：**只有电梯井的楼层端脱出需要"等候"**——楼梯间与绳索是**即时切图**，电梯井是**"呼叫绳索 + 坚守等待"**。**这是把"撤"的最后一段做成可被惩罚的战斗窗口**（§3.9.5）。

## 2. 目标（Goal）

- G1：提供次级下行触发器，允许玩家自建**多个脱出口**，削弱单通道结构带来的挫败（P1）。
- G2：跨层**坐标契约**严格可保证——同存档任意相邻两层 shaft cell 坐标集合**完全一致**；切图落点在目标层 **100% 可达**（§3.10.2）。
- G3：风险回报——绳索落点可能通往下层安全区，也可能直落敌群/Boss 附近，由生成器决定（非纯惩罚）。
- G4：**不侵蚀楼梯间主通道价值**——绳索上行 −50% 速度，且普通敌人不会使用绳索。
- G5：性能——骨架生成 + 落点校验的耗时增量 **< +10ms / 层**。
- **G6（R-25）**：**电梯井把"重复探索的换图次数"从 O(层数) 压缩为 O(1)**，且**不产生"贪搜零风险"循环**（靠**非对称能力**保证，见 §3.9.1 / §3.9.7）。
- **G7（R-25 三次）**：**脱出不是"紧急按钮"**——楼层端脱出**必须付出"坚守等待"的代价**（`(100 − floor) × 1.0 s`），使 **P6「撤即经营」的紧张感在最后一段被保住**；且**等待时长随深度加速增长**（浅层近乎无感、深层显著变重），与 R-23「越深越难」同向。见 §3.9.5。

## 3. 核心机制（Core Mechanics）

### 3.1 VerticalSkeleton（存档级垂直骨架）

**世界生成顺序（改写 procedural-gen §3.3）**：

```
GlobalSeed
   → [GenerateVerticalSkeleton]（存档级，生成一次，固化）
   → [PerFloorFill]（骨架作为硬约束注入逐层填充）
   → [ValidateLanding]（落点可达校验 + 邻域兜底）
   → Ready
```

- **cell 划分**：每个楼层平面按 `cell = 8×8 tile` 划分为粗格（**R-25 用户拍板：`FloorGridTiles = 128×86 tile` → 16×10 = 160 cell**，由 R-22 的 96×64 升档；`FloorGridTilesScaling`「越深越大」**仍为预留**，见 procedural-gen §4.7 与本节 §4 常量块）。
- **确定性**：`SkeletonRNG = RNG(Hash(GlobalSeed, "VERTICAL_SKELETON"))`；由它抽取决定的 shaft cell 集合：
  ```
  ShaftCellCount = clamp(3 + floor(SkeletonRNG01 × 5), 3, 7)          // 存档级常量，∈[3,7]（R-25 由 [2,5] 升档）
  ShaftCellSet   = SkeletonRNG 无重复抽取 ShaftCellCount 个 (cx,cy)   // 排除边界 cell（预留邻域）
  ```
- **固化**：`ShaftCellSet` 在**存档创建时生成一次**并落盘；该存档内**所有楼层共用、永不变更**（与 P0-01「按存档永久固化」同构）。
- **对齐策略**：**严格同 (x,y) cell**，不做跨层偏移表。floor F 的某 shaft cell → floor F−1 的**同 (cx,cy) cell**。

### 3.2 每层生成约束与落点兜底

- 对 floor ∈ [1, 99]：`ShaftCellSet` 中每个 cell **必须**生成为"井道类结构"（井道 + 相邻可站立落点平台）。
- **骨架为硬约束**：房间/走廊生成须**绕开或容纳** shaft cell，不得覆盖井道；冲突时**以骨架优先**（房间局部重排，不重投整层）。
- **落点可达校验（生成后 BFS）**：
  | 校验结果 | 处理 |
  |---|---|
  | 落点可站立且与出生点/楼梯间主通道连通 | 记录落点瓦片坐标到世界状态层 |
  | 不通过 | **在该 cell 邻域局部强制开平台/房间**并打通到主通道（**兜底，不重投整层**，保 G2/G5） |

### 3.3 锚点瓦片（Anchor Tiles）

四种特殊瓦片，均属**可安装绳索的锚点瓦片**；**非锚点瓦片上禁止安装**：

| tile id | 名称 | 语义 | 锚点 |
|---|---|---|---|
| `floor_crack` | 地板裂缝 | 地板开裂、可窥望下层 | ✅ |
| `elevator_shaft` | 电梯井 | 灾变后废弃的电梯井道 | ✅ |
| `exterior_breach` | 破损外墙 / 窗 | 外墙破损 / 破窗，可挂绳垂下 | ✅ |
| `utility_shaft` | 管道井 | 管道 / 通风井（**可选，B 档**） | ✅ |

- **放置规则**：锚点瓦片**只能落在 shaft cell 内**——这是"跨层对齐可保证"的根因；锚点**不与房间功能瓦片重叠**（此处"房间功能瓦片"**不含**楼梯间/主通道出口房——主通道所在 cell 已在**骨架阶段**从 shaft cell 候选中剔除，二者**结构上不会同格**，见 §6.8 / procedural-gen §3.3 步 0）。**多格锚点**（footprint > 1 tile）：**`elevator_shaft` 是唯一的 2×2 多格锚点**（32×32，占 4 tile；见 asset-spec §1.3），其 footprint 须**完整落在同一 shaft cell（8×8 tile）内、不得跨 cell 边界**（否则破坏对齐）——**这正是 AC10 的断言对象**；其余 3 类（`floor_crack` / `exterior_breach` / `utility_shaft`）均为单格瓦片，天然满足。
- 美术规格：art-bible §10.2（垂直通道可读性：电青 `#45d4e0` + 绳结/双下箭头⤓，**禁通行绿**）/ asset-spec §1.3 与锚点瓦片表（`tiles_shared_prop_floor_crack_01` 等）。
- **锚点密度（每层）**：`AnchorsPerFloor(floor) = clamp(ShaftCellCount + floor(descentDepth / 34), 2, 5)`（⚠待调，随 depth 变化）。

#### 3.3.1 锚点瓦片物理语义（R-11 新增 · 裁决 P2-3）

> 补齐"井道/锚点瓦片在**移动碰撞**与**视线 LOS** 中如何表现"的约定——此前 `combat`（可碰撞空间 = 墙/掩体/出口）与 `fog-of-war`（1×1 三态瓦片）均未覆盖。**同时消解"必须站在锚点上安装"与"井道 = 洞"的直觉张力。**

| tile id | 移动（可行性） | LOS / 子弹 | 未安装绳索时 |
|---|---|---|---|
| `floor_crack` | **可行走**（特殊地面） | **不阻挡** | **不提供通行**（仅可选锚点） |
| `utility_shaft` | **可行走**（特殊地面） | **不阻挡** | **不提供通行** |
| `exterior_breach` | **可行走**（破口平台） | **不阻挡** | **不提供通行** |
| `elevator_shaft`（2×2） | **不可行走**（空腔） | **不阻挡** | **不提供通行** |

- **安装 / 交互位置**：玩家站在锚点**所在格**即可安装；`elevator_shaft`（不可行走）改由**相邻格**完成安装与交互（交互距离 ≤ 1 格）。
- **统一原则**：4 类锚点瓦片**均不阻挡 LOS 与子弹**——它们都是**地面层特征**，非墙体/掩体，**不参与掩体计算**（combat §3.4）。
- **不改变连通性**：未安装绳索时，4 类锚点**一律不提供通行**——保证"本层连通性 = 房间 + 走廊 + 主通道"这一 BFS 可达校验基准与无骨架时**一致**（procedural-gen §3.3 步 9）。
- **迷雾处理**：4 类锚点均为**普通 1×1 tile 状态**；`elevator_shaft` 占 2×2 时其 4 个 tile **共用同一三态**（一次 LOS 命中即全部转 Visible/Explored，不逐格判定）。

### 3.4 安装 / 回收流程

- **安装**：玩家站在锚点**所在格**（`elevator_shaft` 为不可行走空腔，站其**相邻格**即可）→ 交互提示 `[E] 安装绳索` → 消耗 **绳索绳缆 ×1** → 在该 cell 形成通往**下层同 cell** 的通道（双向）。
- **回收**：站在已安装绳索上端 → `[E] 回收绳索` → 拆除绳缆并**返还绳索绳缆 ×1**（暂定，待用户复核）。
- **多处安装**：受绳索供给限制，玩家可在不同 cell 各装一条，形成**多个脱出口**。

### 3.5 方向与速度

- 绳索**双向**可攀爬；**上行速度 −50%**（保全楼梯间主通道价值）。
- 下行 / 上行为**脚本化转场**：
  ```
  RopeDescendDuration = 1.2 s（暂定）
  RopeAscendDuration  = 2.4 s   // = 下行 × 2，即上行速度 −50%
  ```
- 转场期间玩家**不可被攻击、不可开火**（与楼梯间过层一致的极短转场语义，**combat §6.9「转场不可攻击态」**协同）。
- 绳索垂降体的**视觉长度 = 固定 8 段**（16×16 整段平铺，禁非整数拉伸）——视觉常量见 **art-bible §10.3 / asset-spec §1.4**（R-11 补引用，P2-12）。

### 3.6 持久化

- 已安装绳索属 **② 存档级持久层**：跨死亡 / **跨探索** **永久保留**（见 §3.7）。
- **R-20 战略意义（关键）**：敌人**按探索重置**（回基地再出发即全部复活），而**绳索跨探索保留** → **绳索是唯一能"跳过楼层、绕过复活敌群"的手段**。它因此成为：① **跑尸的首选路线**（避开已复活的敌群，直达尸体层）；② **长期投资**（玩家可"预先铺设撤退路线"，多次探索复用）。**这是 R-20 让"逃生绳索"从便利道具升级为战略道具的直接原因**（用户设计意图）。
- 绳索口为**持久标记**（**R-45：载体 = `M` 键「地图界面」**，见 `fog-of-war §3.4`）；**落点区域迷雾仍需自探**（遵守 fog-of-war §3.1/§3.4，标记 ≠ 透视地形）。**⚠ R-45 已改（原：R-44「载体待定 · 原 automap 已移除」——4 候选只列不选）**——**载体【落定 = `M` 键地图界面】**。**⚠ R-44 已改（原：绳索口在 automap 永久标记）**——**设计意图保留**：玩家应能知道"绳索装在哪"，以便规划纵向路线与跑尸捷径；**R-45 新增**：**跨层查看 = 在地图界面点选左侧楼层按钮查看该层绳索口标记**（⚠ 只列已探索层，未抵达层无数据可显示）。
- 楼层布局缓存（① 不可变层）**不含绳索**；绳索状态只存于 **② 持久层**。

### 3.7 世界状态分层（与 procedural-gen §3.1 / death-and-corpse §3.4 协同 · **R-20 改三层**）

```
[① 不可变布局层 Immutable Layout]   ← 由 (GlobalSeed, floor) 确定性生成、按存档固化
   + [② 存档级持久层 Archive-Persistent]（跨探索 / 跨死亡，永不重置）
        ├─ 迷雾遮罩（跨死亡保留）                      ← fog-of-war
        ├─ 已安装绳索（floor, cell, state）            ← 本系统（R-20 下是绕过复活敌群的核心手段）
        ├─ **已探索楼层集合 `ExploredFloors`**         ← 本系统 §3.9（R-25 新增；电梯井解锁粒度）
        ├─ **`RopeCrafted` / 电梯井已开启 `HubOpen`**  ← 本系统 §3.9（R-25 新增；一次性里程碑）
        ├─ 尸体记录（floor, tile, items）              ← death-and-corpse
        ├─ 门锁 / 已消耗钥匙（防死锁）                  ← procedural-gen / weapons-loot
        └─ 救援 / 剧情 / Boss 击败里程碑                ← base-survival-npc / enemies-ai
   + [③ 探索级重置层 Expedition-Scoped]（每次新探索开始时复位为 seed 初始）
        ├─ 敌人 / 精英 / Boss 存活与击杀状态            ← enemies-ai（R-20：跨探索复活）
        ├─ 地面物品拾取状态                             ← weapons-loot
        └─ 容器开启状态                                 ← weapons-loot
```

### 3.8 风险回报

- 绳索落点由生成器决定：可能通往下层**安全区**，也可能**直落敌群 / Boss 附近**（有意设计）。
- 锚点位置 + 井道噪声（见 enemies-ai §3.7）+ 绳索供给，共同构成"这条脱出口值不值得用"的决策。
- **R-20 加权（绳索价值上升）**：敌人**按探索重置**（回基地再出发即复活）后，**"跳过楼层"的价值大幅上升**——绳索可在**不重杀敌群**的前提下直达深层或尸体层，成为：
  - **跑尸捷径**（绕过复活路径，直取尸体）；
  - **长期基础设施**（跨探索保留 → **可预铺多条撤退线**，多次探索复用）；
  - **深潜策略**（一次探索内用绳索快速下切到目标深度，跳过已清但耗时的楼层）。
  代价不变（井道噪声吸引、落点可能直落敌群）——即 **R-20 让"风险回报"的天平更偏向绳索**（用户设计意图：凸显逃生绳索价值）。

### 3.9 基地电梯井枢纽 BaseElevatorHub（**R-25 新增 · 机制参考 Diablo II 小站/传送点**）

> **来源（R-25 用户设计意图）**：「可以通过指定从某一层楼层开始探索等方式减少重复探索高楼层的时间（类似 D2 的小站）。具体的想法是通过满足某些条件（比如制作出逃生绳索）打开第 100 层的电梯井，然后安装逃生绳建立通往已经探索过楼层的垂直通道……玩家通过楼梯间前往新楼层 → 探索该楼层 → 玩家返回基地 → 100 层电梯井的该楼层解锁 → 玩家再次探索时可直达 → 玩家在该楼层的电梯井可以直接返回基地结束一局游戏。」

> **⚠⚠ 定位修正（R-25 补充拍板 · 最高优先级 · 推翻本节的早期写法）**：
> **电梯井不是"垂直交通系统"的第三种方式**，而是 **D2 小站式的"关卡流切换器 / 存档节点传送"**。
> - 早期写法（"三种垂直交通并存：楼梯间 / 绳索 / 电梯井"）**已作废**——它把电梯井误当作**空间贯通结构**，而实际上**本作不存在任何"跨层空间结构"**（见 §3.9.0）。
> - **正确归类**：电梯井属于 **UI 层的楼层传送**（读档点 → 读档点），与"玩家在楼层内如何移动、如何垂直通行"**没有关系**。
> - **`TransportMode`（垂直交通方式）只有两种**：① 楼梯间（主通道）② 逃生绳索（自建次级）。

#### 3.9.0 前提：本作的地图加载模型（**R-25 首次显式定义**）

> 本节是理解电梯井的前提，**此前全库从未明确定义**（仅 procedural-gen §4.5 第 140 行隐含"楼层切换时销毁上一层实例"，但无人把它上升为模型）。**R-25 补全。**

```
本作采用【单层常驻 + 按需生成】的关卡流模型：

  · 任意时刻，内存中【只有当前一层】的地图（瓦片 / 实体 / 迷雾实例）。
  · 楼梯间瓦片 = 【换图触发器】：
        玩家走到楼梯间的"下楼瓦片" → 切换到下一层：
              floor F−1 【已生成过（存在于存档布局缓存）】→ 直接载入缓存
              floor F−1 【从未生成】              → 【当场生成】再载入
        玩家走到楼梯间的"上楼瓦片" → 切换到上一层（同理）
  · 切换时销毁上一层实例与瓦片资源（procedural-gen §4.5），【零常驻泄漏】。
  · 因此：楼层地图是【按需生成、用时载入、用完销毁】的，不是"一次生成 99 层同时存在"。
```

**由此推出的三条硬结论（全部与既有设计兼容）**：

| # | 结论 | 说明 |
|---|---|---|
| **C1** | **不存在"跨层空间结构"** | 本作**没有**"从 F 层掉到 F−1 层同坐标"这类**物理空间贯通**。绳索、楼梯间、电梯井**全部都是"切图触发器"**，不是"空间通道"。 |
| **C2** | **但"跨层坐标契约"仍然完全成立** | `ShaftCellSet` 的"相邻两层 shaft cell 同 (x,y) 对齐"是**生成期契约**（F 层生成时查骨架决定井位落在哪个 cell），**不依赖两层同时在内存**。绳索的"下层同 cell 落点"= 切图后**把玩家放到新层的同 cell 坐标**——**同 cell 是"落点坐标约定"，不是"空间贯通"**。**故 `VerticalSkeleton` / AC1 / AC2 / AC10 全部无需修改，语义重新表述即可**（见 §3.10）。 |
| **C3** | **"逐层下行"的耗时本质是"逐次换图"** | 从基地到 50 层 = **50 次换图**（每次都可能是"生成 + 载入"）。这解释了为什么"重复路过已探索楼层"代价高昂 → 电梯井的价值正是**把 50 次换图压缩为 1 次**。 |

- **对下沉设计的直接影响**：电梯井的价值**不需要**"跨层空间"来支撑——它节省的是**换图次数与重新清怪**，这本身就是足够的动机。
- **对既有界面的影响**：ux-spec §3.6 的 `[E] 下行` / `[E] 上行（回撤）` 提示**语义不变**（它本来就是"换图触发器"的提示，只是此前未点名）。

#### 3.9.1 设计目的与能力分工（**R-25 修正：非对称**）

**设计目的**：解决"重复探索高楼层"的时长问题 → 服务 §P1 单局 25–40 分钟。

```
无电梯井：  100 → 99 → 98 → … → F      （F−100 次换图 + 重复清怪 + 迷路）
有电梯井：  基地 → [速降到 F]           （1 次换图）
```

**⚠ 电梯井的能力是【非对称】的（R-25 用户明确拍板）**：

| | 🏢 **第 100 层 基地电梯井** | 🕳️ **99 及以下楼层电梯井** |
|---|---|---|
| **性质** | **D2 小站**（传送枢纽） | **单向逃生口（脱出点）** |
| **可指定目的层？** | ✅ **可以**——从楼层列表选任意已解锁层速降 | ❌ **不可以**——**无目的地选择** |
| **唯一可用动作** | 选择已解锁层 → 速降 | **返回基地（脱出）** |
| **方向** | **控制台在基地**（只能从基地出发） | **控制台在楼层**（只能从楼层回基地） |
| **是否双向传送** | ⚠ **不是"任意两点互传"**——是"**基地 → 任意已解锁层**"的**星形**拓扑 | 同左（楼层端只提供"回基地"这**一个**方向） |

- **关键设计含义（务必理解）**：
  - **玩家无法在楼层之间直接跳转**。要换层，**必须先回基地**（经电梯井脱出 or 经楼梯间上行），再从基地速降下去。
  - **因此不存在"清一层 → 电梯回家存钱 → 电梯直接下来继续"的零成本循环**——因为"下来"需要**从基地重新出发**，而**"离开基地"就是触发 ③ 探索级重置的那一时刻**（§3.1 / progression §6.10）。
  - ⚠ **这实际上【大幅削弱】了 §3.9.7 记录的"R-20 被架空"风险**——非对称设计天然保留了"回基地 = 重开敌情"的代价。**详见 §3.9.7（已重写）。**

**与绳索的分工（二者不可互替）**：

| | 🧵 逃生绳索（R-11/R-20） | 🚪 电梯井（R-25） |
|---|---|---|
| **本质** | 玩家在楼层内**自建的次级换图触发器** | **存档节点级别的楼层传送** |
| **连接** | 仅**相邻层** F↔F−1（切图后落在同 cell） | **基地 ↔ 任意已解锁层**（星形） |
| **方向** | 双向，上行 −50% | **非对称**：基地端可指定目的层；楼层端**只能回基地** |
| **成本** | 每次安装 `RopeCable ×1` | 首次开启 `RopeCable ×1`；之后乘坐 **0** |
| **前置** | 站在锚点 + 持绳缆 | 须先造出绳索（`RopeCrafted`）+ 基地安装 + 该层已探索 |
| **用途** | 逃生 / 跑尸捷径 / 相邻层机动 | **跳过已探索层** / **从任意已解锁层脱出结束一局** |

- **关键分工**：绳索**同时**是①电梯井的解锁条件（"制作出逃生绳索"是用户点名的前置），②**通往未探索相邻层的唯一自建触发器**（电梯井**只能去已探索层**）。二者**不可互相取代**。

#### 3.9.2 解锁三要素（缺一不可）

| # | 条件 | 判定 | 持久性 |
|---|---|---|---|
| 1 | **已制作逃生绳索** | `RopeCable` 曾被合成成功（存档级里程碑 `RopeCrafted`） | ② 存档级持久 |
| 2 | **在 100 层基地电梯井安装绳索** | 玩家在基地电梯井处执行 `[E] 开启电梯井`，消耗 `RopeCable ×1`（一次性） | ② 存档级持久 |
| 3 | **该楼层已探索** | `floor ∈ ExploredFloors` | ② 存档级持久 |

- **`ExploredFloors` 的判定口径（R-25 用户拍板 = 口径 b）**：**玩家"抵达过该层电梯井锚点"**，即该层电梯井锚点进入过玩家的**可见 / 已探索态**（`elevator_shaft` 2×2 的 4 tile 共用同一三态，一次 LOS 命中即点亮，见 §3.3.1 迷雾处理）。
  - **⚠ 口径 b 的设计含义（必须记录）**：玩家**必须实际走到该层的电梯井锚点**才算"探索过" → 电梯井**不是"下过这层就解锁"**，而是"**找到过这层的电梯井**"才解锁。**这天然要求玩家至少对该层做一次有目的的空间搜索**（`ShaftCellCount ∈ [3,7]`，锚点分散在 16×10 网格中），比"踩一脚任意格子"更有分量。
  - **⚠ 已知取舍（R-25 记录的边界风险，见 §6.14）**：口径 b 会诱使玩家形成"**直奔电梯井踩点 → 立刻坐电梯回家 → 图层永久可直达**"的**最小成本解锁策略**（"只踩点、不清层"）。这是**用户明确选择的完全免费（HubTravelCost = 0）** 的直接后果，**当前判定为可接受**，并**作为待实测项挂起**。

#### 3.9.3 数据存储（**新开 `ExploredFloors` 字段 · R-25 用户拍板不复用迷雾**）

- **`ExploredFloors`**：`Set<int>`，楼层号为元素，属 **② 存档级持久层** —— **跨死亡 / 跨探索永久保留**。
- **不复用迷雾数据的理由（用户拍板）**：迷雾遮罩虽天然记录"哪些层去过"，但其**三态粒度是 tile 级**（未探索 / 已探索 / 可见）且语义是"看得见"，与"电梯井是否解锁"的**楼层级布尔语义**不同。**解耦**可避免两个系统互相牵制（例如未来若调整迷雾持久化策略，不会意外改变电梯井解锁状态）。
- **写入时机**：`floor` 的 `elevator_shaft` 锚点三态**首次由未探索 → 已探索**的那一帧，将 `floor` 写入 `ExploredFloors`（幂等，重复写入无副作用）。
- **存档字段登记**：见 `progression.md §4.1.1`（R-25 已登记 `ExploredFloors` 与 `RopeCrafted`）。
- **世界状态分层图更新**：`vertical-traversal.md §3.7` 的 ② 层新增两行（见下）。

#### 3.9.4 交互与流程（**两端各自单向 · R-25 非对称修正**）

**A. 基地端（第 100 层 · D2 小站式传送枢纽）**

```
[HubLocked（井道关闭：未合成过绳索 / 未安装）]
   ─(玩家在基地电梯井 + 持 RopeCable + [E] 开启)─> [HubUnlocking（1.5s 读条）] ─> [HubOpen]
   ─(无 RopeCable)─> 提示置灰「需要绳索绳缆 ×1」

[HubOpen（已开启）]
   ─(玩家与基地电梯井交互 [E])─> [FloorSelectPanel（楼层列表）]
        ├─ 已解锁层（∈ ExploredFloors）→ 可选中
        │     ─(选中 + 确认)─> [Descend(2.0s 转场)] ─> [该层电梯井锚点落点]
        └─ 未解锁层 → **可选中但带警告**，提示「该楼层未经探索，贸然前往太过危险！」
              ⚠ **非阻塞**：允许继续（遵守 R-22 §P3「以死为师」教学边界，见 §3.9.6）
```

**B. 楼层端（99 及以下 · **单向脱出点**）**

```
[玩家站在某层(99–1)的 elevator_shaft 锚点旁]
   ─(该层 ∈ ExploredFloors ?)─>
        ├─ 是 → 显示 [E] 脱出 · 降下逃生绳 ─> [HubAscendCountdown（倒计时）]（见 §3.9.5）
        │        ─(倒计时走完，玩家全程未离开锚域)─> [Ascend(2.0s 转场)] ─> [基地]（**结束当前一局**，进入 RunEnd 结算）
        │        ─(玩家离开锚点邻域)─> [CountdownCancelled] ─> 回到 Idle（倒计时重置，下次需重新开始）
        └─ 否 → **不显示该交互**（该层尚未"开通脱出通道"）——见下"判定前提"
```

- **⚠ 楼层端的关键约束（R-25 明确）**：
  - **楼层端只有一个动作：回基地。** **没有**楼层列表、**不能**选择去其他楼层、**不能**上行到相邻层（那是楼梯间 / 绳索的职责）。
  - **该交互的可用前提**：该层 **∈ `ExploredFloors`**（即玩家抵达过**本层**电梯井 —— 这是自然满足的：玩家此刻就站在这层的电梯井旁，**站在这里的同一帧它必然已被写入**）。因此**判定实际恒为真**——保留该条是为了逻辑自洽与边界清晰。
  - **与楼梯间的分工**：楼层端电梯井 = **"一键回家"（脱出，需等倒计时）**；楼梯间 = **"逐层移动"（可上可下）**。玩家想"去别的楼层"**必须走楼梯间或绳索**，或回基地后从基地速降。
- **落点保护**：从基地速降的落点 = 该层 `elevator_shaft` 锚点**相邻格**；抵达后给 `RopeLandingGrace ≤ 0.5s`（与绳索一致，见 §6.1）。
- **转场语义**：转场期间玩家**不可被攻击、不可开火**（combat §6.9）。
- **⚠ 空井道从基地侧速降到"已解锁但电梯井未建成实体"的层**：不存在此情况——`ShaftCellSet` 是存档级固化常量，**每层（1–99）必然生成对应的井道结构**（§3.2），故"已解锁 = 该层必有井道实体"恒成立。

#### 3.9.5 脱出倒计时机制（**R-25 三次拍板新增 · 「翘首期盼」的等待**）

> **来源（R-25 用户设计意图）**：「脱出一键回家要有倒计时，比如提示玩家"（NPC某某）正在降下逃生绳，还剩XX（数字随时间快速递减）米。"，也就是楼层越低，需要的逃脱等候时间越长。」

**设计意图（关键 · 为什么要加倒计时）**：
「一键回家」若**瞬间完成**，则**楼层端电梯井会沦为"紧急按钮"**——玩家在压力下按一下就走，**P6「撤即经营」的紧张感被彻底抹掉**（§3.9.7 残留观测项 ① 正是这个担忧）。
**倒计时的作用，是把"脱出"从"瞬移"重新变回"一段需要守住的等待"**——它不是惩罚，而是**把"撤"的最后一程做成一场小型防御战**：
- **配合"递减米数"的叙事皮**（见下），玩家在等待中**看着绳子一米米接近**，形成"回家的路正在被铺出来"的**期待感**，而非干等；
- 越深的楼层等得越久 → **深度带来的风险有了最后一道兑现窗口**，与 §3.9.7「贪搜零风险循环不成立」形成互补：**你可以随时开始脱出，但你必须活着等到绳子放完**。

**核心公式（R-25 用户拍板：每下降 1 层耗 1 秒）**：

```
HubAscendCountdown(floor) = (100 − floor) × 1.0 s          // 楼层端脱出的等候时长
```

| 所在层 | 等候时长 | 说明 |
|---|---|---|
| 99 层 | **1 s** | 几乎瞬发——刚下潜一层即可轻松脱出 |
| 70 层 | 30 s | 已进入"需要清一块安全地"的区间 |
| 50 层 | 50 s | — |
| 30 层 | 70 s | — |
| 10 层 | 90 s | — |
| **1 层** | **99 s** | **全游戏最长等待**——最深处脱出的代价最高 |
| **终局广场** | **无脱出口** | ⚠ **末日之源终局战没有电梯井 / 没有逃生绳**（新增边界，见 §6.20） |

- **⚠ 为什么是"每层 1 秒"这个量级（不是每层 0.2s 或每层 5s）**：① **1 秒/层**使得**浅层脱出近乎无感**（99→90 层只等 1–10 秒），而**深层脱出显著变重**（≤30 层须等 70–99 秒）——**惩罚曲线斜率随深度加速**，与 R-23「越深越难」的三段难度曲线同向；② 99 秒**刚好是一个"必须认真对待但并非不可能"的量级**（一个完整的清房间 + 应对 2–3 波敌人），超过 2 分钟则会从"紧张"滑向"折磨"。

**叙事显示：递减米数（R-25 用户拍板：递减，给人翘首期盼的感觉）**：

```
「（蕾娜·哈特）正在降下逃生绳，还剩 73 米到达。」
                                    ↑ 随倒计时快速递减
```

- **口径（关键）**：**底层计时是"秒"，显示的是"米"**——米数是**叙事皮（narrative wrapper）**，让等待有画面感。
  - **映射建议（暂定）**：`显示米数 = 当前剩余秒数 × 1.0`（**1 秒 = 1 米**），即 50 层起始显示「还剩 50 米到达」，1 层起始显示「还剩 99 米到达」——**这样"米"与"楼层深度"直觉同构**（楼越高，绳越长）。

  - ⚠ **不得**同时显示「秒」与「米」两个数字（会立刻暴露"米是编的"，破坏叙事皮）。**只显示米。**

**与 R-20 探索级重置的关系**：

- 倒计时**走完并完成 `[Ascend]` 转场** → 玩家回到基地 → **本次探索结束**（与死亡 / 主动放弃同一条 RunEnd 路径，progression §6.12）。

**⚠ 平衡风险（R-25 三次 · 已识别并登记为阶段 1 头号校准项）**：
- **风险描述**：在**深层（≤40 层）**，玩家已进入 R-23 的**第三段难度曲线**（"打不穿"是常态），而**敌人会按 R-20 在本次探索内持续存在、且 99 秒的长度足以让大量敌人聚集到锚域周围**。**99 秒的静止坚守 + 打不穿的敌人 = 可能是必死局**，而非"可承受的压力"。
- **当前处理**：**照公式实现（用户拍板，不改数值）**，但**登记为阶段 1 试玩校准的头号项**，并预留以下**不改公式**的缓解杠杆（按优先级）：
  1. **锚点邻域的"天然防御性"**（生成侧）：`elevator_shaft` 锚点所在 cell 在生成时**优先靠近墙体 / 单入口空间**，使"坚守"有地形可用（procedural-gen 协同，**优先项**）；
  2. **倒计时的"分段喘息"**：倒计时过半时给一次**极短的无敌帧 / 屏震**（如 0.3s，"绳子猛然一坠"），仅作节奏调剂，**不改总时长**；
  3. **深层锚点额外刷新保护**（enemies-ai 协同）：`HubAscendCountdown` 期间，锚点邻域**限制同时存在的敌人数上限**（如 ≤6），避免"围成铁桶"。
- **⚠ 反向风险（也要防）**：若未来把倒计时调得太短（如改成"每层 0.3 秒"），**深层脱出会重新变成"紧急按钮"**，§3.9.7 观测项 ① 的担忧会回归。**故该校准是双向的**。

### 3.10 单层载入模型与"跨层坐标契约"（**R-25 首次显式定义**）

> 本节把 §3.9.0 的载入模型与其对**全部跨层机制**的语义影响集中收口，避免"跨层对齐"被误读成"跨层空间结构"。

#### 3.10.1 三种"换图触发器"总表（**取代"三种垂直交通"的旧写法**）

| 触发器 | 位置 | 目的地 | 方向性 | 是否需目标层已存在 |
|---|---|---|---|---|
| 🪜 **楼梯间** | 每层固定 | **相邻层**（F±1） | **双向**（可上可下） | ❌ 不需——**不存在则当场生成** |
| 🧵 **逃生绳索** | 玩家在锚点自建 | **相邻下层**（F−1，落同 cell） | 双向（上行 −50%） | ❌ 不需（同上） |
| 🚪 **电梯井** | 楼层电梯井锚点 / 基地电梯井 | **基地**（楼层端）／**任意已解锁层**（基地端） | **两端各自单向**（非对称） | ✅ **需已解锁**（`floor ∈ ExploredFloors`） |

- **三者都是"换图触发器"**，**都不是"空间通道"**（§3.9.0 C1）。
- **唯一的语义差异**：楼梯间 / 绳索**可以创造新楼层**（目标层不存在就生成）；电梯井**只能在"已存在且已解锁"的楼层之间传送**。

#### 3.10.2 跨层坐标契约的准确语义（**关键澄清**）

```
【准确表述】
  · ShaftCellSet 是【存档级固化常量】：一组 (cx,cy) 粗格坐标。
  · "相邻两层同 cell 对齐" 的含义 = 生成 floor F 时，读取 ShaftCellSet，
    在这些 (cx,cy) 处生成井道结构；
    生成 floor F−1 时，【读取同一份 ShaftCellSet】，在【相同的 (cx,cy)】处生成井道结构。
  · 因此对齐是【生成期契约】，而非【运行期空间贯通】。

【绳索"下层同 cell 落点"的准确含义】
  · 玩家在 F 层某个 shaft cell 安装绳索 → 使用绳索 = 切图触发器
  · 切图后，把玩家【放置到 F−1 层该 cell 的对应坐标】（该处已被契约保证有可站立落点）
  · 这不是"从洞里掉下去"，而是"换图 + 坐标定位"。视觉上表现为垂降转场（1.2s）。
```

- **⚠ 三条被此澄清影响、但结论不变的既有设计**（**无需修改内容，仅语义重新表述**）：
  | 既有设计 | 旧（易误读） | 新（准确） |
  |---|---|---|
  | `VerticalSkeleton` / AC1（相邻层 shaft cell 集合一致） | "两层共用的空间结构" | **"生成器读取的同一份坐标表"** |
  | AC2（落点 100% 可达） | "下层洞底可达" | **"切图落点坐标在目标层可站立且连通"** |
  | AC10（2×2 锚点不跨 cell） | "跨层对齐的必要条件" | **"同一坐标表下井道结构的稳定性条件"**（不变） |
- **`elevator_shaft` 锚点自身仍不可行走（§3.3.1）**：它在目标层是**井道空腔**，故绳索落点取**相邻格**——这在单层载入模型下**同样成立**（落点由目标层的实地形决定）。
- **对跑尸的影响（R-25）**：跑尸路线 ③（电梯井直达）**在单层载入模型下更显必要**——因为"从基地逐层换图到深层"要触发 F 次生成/载入，成本远高于"1 次传送"。**路线 ③ 的价值是"省 F 次换图"**。

```
MapLoadModel            = **单层常驻**（同一时刻只载入当前 1 层；楼梯间瓦片 = 换图触发器；目标层不存在则当场生成）
--- R-25 三次拍板：脱出倒计时（HubAscendCountdown · 见 §3.9.5）---
HubAscendCountdown(floor) = (100 − floor) × 1.0 s          // 每下降 1 层耗 1 秒；99层=1s，50层=50s，1层=99s
HubCountdownDisplayUnit   = "米"（**叙事皮**：显示米数 = 剩余秒数 × 1.0；**1 秒 = 1 米**）
HubCountdownRefresh       = ≥1 Hz 刷新；亚秒刷新时数字按整米跳变（**禁小数**）
HubCountdownCancelRule    = **仅"离开锚点邻域"取消**；受伤/移动/开火/翻滚/用药/换弹**均不中断**
HubAnchorRadius           = 3 tile（锚点 2×2 footprint 中心为圆心，暂定）
HubCountdownNpcPriority   = [NPC#2 蕾娜·哈特（电梯维保女技师）→ NPC#5 玛雅·索恩（R5 电力间 · 电力工程师）→ 其余已救出 NPC] → **中性兜底**「（基地）」
HubCountdownNpcEffect     = **纯叙事**（只改提示里的人名，**不改时长公式**；与 base-survival-npc AC16 兼容）
HubAscendPostCountdown    = 2.0 s（倒计时走完后才进入的转场；**此 2.0s 才属 combat §6.9 不可攻击态**）
HubPlazaTimeoutExempt     = **终局广场（末日之源）无脱出口**（**不存在**电梯井 / 逃生绳；见 §6.20）
```
> 变量单位：距离 = tile / px；时间 = s。全部数值 ⚠待调，阶段 1 试玩校准。

**锚点数硬约束（R-11，裁决 P2-1）**：因锚点**只能落在 shaft cell 内**（§3.3），而**每个 shaft cell 至多承载 1 枚锚点**，故 `AnchorsPerFloor` **必须 ≤ ShaftCellCount**：原式 `clamp(ShaftCellCount + floor(descentDepth/34), 2, 5)` 在 `ShaftCellCount=2、descentDepth≥68` 时会算出 4 > 2，属**越界**。修正为 `AnchorsPerFloor = min( clamp(ShaftCellCount + floor(descentDepth/34), 2, 5), ShaftCellCount )`；**若 ShaftCellCount 较小（如 2），则本层锚点数封顶为 2**，并记一条 warning（不报错）。

## 6. 边界与异常（Edge Cases & Anomalies）

1. **落点被敌占**：绳索下端落点平台**保证可站立**；若落点邻域有敌（含精英/Boss），玩家**正常抵达**（这是有意的风险回报），抵达后给 `RopeLandingGrace ≤ 0.5s` 落点保护，避免"落地即被秒"的不可读死亡。
2. **绳索被破坏**：T 档绳索**不可被破坏**；M 档下环境爆破 / 特定事件可摧毁已安装绳索 → 回到"锚点裸露"态，**绳缆不返还**（暂定）。
3. **无落点兜底**：落点校验失败 → 在 shaft cell **邻域局部强制开平台/房间**并连通主通道；**不重投整层**（保 G5 性能与 G2 可达）。
4. **连续多层绳索**：**单条绳索只连相邻两层**（F ↔ F−1，同 cell；**不存在"单绳跨多层"**）。跨多层须在同一 cell 的相邻多层**各装一条** → 形成**多级直降链**（可连续下行数层）；每级仍需各自消耗绳缆；上行时逐级攀爬（每级 2.4s）。
5. **楼层 1 与大门特殊处理**：楼层 1 出口为**大厦大门 / 广场**（非楼梯间）；楼层 1 **无下层**（floor 0 不存在）→ 该层 shaft cell 生成为**封死井底 / 渗光通风口**，**禁用下行安装**（提示"已到底层，无法下行"）；上行仍可用（回到 2 层同 cell）。
6. **楼层 100 基地**：静态场景，**不参与**骨架 / 锚点生成；**无楼层电梯井锚点**。**（R-25 例外）但基地含「基地电梯井枢纽 `base_elevator_hub`」——它不是一个锚点，而是一个静态功能枢纽**（§3.9.7），负责楼层列表 / 直达 / 返回基地；其开启条件与楼层锚点无关（见 §3.9.2）。
7. **锚点与房间重叠**：骨架为硬约束，房间模板放置须绕开 / 容纳 shaft cell，不得覆盖井道；冲突以**骨架优先**。
8. **锚点与楼梯间同格（R-11 修订，裁决 P2-4）**：**在主通道 cell 上不会出现锚点**——主通道（楼梯间）出口房所在 cell 已在**骨架生成阶段**从 SkeletonRNG 的 shaft cell 候选中**剔除**（procedural-gen §3.3 步 0），故二者**结构上互斥、不可能同格**。此前"若同格则互不干扰"的写法**已废弃**（它与 §3.3 的"不与房间功能瓦片重叠"自相矛盾）。
9. **无绳缆时**：锚点交互提示置灰并显示"需绳索绳缆"；不阻塞其他玩法。
10. **（R-25）电梯井未开启时**：基地电梯井为**叙事装饰态**（无青标识）；玩家交互提示置灰「需要绳索绳缆 ×1」；不阻塞其他玩法。**开启是存档级永久事件**，一旦开启不再关闭。
11. **（R-25）从基地直达未探索层**：**允许**（非阻塞）；提示「该楼层未经探索，贸然前往太过危险！」。落点 = 该层 `elevator_shaft` 锚点相邻格 —— ⚠ **但该层的锚点此前可能从未被玩家看见**，故**落点迷雾必须仍为未探索态**（不得因"坐电梯到达"而出卖迷雾），玩家落地后须自探地形。
12. **（R-25）从基地直达的楼层若锚点尚在敌群中**：与绳索同构（§6.1）——落点保证可站立，但**不保证安全**；抵达后给 `RopeLandingGrace ≤ 0.5s`。这是有意的风险回报。
13. **（R-25）一局内多次"基地↔楼层"往返**：**允许且免费**（`HubTravelCost = 0`）；每次往返都触发 ③ 层探索级重置的常规语义（**敌人状态不因乘电梯而变化**——电梯**不是**"休息点"，不重置敌人，也不刷新敌人；敌人复活只在"回基地再出发"这一事件发生时按 R-20 规则执行）。**⚠ 注意往返的时长不对称**：**基地端速降无倒计时**，**楼层端脱出需等 `(100 − floor) × 1.0 s`**（§3.9.5）——即"下去快、回来慢"。
14. **（R-25）"只踩点不清层"的最小成本解锁**：因解锁口径为"抵达过该层电梯井"，理论上存在"玩家直奔电梯井踩点 → 立即脱出回家 → 该层永久可直达"的**低成本解锁**。**当前接受**——理由：解锁仍需玩家**真实下潜到该层**（走楼梯间或绳索，逐次换图），且**下次从基地速降该层时敌人已全部复活**（R-20 重置），故不构成"零成本"。见 §3.9.2 / §3.9.7。
15. **（R-25）楼层端电梯井【不可】选择目的层**：**硬约束**——楼层电梯井锚点的交互**只提供"返回基地"**，**不得**出现任何"选择其他楼层"的 UI（那是基地端专属）。断言：在 99–1 层的电梯井处，**不存在**楼层列表 / 目的层选择控件。
16. **（R-25）楼层之间不可直接传送**：**硬约束**——电梯井拓扑是**星形**（基地 ⟷ 已解锁层），**不存在**"50 层 → 60 层"这类楼层间直达。要换层必须**先回基地**（或走楼梯间 / 绳索逐层）。断言：任意两层的电梯井**不构成互通**。
17. **（R-25）单层载入的资源释放**：每次换图**必须销毁上一层实例**（瓦片 / 实体 / 迷雾实例），**零常驻泄漏**（procedural-gen §4.5）。断言：连续换图 200 次后，内存占用**不随换图次数线性增长**。
18. **（R-25）目标层按需生成的确定性**：首次进入 floor F 时**当场生成**，其布局必须**与后续任何时刻重新生成的结果完全一致**（`(GlobalSeed, floor)` 确定性，procedural-gen §3.1）。断言：同一存档下，某层"首次生成"与"清缓存后重建"的结果**逐瓦片一致**。
19. **（R-25）"跨层坐标契约"在单层载入下仍生效**：绳索切图后玩家落在目标层**同 (cx,cy) cell 的坐标**——这是**坐标定位**，非空间贯通。断言：从 F 层某 shaft cell 用绳索切到 F−1，玩家在 F−1 的坐标**落在该 cell 范围内**（AC2 的可达性校验同时覆盖）。
20. **（R-25 三次）终局广场战没有脱出口**：**楼外广场（末日之源终局战）是独立静态地图，不属 99–1 探索区**（enemies-ai §6.14），因此**不存在**楼层电梯井锚点，**也就没有"一键脱出"**。玩家在终局战中**只能战斗到底或死亡**（无撤退通道）。**设计含义**：这是**唯一一处"必战"的地图**，与 99–1 层"随时可等绳脱出"形成对比——**终局是承诺，不是又一层**。断言：在广场地图中，**不存在**任何电梯井 / 逃生绳交互点。
21. **（R-25 三次）脱出倒计时的中断与重开**：① **受伤 / 移动 / 开火 / 翻滚 / 用药 / 换弹均不中断**倒计时（玩家可自由自卫）；② **仅"离开锚点邻域"（`HubAnchorRadius = 3 tile`）取消**倒计时并归零；③ 取消时**必须给可读反馈**（文案「已离开锚点，逃生绳回落。」+ 绳索上收动画 + 卷扬机音效），**不得静默消失**；④ 取消后**无冷却、无额外消耗**，回到锚点可**立即重新开始**（`HubTravelCost = 0` 不变）；⑤ **⚠ 倒计时期间玩家可被攻击、可开火——这不是 combat §6.9 的转场不可攻击态**（二者语义相反，见 §3.9.5 对照表）；⑥ **只有倒计时走完后的 `HubAscendPostCountdown = 2.0 s` 转场**才进入不可攻击态。断言：倒计时进行中，玩家**受到伤害即正常扣血**（保护逻辑未被误用）。
22. **（R-25 三次）倒计时期间的敌人行为（与 R-20 / enemies-ai 协同）**：倒计时**不改变敌人 AI**——敌人**不会**因为玩家在脱出而停止追击，**也不会**产生新的"守锚"行为；它们只是按既有规则（R-20 探索级状态下的存活敌人）行动。井道噪声（enemies-ai §3.7）**在倒计时期间持续发出**，会吸引附近敌人 → **"坚守即引怪"是有意设计**。⚠ 深层风险见 §3.9.5「平衡风险」段（已登记为阶段 1 头号校准项）。
23. **（R-25 三次）倒计时与基地端速降的不对称（再确认）**：**倒计时只在"楼层端脱出"出现**。**基地端速降（基地 → 已解锁层）没有倒计时**（`HubTravelDuration = 2.0 s` 转场，瞬发）——因为速降是**进入危险**（玩家自愿承担），脱出是**离开危险**（须先挣得）。断言：基地端前往面板**不出现**任何倒计时 UI。

## 8. 验收标准（Acceptance Criteria）

- **AC1**：**同一存档内，任意相邻两层的 shaft cell 坐标集合完全一致**（跨层断言）。**准确语义（R-25）**：两层**读取同一份存档级 `ShaftCellSet`**（生成期契约），**非"运行期空间贯通"**（§3.10.2）。
- **AC2**：**每个 shaft cell 在下层的落点 100% 可达**（BFS 校验，100 次抽样）。**准确语义（R-25）**：**切图后玩家的落点坐标**在目标层可站立且与主通道连通。
- **AC3**：**生成耗时增量 < +10ms / 层**（性能打点，对比无骨架基线）。
- **AC4**：非锚点瓦片**禁止**安装；锚点安装消耗 `RopeCable ×1` 并生成双向通道。
- **AC5**：上行耗时 = 下行 × 2（上行速度 −50%）；转场期间不可被攻击 / 开火。
- **AC6（R-44 改 · R-45 定）**：已安装绳索跨死亡 / **跨探索（run）** 持久（**② 持久层**）；绳索口为**持久标记**（**R-45：载体 = `M` 键地图界面**，见 fog-of-war §3.4）；落点迷雾仍自探。**⚠ R-45 已改（原：R-44「载体待定」）**。**⚠ R-44 已改（原：automap 永久标记）**。**R-20 补**：**探索级复位不影响绳索**——断言：连续 3 次探索后，已安装绳索**仍在原位、仍可用**。**反例断言补充**：HUD 左上**不存在**小地图（automap）元素（详见 fog-of-war AC7）。
- **AC7**：锚点密度符合 §4 公式（3–7 / 层，随 depth），**且 `AnchorsPerFloor ≤ ShaftCellCount`**（每 shaft cell ≤1 锚点；越界时截断 + warning）。
- **AC8**：落点被敌占时玩家可正常抵达（不卡死）；落点校验失败走邻域兜底且**不重投整层**。
- **AC9**：楼层 1 禁用下行安装、封死井底正确生成；楼层 100 无锚点。
- **AC10**：**若存在多格锚点（footprint > 1 tile），其 footprint 必须完整落在单一 shaft cell（8×8 tile）内、不跨 cell 边界**（跨层对齐的必要条件；单格锚点天然满足）。**断言对象 = `elevator_shaft`（2×2）**。
- **AC11**（R-11）：**锚点瓦片物理语义生效**——`floor_crack` / `utility_shaft` / `exterior_breach` 可行走、`elevator_shaft` 不可行走（可由相邻格安装）；4 类**均不阻挡 LOS/子弹**；**未安装绳索时均不提供通行**（本层连通性与无骨架基线一致）。
- **AC12**（R-25）：**电梯井解锁三要素全部生效**——① 未合成过绳索时无法开启；② 未在基地安装时无法使用；③ 仅 `floor ∈ ExploredFloors` 的楼层出现在可直达列表中（断言：全新存档下，`ExploredFloors` 为空 → 电梯井可开启但列表无任何可直达层）。
- **AC13**（R-25）：**`ExploredFloors` 是楼层级且持久**——玩家在某层**抵达电梯井锚点**的同一帧，该 `floor` 被写入 `ExploredFloors`（幂等）；写入后**跨死亡 / 跨探索永久保留**（断言：解锁 5 层后连续 3 局死亡重开，`ExploredFloors` 仍为这 5 层）。
