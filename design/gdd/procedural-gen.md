## 1. 概述（Overview）
楼层 99–1 由代码生成：房间 + 走廊 + **主通道出口（楼梯间）** + 敌群/战利品布置（另按 `vertical-traversal.md` 生成**垂直骨架**与**锚点特殊瓦片**，供玩家自建次级通道）。**第 100 层为玩家基地（静态安全屋，不参与程序化生成）**。**世界生成顺序改为：`GlobalSeed → 生成 VerticalSkeleton（存档级、固化）→ 逐层填充（骨架作为硬约束）`**（见 §3.1）。以**种子（seed）驱动、确定性可复现**为核心，保证"同种子 100% 复现"（P4）。关键约束：**楼层 99–1 首次生成后固化持久（persist），再次进入复用同一布局，不再重新随机**——生成确定性 + 持久化共同保证"同层永远一致"。百层通过**楼层难度递进**与**模板主题切换**实现"前慢后快"与"可重玩多样性"，同时受**性能约束**保证 solo/lean 下的流畅。

> **生成范围边界（R-24 用户明确 · 必须先钉死）**：**本文件的一切生成规则（含 §4.8 空间风格、§4.9 房间用途）只作用于楼层 99–1**。**第 100 层基地是手工静态场景**——其 R1–R10 房间、厨房、医疗室、空投站等**全部预绘制、不走生成器**（§6.8 / base-survival-npc §B.3）。**两侧唯一的联系是"名称相似"**：生成层里的「餐厅房间」「医疗房间」是**生成器内部的房间用途标签**（§4.9），与基地的 R3 厨房 / R4 医疗室**没有任何结构与功能上的依赖**——不得因名字相同而互相牵连（这是一条防伪冲突的护栏，R-24 立）。

## 2. 目标（Goal）
- G1：种子可复现（同 seed+floor 生成完全一致地图）。
- G2：同一存档内 100 层各不相同；**不同存档之间的模板重叠率 < 40%**（P4，可重玩性来自新存档）。
- G3：难度与内容随 descentDepth 平滑递进（心流曲线，concept §4.1）。
- G4：生成性能可控：单楼层生成耗时 < 50ms（目标）、峰值实体数封顶、无内存泄漏。
- G5：出口 100% 可达，无死路困死玩家（P1 逃生感底线）。

## 3. 核心机制（Core Mechanics）

### 3.1 种子与确定性
- `FloorSeed = Hash(GlobalSeed, floor)`；所有随机均从该 seed 派生的确定性 RNG 取数。
- **存档级种子**：每个**存档创建时生成 1 个 GlobalSeed**（不是每局生成）；该存档内所有楼层共用此 seed。控制台可输入 seed 复现。
- **持久化（按存档永久固化，已拍板）+ 世界状态三层模型（R-07 立 · R-20 改三层）**：楼层 99–1 在**首次进入时生成**并落盘到当前存档；此后整个存档周期内**布局永不变更**——跨死亡、跨探索再次进入均直接加载同一布局，绝不重新随机。第 100 层基地为静态手工内容，永不参与此流程。缓存采用**三层模型**：
  - **① 不可变布局层 Immutable Layout**：由 `(GlobalSeed, floor)` 确定性生成，含布局、房间模板、**骨架约束下的井道结构**；缓存损坏可按原 seed 重建（同 seed 字节一致，AC1）。**跨探索永不变更**。
  - **② 存档级持久层 Archive-Persistent（跨探索 / 跨死亡，永不重置）**：
    - **迷雾探索遮罩**（fog-of-war）——空间记忆是跨死亡的奖励，也是跑尸"认路"的前提；
    - **已安装绳索**（vertical-traversal）——玩家自建的逃生通道属**长期投资**（见下方设计意图 ②）；
    - **尸体记录**（death-and-corpse）——**跑尸系统的根基，绝不可被重置清除**；
    - **门锁 / 已消耗钥匙 / 已交付关键物品**——**必须保留**，否则会出现"钥匙已用掉、门又锁上"的**死锁**；
    - **救援 / 剧情 / Boss 击败里程碑**（与 ③ 的区分见下方 §3.1.1）。
  - **③ 探索级重置层 Expedition-Scoped（R-20 新增 · 每次新探索开始时复位）**：**敌人 / 精英 / Boss 的存活与击杀状态**、**地面物品拾取状态**、**容器开启状态**。复位目标 = **seed 初始态**（确定性，**不重新随机**）。
- **探索级重置定义（R-20，用户拍板）**——术语：**一次探索 Expedition ≡ 此前的 `run` 作用域**（本文件统一称"探索"）：
  - **一次探索 = 玩家离开基地（第 100 层）→ 返回基地**（无论探索了几层、是否用绳索、是否中途死亡）。
  - **探索进行中**：敌人死亡**不回位**（已清空的楼层保持清空）——避免玩家在**同一次探索内**来回跑动时反复重刷同样的怪。
  - **返回基地后，于下一次离开基地时**：③ 层**整体复位**——**已死亡的普通敌人 / 精英 / Boss 全部复活、地面物品与容器恢复**。
  - **"重置"≠"死亡即重置"**：**死亡回基地只是一次探索的结束**；需玩家**再次出发**才触发复位。**② 存档级持久层完全不受影响**（尸体、迷雾、绳索、门锁、剧情进度一律保留）。
  - **幂等**：复位**只对本次探索中被实际改动过的楼层**写入；未探索 / 未改动的楼层本就处于初始态，复位为空操作。
  - **设计意图（用户原话）**：① **跑尸难度显著上升**——尸体附近乃至整条回程路线上的敌人重新站岗，跑尸从"散步"变成"**再杀一遍**"；② **凸显逃生绳索的价值**——楼梯间主通道会被重新堵住，而绳索可**跳过楼层、绕过敌群**，成为跑尸与深入的核心捷径（且绳索属 ② 层、**跨探索保留**，可"预先铺设撤退路线"）；③ 提供"**大厦逃生**"的特殊体验——一次探索内从 100 层一路杀到 1 层，是"肃清一整栋楼"的马拉松式推进，而**回基地补给的代价就是重新肃清**。
  - **副作用（已接受）**：**"打一半回基地补药、再下来继续清同一层"不再可能**——「撤即经营」（P6）的取舍被显著强化：**回基地 = 保住战利品但重开敌情；不回 = 继续深入但风险累积**。
- **口径修正史（避免与新规则混淆）**：
  - ~~R-07 旧口径「世界物品拾取状态持久，拾取即消费，死亡不回位」~~ → **R-20 已被 ③ 层取代**：拾取在**本次探索内**有效，**下次探索时恢复**。
  - ~~R-07 旧口径「敌人 / 精英 / Boss 击杀状态持久，死亡不回位」~~ → **R-20 已被 ③ 层取代**：**探索内不回位，跨探索复活**。
  - ~~旧「死亡时重置为本层初始 / 物品回原位」~~ → **仍然废弃**（R-20 的复位发生在**再次出发**时，**不是死亡时**）。
  - **"每局换新图"仍然废弃**：复位的是**敌人与物品状态**，**布局永不重新随机**（可重玩性仍来自新存档 / 新 GlobalSeed）。
  - **旧依据作废**：R-07 的依据是"若敌人回位则跑尸 = 重打一遍，与『惩罚只有消耗』矛盾"。**R-20 用户明确接受"跑尸就是重打一遍"**——把死亡惩罚从"仅消耗"升级为"**再肃清**"，并以此作为**逃生绳索与空间规划**的价值来源。故该依据作废（详见 §3.1.1 / death-and-corpse §3.4 / progression §6）。

#### 3.1.1 「Boss 存活状态」vs「Boss 击败里程碑」（R-20 关键区分）

探索级重置会**复活 Boss**，但 **Boss 曾经被击败过**这件事属于**剧情 / 救援进度**，两者必须分开存：

| 状态 | 所属层 | 重置行为 |
|---|---|---|
| **Boss 当前是否存活**（本层 Boss 实体） | ③ 探索级 | **每次新探索复活** → 可**重复击杀**（掉落、练手、路线演练） |
| **"该 Boss 已被击败过"里程碑** | ② 存档级 | **永不撤销** → 用于一次性解锁（NPC 救援 / 通关判定）；**不会重复触发** |
| **最终 Boss 末日之源** | — | 属**楼外广场终局地图**，**不参与探索级重置**（每次召唤都是全新战斗） |

- **推论**：楼内 Boss **可 farm**（重复击杀拿掉落），但**救援 / 通关等一次性奖励不会重复发放**。
- **重复击杀掉落（R-20 立 · R-21 已定 · D2 式）**：Boss 重复击杀走**同一张掉落表**——**掉落概率固定、物品等级档固定、具体掉落物随机**（机制参考《暗黑破坏神2》）。R-20 的"首次击杀保底高价值 / 重复走普通表"建议**已作废**（用户 2026-09-23 拍板）。**不构成主导策略的理由**：重复收益**稳定但不递增**，装备成长靠**深度**而非**重刷次数**。见 enemies-ai §3.7 / §6.16。

#### 3.1.2 垂直骨架 VerticalSkeleton（R-07 新增）

- **定义**：世界生成顺序为 `GlobalSeed → 生成 VerticalSkeleton（存档级、固化）→ 逐层填充（骨架作为硬约束）`。
- **cell 尺寸**：楼层平面按 **`cell = 8×8 tile`** 划分粗格（**R-25：`128×86 tile` → 16×10 = 160 cell**，由 R-22 的 96×64 升档；见 §4.7）。
- **确定性**：`SkeletonRNG = RNG(Hash(GlobalSeed, "VERTICAL_SKELETON"))`；`ShaftCellCount = clamp(3 + floor(SkeletonRNG01 × 5), 3, 7)`（**R-25 由 [2,5] 升档**），由 SkeletonRNG 无重复抽取 `ShaftCellCount` 个 cell 作为**贯穿井位 shaft cell**（排除边界 cell）。
- **固化**：`ShaftCellSet` 在**存档创建时生成一次并落盘**，该存档内**所有楼层共用、永不变更**（与 P0-01 同构）。
- **对齐策略**：**严格同 (x,y) cell**（不做跨层偏移表）；floor F 的 shaft cell → floor F−1 的**同 (cx,cy) cell**。
  - **⚠ 准确语义（R-25）**：这是**生成期坐标契约**——生成 F 层与 F−1 层时**读取同一份存档级 `ShaftCellSet`**，在两层的**相同 (cx,cy)** 处生成井道结构。**它不是"运行期空间贯通"**（本作单层载入，见 §4.5）。绳索"下层同 cell 落点"= 切图后**把玩家放到目标层该 cell 的坐标**。详见 `vertical-traversal.md §3.10.2`。
- **每层约束**：每个 shaft cell 必须生成为井道类结构，且落点**必须可达**（生成后 BFS 校验；不满足则在该 cell **邻域局部强制开平台/房间**兜底，**不重投整层**）。
- 完整机制 / 数值 / 边界 / AC 见 **`vertical-traversal.md`**。

每个主题含若干**房间模板**（战斗房/搜刮房/休息房/出口房）与**连接规则**。

### 3.3 生成流程（Layout）
0. **加载 VerticalSkeleton（存档级，见 §3.1）**，取出本存档 `ShaftCellSet` 作为**硬约束**（R-11 注：**主通道/楼梯间出口房所在 cell 已在骨架阶段从 shaft cell 候选中剔除**，故"锚点"与"楼梯间"**结构上互斥、不会同格**，见 §6.10 / vertical-traversal §3.3、§6.8）→ 1. 选主题 → 2. 选房间模板并按权重放置（BSP 或网格法，**绕开 / 容纳 shaft cell**）→ 3. 走廊连接（保证全连通）→ 4. **在每个 shaft cell 生成井道类结构**（井道 + 相邻可站立落点平台，见 vertical-traversal §3.2）→ 5. **放置锚点特殊瓦片**（`floor_crack` / `elevator_shaft` / `exterior_breach` / `utility_shaft`，**仅落在 shaft cell 内**，密度见 §4.7）→ 6. 放置**主通道出口房（楼梯间）**（即本层固定主通道与下层入口；**双向**，可上行回撤）→ 7. 按权重填充普通敌人 / 容器 / 掉落（调用 enemies-ai、weapons-loot 的放置接口）→ 8. **放置 1 个精英怪（每层必出，按 §4.6 缩放）**；若本层为十进制楼层（90/80/…/10）则额外放置 **Boss 房 + 该层 Boss**（Boss 仅为 NPC 出现条件之一，非刚性绑定 NPC#k，见 base-survival-npc §C.3） → 9. 可达性校验（出生点可达楼梯间 / Boss 房可达 / **每个 shaft cell 落点可达**）→ 10. 固化缓存（**① 不可变布局层** + **② 存档级持久层**（迷雾 / 绳索 / 尸体 / 门锁 / 剧情进度）+ **③ 探索级重置层初始化**为 seed 初始态）→ 11. Ready。楼层 100 基地跳过本流程（静态加载）；**楼层 1 出口不是楼梯间而是大厦大门，触发切换至「楼外广场」终局地图（见 enemies-ai §5）**；**楼层 1 的 shaft cell 生成为「封死井底 / 渗光通风口」，禁用下行安装**（见 vertical-traversal §6.5）。

> **特殊瓦片放置规则（R-07）**：锚点瓦片（`floor_crack` / `elevator_shaft` / `exterior_breach` / `utility_shaft`）**只能落在 shaft cell 内**——这是"跨层对齐可保证"的根因；**非锚点瓦片上禁止安装绳索**。特殊瓦片不与房间功能瓦片重叠；若房间模板与 shaft cell 冲突，**以骨架优先**（房间局部重排，不重投整层）。美术规格见 art-bible / asset-spec。

> **楼梯间连通性（P2-02 · R-20 补代价 · R-25 定位补全）**：楼梯间为**双向换图触发器**——走到"下楼瓦片"切到下一层、走到"上楼瓦片"切到上一层、乃至逐步撤回第 100 层基地。**⚠ R-25 补充**：楼梯间是本作的**主换图触发器**（另一类是电梯井，只传送到已解锁层）——目标层**不存在则当场生成**（§4.5 单层载入模型）。**回撤代价（R-20 显著加重）**：① **在探索内**上下移动**不重置敌人**（同一次探索，③ 层不动）；② **但一旦撤回基地，下一次出发即触发 ③ 层复位——敌人（含精英/Boss）与物品全部恢复**（§3.1 探索级重置），这是回撤**最大的代价**；③ 回补库存必须回基地，而回基地就意味着**重新肃清**；④ 游戏内时间推进使基地 NPC 消耗继续——"回撤不是免费补给"（见 concept §7.1 / base-survival-npc §A）。**口径修正（R-07）**：楼梯间是每层**固定的主通道**（非"唯一撤点 / 唯一出口"）；玩家另可自建**逃生绳索**作为**次级换图触发器**（vertical-traversal §3）——**在 R-20 下，绳索是唯一能"绕过被复活的敌群"的手段，战略价值大幅上升**。

### 3.4 难度递进与随机权重
- 房间数、敌人预算、战利品等级、类型权重均随 `descentDepth` 插值（见 §4）。
- 类型权重表（僵尸/怪物/雇佣兵占比）按区段切换，实现"前慢后快"。

## 4. 关键数值与公式（Key Numbers & Formulas）

### 4.1 房间数与复杂度
```
descentDepth = 101 - floor                      // 1..100
RoomsPerFloor = clamp( round( (5 + descentDepth × 0.09) × StyleRoomCountK ), 4, 20 )   // R-24：叠加空间风格系数
StyleRoomCountK = S1:0.95 / S2:0.45 / S3:1.15 / S4:0.35 / S5:1.30
```
- 越往下房间越多越碎，增加迷失感与探索量（P4），但封顶防性能。
- **R-24 修正**：原式为纯 depth 函数（`clamp(...,5,14)`），**与空间风格无关** → 会导致 S4 大平层被强塞 14 间、S5 迷宫被上限 14 截断。**必须叠加 `StyleRoomCountK`**（详见 §4.8.4）；上限放宽至 20、下限放宽至 4。**生成 S4/S5 之前须先选风格**（§5 流程）。

### 4.2 敌人预算（按 cost 分配类型）
```
EnemyBudget(floor) = clamp( round(8 + descentDepth × 0.55), 8, 40 )   // 单楼层敌人上限40（性能）
```
- 预算按"类型 cost"消耗：僵尸 cost 1 / 怪物 cost 2 / 雇佣兵 cost 3；逐只抽取直至预算耗尽或达类型权重上限。

### 4.3 类型权重（玩法翻转的核心）
```
Zone权重(僵尸 : 怪物 : 雇佣兵)：
  豪宅层( 99–71):  0.80 : 0.18 : 0.02
  突变层( 70–41):  0.45 : 0.50 : 0.05
  封锁层( 40–11):  0.20 : 0.35 : 0.45
  底层  ( 10– 1):  0.10 : 0.30 : 0.60
```
> 雇佣兵从 **≤40 层**正式**成主力**（concept P3 量化指标落地）。兵源最低权重恒 **≥0**：豪宅/突变层可保留彩蛋式极低权重（如豪宅 0.02 / 突变 0.05），属惊喜遭遇而非主力；"成主力"自 ≤40 层起。
>
> **⚠ R-23 补注 · 机械敌人（底层专属第四类）**：上表三元组**不含机械**——机械敌人（Machine，见 enemies-ai §3.2.1）**只在底层 10–1 出现**，**不参与权重抽取**，而是按**底层独立预算**配置（⚠待调，建议每层 2–4 台，计入 §4.2 敌人预算但按 cost 3.5 消耗 ⚠待调）。**这意味着底层 10–1 的实际敌人构成 = 三元组（0.10:0.30:0.60）+ 机械**，战术复杂度最高（三种不同解法：绕后近战 / 切 LOS 枪战 / 破甲打核心）。
>
> **⚠ R-23 补注 · 初期密度（僵尸重定位的连带）**：僵尸由「脆皮铺量」改为「**少而强**」（HP 30→60–80、同屏密度 ~8→**2–3 只**），**budget cost 由 1 上调至 2 ⚠待调**。因此 §4.2 `EnemyBudget` 在**豪宅层区间**的实际效果会**下降**（同样预算下敌人数减半）——**这是刻意的**（配合"少而强"与"单挑练习"定位）。**⚠ 须复核**：豪宅层原设计"低威胁、让新手进入心流"是否因此**变得过难**（单位威胁↑ 但总数↓，净效果待实测）。**若实测偏难，优先调低僵尸单只 HP 而非恢复数量**（保"少而强"的形态）。

### 4.4 战利品等级
```
LootTier(floor) = clamp( floor((100 - floor)/20) + 1, 1, 5 )   // 顶层tier1 → 底层tier5
```
- LootTier 决定掉落表里**型号档位上移 + `MinTier` 硬门槛**（越深的层只出高级型号，见 weapons-loot §4.1，R-15）。

### 4.5 性能约束
- **⚠ 地图载入模型（R-25 首次显式定义 · 前置约束）**：本作采用 **【单层常驻 + 按需生成】** ——
  ```
  · 任意时刻内存中【只有当前一层】；楼层地图【按需生成、用时载入、用完销毁】。
  · 楼梯间瓦片 = 【换图触发器】：走到"下楼瓦片"→ 切到 F−1；
        F−1 已生成过（存档布局缓存命中）→ 直接载入缓存；
        F−1 从未生成                        → 【当场生成】再载入。
  · 电梯井（R-25）同样是换图触发器，但【只传送到已解锁层】（不创造新层）。
  ```
  - **影响**：单层生成耗时是**换图体感延迟**的直接来源（玩家每次下楼都会等这一下）→ 故 §4.5 的 <50ms（R-25 后预估 <90ms）不仅是性能指标，**也是手感指标**。
  - **确定性要求**：`(GlobalSeed, floor)` 决定布局 → **首次生成与"清缓存后重建"必须逐瓦片一致**（否则玩家重访某层会发现布局变了）。断言见 vertical-traversal AC19。
- **实体上限**：敌人 ≤ 40、可交互容器 ≤ 60、掉落物 ≤ 80 / 层（精英/Boss 计入预算外单独放置，不突破单项上限）。**R-25 注**：128×86 下单位面积密度降约 44%，会显得**比 R-22 更空**——当前接受（空间感是 S4/S5 的风格资源）；若实测"太空旷"，**优先上调容器/掉落上限，敌人上限暂不动**（见 §4.7）。
- **生成耗时**：目标 < 50ms / 层（超限则简化走廊/减房间，但保留出口可达）。**R-25 后目标值需上调为 < 90ms / 层**（面积 +79%）——⚠ 待阶段 1 p95 实测校准。
- **休眠 AI**：同屏外敌人进入"休眠"（不更新感知/移动），仅保留占位（combat §6.7 / enemies-ai §4）。
- **内存**：楼层切换时销毁上一层实例与瓦片资源，零常驻泄漏（**R-25：此条升格为"单层载入模型"的核心约束**，见上）。

### 4.6 精英与 Boss 节奏（落地用户决策）
```
每层：必放 1 精英（Elite，HP×2.2 / 伤害×1.4，见 enemies-ai §4.4），提供"每层一个小高潮"；精英**不做非整数缩放**，用 tint + 描边 + 独立 elite 标记区分（详见 art-bible）
十进制楼层(90,80,…,10)：额外放 Boss 房 + Boss，共 9 个十进制 Boss（Boss 仅为 NPC 出现条件之一，非刚性绑定，见 base-survival-npc §C.3）
楼层 1：含第 10 个楼内 Boss（Boss 仅为 NPC 出现条件之一，非刚性绑定，见 base-survival-npc §C.3）；击败后经基地「末日之源召唤器」召唤末日之源至「楼外广场」终局地图（最大面积；末日之源复活 10 个楼内 Boss 作精英 + 本体，见 enemies-ai §5）
```
> 精英/Boss 房预留与放置接口来自 enemies-ai；Boss 房需保证可达（§6 校验）。

### 4.7 垂直骨架与锚点密度（R-07 新增 · **R-25 尺寸升档**）
```
CELL                   = 8 × 8 tile
FloorGridTiles         = 128 × 86 tile                                    // R-25 用户拍板：由 96×64 升档（= 16×10 = 160 cell）
FloorGridTilesScaling  = ⚠ 预留（R-22）：FloorGridTiles 可随 descentDepth 增长（越深越大）
ShaftCellCount         = clamp(3 + floor(SkeletonRNG01 × 5), 3, 7)        // R-25 由 [2,5] 升为 [3,7]；存档级常量
AnchorsPerFloor(floor) = min( clamp(ShaftCellCount + floor(descentDepth / 34), 3, 7), ShaftCellCount )
```
- **单层尺寸（R-25 用户拍板 · 取代 R-22 的 96×64）**：**`128 × 86 tile`（16 × 10 = 160 cell）**。B 折中方案——在"单局 25–40 分钟"指标不变的前提下，通过**放大单层面积**降低"必须一路清怪下潜"的时长压力（配合 R-25 新增的**基地电梯井直通已探索层**，见 `vertical-traversal.md §3.9`，重复楼层的往返时间被进一步压缩）。
  - **升档的连带影响（全部已同步落地）**：
    | 项 | R-22 值 | R-25 值 | 变化 |
    |---|---|---|---|
    | cell 网格 | 12 × 8 = 96 | **16 × 10 = 160** | +67% |
    | 单层面积 | 6144 tile² | **11008 tile²** | +79% |
    | 预计单层停留 | 2.41 min | **≈3.2 min** | §P1 已同步改为 60–90s |
    | `ShaftCellCount` | [2,5] | **[3,7]** | 防锚点相对稀疏 |
  - **§4.5 实体上限复核（R-25）**：敌人 ≤40 / 容器 ≤60 / 掉落 ≤80 仍为**每层绝对值**；面积 +79% 后**单位面积密度下降约 44%**，大面积层会**比 R-22 更空**。当前判定为**可接受**（空间感本身是 S4/S5 风格的设计资源），但**阶段 1 试玩须专项校准**：若玩家反馈"太空旷"，优先上调**容器/掉落**上限（战利品密度比敌人密度更影响"值不值得搜"的体感），敌人上限**暂不动**（敌人是压力源，密集化会破坏 P1 逃生感）。
  - **§4.5 生成耗时复核（R-25）**：面积 +79% → 单层生成耗时预估由 <50ms 升至 **<90ms / 层**；仍满足 §4.10 性能护栏（S5 最贵，降级链不变）。**⚠ 待实测**（阶段 1 p95 打点）。
  - **`FloorGridTilesScaling` 仍为预留**：R-25 的 128×86 是**常量升档**，**不代表启用"越深越大"**。是否后再叠加递增，待用户后续裁决。
- `ShaftCellCount` 由存档种子派生 RNG 决定，**存档内固定**；`AnchorsPerFloor` 随 `descentDepth` 提高（**3–7 / 层**），**并受 `ShaftCellCount` 截断**（每 shaft cell ≤1 锚点，R-11 裁决 P2-1）。完整机制见 `vertical-traversal.md §3–§4`。
  - **密度校验（R-25）**：`ShaftCellCount ∈ [3,7]` 对应密度 **1.9–4.4 / 100 cell**；R-22 的 `[2,5]` 在 96 cell 下是 **2.1–5.2 / 100 cell** → 升档后**略降但同量级**，属**有意保守**（锚点太密会让"绳索 = 战略资源"的稀缺感消失）。
- **锚点瓦片物理语义（R-11 补，裁决 P2-3）**：4 类锚点**均不阻挡移动空间中的 LOS/子弹**（地面层特征，非墙/掩体）；`floor_crack`/`utility_shaft`/`exterior_breach` **可行走**、`elevator_shaft`（2×2）**不可行走**（由相邻格安装）；**未安装绳索时 4 类均不提供通行**，故**本层连通性 = 房间 + 走廊 + 主通道**这一 BFS 基准不受锚点影响（详规见 vertical-traversal §3.3.1）。

### 4.8 楼层空间风格系统（R-24 新增 · 机制参考 ZERO Sievert 商场地图）

> **来源（R-24 用户拍板）**：**室内部分的空间组织要模仿 ZERO Sievert 的商场地图**。用户给出的商场图（已缩小，ZS 实机精度更高）暴露出该图的**核心空间语法**：**网格状正交路网 + 房间沿街两侧排布 + 店内功能分区/货架岛 + 大型中庭 + 多尺度房间 + 中央大堂多出口**。R-24 的做法不是"照抄一张图"，而是**把该图的空间语法抽象成可参数化的风格族**，**按风格切分到不同楼层**——从而让**楼层风格 → 适合武器类型**（霰弹房 vs 对狙房）成为可玩的备战决策。

#### 4.8.1 两层正交模型（R-24 立 · 取代一切"楼层主题 = 房间类型"的混合写法）

| 层 | 名称 | 决定者 | 内容 | 状态 |
|---|---|---|---|---|
| **A** | **楼层主题 `FloorTheme`** | `descentDepth`（§3.2 四套） | 环境基调：豪宅 99–71 / 突变 70–41 / 封锁 40–11 / 底层 10–1 | **全库已存在**，本系统**不修改** |
| **B** | **空间风格 `FloorStyle`** | **楼层级 RNG**（`FloorSeed` 派生，**非 depth**） | 空间组织：S1 蜂窝格状 / S2 中庭环廊 / S3 走廊鱼骨 / S4 大平层 / S5 竖向迷宫 | **本系统新增** |

- **两层互相独立、可任意组合** → 组合结果 = **4 主题 × 5 空间风格 = 20 种楼层观感**。**代码只需维护 5 个空间风格预设**（主题是既有资产）。
- **正交的意义**：同是「封锁层 40–11」的相邻两层，**41 层是 S3 走廊鱼骨、35 层是 S4 大平层** —— 玩家会读到"这层要换枪"，而不是"又一层一样的军绿走廊"（服务 **P4 可重玩多样性** 与 **P3 玩法翻转**）。
- **同层内跨主题的观感差异**：生成层的「餐厅房间」在豪宅层是**金色调**、在封锁层是**军绿调** —— **不新增美术量，只换调色与家具权重**（art-bible 四主题调色板已定义）。

#### 4.8.2 三个空间参数（R-24 用户点名的参数族）

```
RoomSizeRange          = (min, max) tile 边长         // 小房间尺寸区间
Openness               = 0.10 .. 0.35                 // 开阔度（空腔占比）
CorridorMaxStraight    = 16 .. 48 tile                // 每段走廊最大直线长度
```

| 参数 | 含义 | 机制落点 | 用户原话 |
|---|---|---|---|
| **`RoomSizeRange`** | BSP 分割的**目标面积区间**（房间边长，tile） | §3.3 步骤 2「选房间模板并按权重放置」 | 「小房间的大小」 |
| **`Openness`** | **先预留一块空腔**（中庭/广场/货架岛开放区）的**面积占比**；剩余面积才交给 BSP | §3.3 步骤 2 **前置**：抠空腔 → 再排房间 | 「开阔度（空旷度，影响小房间的生成数量）」 |
| **`CorridorMaxStraight`** | 走廊的**每段最大直线长度**；超出即**强制拐弯**（或插入门/拐角/立柱） | §3.3 步骤 3「走廊连接」 | 「走廊曲折程度（每段走廊的最大直线长度）」 |

- **`Openness` 的连带效应（这是它最重要的作用）**：空腔占掉面积后，**同样楼层面积能容纳的房间数下降** → 它是"房间数量"的**上游旋钮**。因此 §4.1 `RoomsPerFloor` **必须叠加风格系数**（见下）。
- **`Openness` 上限卡在 0.35（R-24 护栏）**：玩家视野仅 **≈8–10 tile**（combat §4.8，屏内约 80 tile²），而整层 6144 tile² —— **开阔度越高，玩家站在空腔中心能一眼看掉整层的比例越大，迷雾张力与"拐角探头"战斗手感越弱**。0.35 是本作能容忍的上限（再高则 P1 逃生感与 P5 手感受损）。**S5 迷宫的"空旷感"不用大空腔实现，而用"多个小空腔"实现**（详见 §4.8.3）。
  - ⚠ **这同时是"对狙层"存在的理由**：没有超远视距就不可能有对狙（狙击 `FalloffEnd` 需 ≥80 tile 通视，combat §4.8）。**故 S4 大平层的 0.30 开阔度是刻意的战术资源，不是设计疏忽**——它牺牲了一部分迷雾张力，换来了另一种战斗形态（服务 **P4**：让不同楼层值得用不同打法）。

#### 4.8.3 五个空间风格预设（S1–S5 · 每个预设 = 前三参数的打包）

| ID | 名称 | `RoomSizeRange` | `Openness` | `CorridorMaxStraight` | `StyleRoomCountK` | 空间效果 | 主武器倾向 |
|---|---|---|---|---|---|---|---|
| **S1** | **蜂窝格状** | 16–24 t | 0.15 | ≤ 24 t | 0.95 | 网格路网 + 房间沿街两侧（**商场/住宅**） | 霰弹 / SMG |
| **S2** | **中庭环廊** | 20–40 t | 0.35 | ≤ 40 t | 0.45 | 大空腔 + 环形廊道（**商场中庭/餐厅**） | 步枪 / SMG |
| **S3** | **走廊鱼骨** | 12–20 t | 0.20 | **≤ 48 t** ★ | 1.15 | 长走廊 + 单侧小房间（**办公/医疗**） | 步枪 / 手枪 |
| **S4** | **大平层** | 32–64 t | 0.30 | ≤ 32 t | 0.35 | 少而大的开阔厅（**安保/仓储**） | 狙击 / DMR |
| **S5** | **竖向迷宫** | 10–16 t | 0.45 ⚠ | **≤ 16 t** ★ | 1.30 | 极短直段 + 密集小房间（**Boss 前室**） | 霰弹 / 投掷 |

> **★ 两处极端值**：**S3 的 ≤48 t**（最长直段 → 走廊对射，本作唯一允许"超视距对枪"的非空腔场地）与 **S5 的 ≤16 t**（最短直段 → 贴脸遭遇，走廊本身成为掩体迷宫）。
>
> **⚠ S5 的 0.45 特殊口径**：`Openness = 0.45` **不是"一个大空腔占 45%"**，而是**"45% 的面积为多个互不连通的小空腔（天井/管道井/隔断空档）"** —— 因此 S5 的**实际可达开阔区极小**、**无超远视距**，符合 0.35 上限的护栏意图（"迷宫感"来自拓扑复杂度，不是来自空旷）。**实现约束**：S5 的每个空腔面积 **≤ 6×6 tile**，否则退化为 S4。
>
> **⚠ S4 的瓦片实现提示**：32–64 tile 的大平层**不要按 tile-sheet 手画整张大图**（每张 sheet 只含单房间会很浪费）。应走**"矩形匀质铺满"路径**：画 1 块**主地平瓦片 + 边缘/角落变体**，由程序 tiling 铺满——美术成本可控（asset-spec 待补规格）。

#### 4.8.4 `RoomsPerFloor` 必须叠加风格系数（R-24 关键修正）

**冲突背景**：§4.1 原式 `RoomsPerFloor = clamp(round(5 + descentDepth × 0.09), 5, 14)` 是**纯 depth 函数、与风格无关**。若不加修正，**S4 大平层（只有 2–3 个大房间）会被公式强行塞进 14 个房间 → 风格失效**；**S5 迷宫需要 18 间才成立，却被上限 14 截断 → 也没法成立**。

```
RoomsPerFloor = clamp( round( (5 + descentDepth × 0.09) × StyleRoomCountK ), 4, 20 )
StyleRoomCountK = S1:0.95 / S2:0.45 / S3:1.15 / S4:0.35 / S5:1.30
```

- **上限由 14 放宽至 20**（为 S5 让路），**下限由 5 放宽至 4**（为 S2/S4 让路）。**性能护栏**：§4.5 单层生成 <50ms 与实体上限**由"实体数"独立约束，不由房间数决定**，故放宽房间数上限不破坏性能底线（但需实测 S5 的生成耗时，见 §4.8.5）。
- 示例（`descentDepth = 100`，base = 14 间）：S1 → 13｜S2 → 6｜S3 → 16｜S4 → 5｜S5 → 18。
- **风格必须与"房间用途"配套才可读**：S4 大平层里放 5 个「住宅房间」不合理 → 各风格的**房间用途权重表**见 §4.9。

#### 4.8.5 风格分配规则（哪个楼层用什么风格）

```
FloorStyle(floor) = WeightedPick(StyleWeights, RNG(Hash(GlobalSeed, floor, "STYLE")))
```
- **确定性**：风格由 `(GlobalSeed, floor)` 派生，**按存档永久固化**（属 **① 不可变布局层**，§3.1）——**同层风格跨探索/跨死亡永不变**。
- **先决约束（硬）**：
  1. **十进制楼层（90/80/…/10）含 Boss 房** → **必须 S4 或 S5**（大平层做 Boss 战场 / 迷宫做 Boss 前室），**保证 Boss 战有足够空间与"进场压迫感"**；
  2. **楼层 1（终局层）固定 S4**（最大平层 + 大门）；
  3. **楼层 100 不参与**（静态基地）。
- **主题×风格的软约束（权重不为 0，只调倾向）**：豪宅层偏 **S1/S2**（住宅/中庭，契合"奢华住宅"）；突变层偏 **S2/S3**（生物组织蔓延的长走廊）；封锁层偏 **S3/S4**（军用办公与仓库）；底层偏 **S4/S5**（安保大厅 + 密闭迷宫）。**⚠ 权重表数值待调**，阶段 1 试玩校准。
- **连续性护栏**：**连续两层不得同风格**（避免"连着两层都是大平层"的重复感）——以 `RNG` 抽到与上一层相同则**重抽**（最多 3 次，仍相同则接受，避免死循环）。

#### 4.8.6 风格 → 武器适配（R-24 的玩法落点）

**核心意图（用户原话）**：让**有些楼层适合霰弹枪，有些楼层适合对狙**，**玩家需要装备更适合该楼层的武器** → 把 R-23 的"换弹种"推进到"**换武器类型**"。

| 空间风格 | 典型交火距离 | 有利武器 | 不利武器 | 玩法要求 |
|---|---|---|---|---|
| **S1 蜂窝格状** | 8–24 t（视距边缘） | 霰弹、SMG | 狙击（无通视） | 拐角探头、房间清角 |
| **S2 中庭环廊** | 24–48 t | 步枪、SMG | 霰弹（近不了身） | 环廊走位、切 LOS |
| **S3 走廊鱼骨** | 32–80 t（走廊对射） | 步枪、手枪 | 霰弹（被拉远） | 卡走廊、对枪、后坐控制 |
| **S4 大平层** | 48–96 t+（超视距） | **狙击、DMR** | 霰弹、SMG | 抢高点、掩体 peek、预瞄 |
| **S5 竖向迷宫** | 4–16 t（贴脸） | **霰弹、投掷物** | 狙击（完全失效） | 听声辨位、贴脸爆发、撤退 |

- **备战决策（R-24 的核心体验）**：玩家在**下潜前**可看到下一层的**风格预告**（ux-spec §3.6 R-24 新增）→ 据此**改带武器**。**这使"带什么枪"从随机变成策略**（服务 **P6 撤即经营**：回基地 = 换装备的机会成本）。
- **与 R-23 难度曲线的兼容**：**豪宅层（僵尸"少而强·单挑"）应偏 S1/S5**（近距遭遇，配合"僵尸近身缠斗"）；**封锁层/底层（雇佣兵/机械远程对射）应偏 S3/S4**（远程枪战，配合"掩体 peek 主导"）。**⚠ 这条是全系统最重要的"风格 × 难度"耦合**，若错配（如豪宅层出 S4），会**破坏 R-23 三段曲线的初期手感**——故 §4.8.5 的主题×风格软约束**必须**体现此倾向。
- ⚠ **不得用风格制造"无法应对"的局**：任何风格都必须存在**至少一种通用解法**（如 S4 大平层即使只带霰弹，也能靠**侧翼走位 + 掩体推进**接近）——否则玩家"因为上一层的风格预告看漏了"就被判死，违反 P1（逃生感底线：打不过能跑）。


### 4.9 房间用途标签（RoomTag · R-24 新增）

**定位**：`RoomTag` **不是第三层体系**，而是**挂在空间风格内部的"这个房间填什么"标签** —— 决定该房间的**家具/掩体/战利品倾向**，与 §4.8 的「楼层主题」（调色/光照）**正交**。

> **⚠ 边界声明（R-24 用户明确 · 防伪冲突 · R-27 迁号）**：`RoomTag` 里的「**餐厅**」「**医疗**」是**生成器内部的房间用途**，**与第 100 层基地的 R3 厨房 / R4 医疗室毫无关系**。基地房间走静态手工绘制（§6.8 / base-survival-npc §B.3），**不参与生成**；生成层的同名房间**不提供任何基地功能**（不能制药、不能做饭、不能交易），只是**有对应家具与掉落倾向的空间**。

| `RoomTag` | 家具/掩体倾向 | 战利品倾向（weapons-loot 容器） | 战斗空间特征 | 适配空间风格 |
|---|---|---|---|---|
| **住宅 Residential** | 床/沙发/衣柜（**软掩体**，低耐久） | 衣物、少量药品、现金 | 小房间密集、门口遭遇 | S1 / S5 |
| **安保 Security** | 柜台/装甲板/哨位（**硬掩体**，高耐久；可能有**单向玻璃**） | **弹药、护甲、武器**（高价值） | 开阔 + 硬掩体、易成对射场 | S3 / S4 |
| **餐厅 Dining** | 餐桌阵列/吧台/座椅（**中掩体**，通道曲折） | 食物、饮料、少量现金 | 家具密、视线被切碎 | S1 / S2 |
| **医疗 Medical** | 病床/药柜/隔帘（**软掩体**） | **药物原料、药品**（R-19 三轴）、绷带 | 小隔间、走廊串联 | S3 / S5 |
| **Boss 房 Boss Arena** | 场景化掩体（柱/台/废墟），**对称布局** | **Boss 掉落表**（§4.6） | 大空间 + 少量硬掩体、需走位 | **仅 S4 / S5** |
| （通用）**通用房 Generic** | 货架岛/纸箱（中掩体） | 混合（按 `LootTier`） | 无特殊倾向 | 全部 |

- **权重来源**：每层按 `FloorStyle` 定一张 `RoomTagWeights` 表（如 S4 大平层 → 安保 0.45 / 通用 0.30 / 住宅 0.10 / 餐厅 0.10 / 医疗 0.05），**由 `FloorSeed` 抽取**。**⚠ 权重数值待调**。
- **硬约束**：
  1. **每层至少 1 个「安保」房**（保证弹药/护甲可得，避免"断供"死局）；
  2. **Boss 房仅出现在十进制楼层与楼层 1**，且**只能是 S4/S5**（§4.8.5）；
  3. **`RoomTag` 不影响迷雾/连通性**（纯内容层，不改变布局拓扑）；
  4. **`RoomTag` 的家具是"战斗掩体"的一等公民** —— 家具的**掩体等级（软/中/硬）**须在生成时标注入碰撞数据，供 combat §3.4 掩体系统消费（软掩体可被高穿透弹击穿，硬掩体不可）。

### 4.10 风格系统的性能与异常（R-24 护栏）

1. **生成耗时**：**S5（≤16 t 直段）是最贵的**（频繁拐弯 → 走廊拓扑与 BFS 连通性校验开销上升）。**若 S5 单层生成 >50ms**（§4.5），**优先简化 S5 的走廊拓扑（放宽至 ≤20 t），而不是取消 S5 风格**。
2. **风格降级链**：若某风格在当前 `ShaftCellCount`（2–5 个井道硬约束）下无法满足落点可达 → **降级顺序 S5 → S1 → S3 → S2 → S4**（先保可达性，再保风格）。
3. **`Openness` 与井道冲突**：空腔**不得吞掉 shaft cell**（骨架优先，§3.3 特殊瓦片规则）——空腔生成时须**绕开 shaft cell**，若某 shaft cell 落在空腔内则**将其处理为"空腔中的井道平台"**（反而是好设计：可见的深渊井口）。
4. **风格不可读的护栏**：**同一存档内，S5 不得连续出现 >2 层**（迷宫过密会让整局节奏变成"贴脸疲劳"）；**S4 不得连续出现 >2 层**（超视距过密会让"对狙"从特色变成噪声）。


## 5. 状态机（Generation Pipeline）
```
[Skeleton(存档级,仅首次)] ─> [SeedInit] ─> [ThemeSelect(楼层主题)] ─> [StyleSelect(空间风格 S1–S5 · R-24)]
   ─> [CarveOpenness(抠空腔, 绕开 shaft cell)] ─> [Layout(BSP/Grid, 绕开 shaft cell)]
   ─> [CorridorConnect(含 CorridorMaxStraight 强制拐弯)] ─> [TagRooms(房间用途标签 RoomTag · R-24)]
   ─> [BuildShafts(井道+落点)] ─> [PlaceAnchorTiles(锚点瓦片)] ─> [PlaceExit(主通道)]
   ─> [Populate(敌人/容器/掉落 by 权重; 家具掩体等级标注入碰撞)]
   ─> [Validate(可达性+上限+落点可达)] ─(通过)─> [Freeze(①不可变层 + ②持久层 + ③探索层初始化)] ─> [Ready]
                     └─(失败, 重试<N次)─> [Layout]   // 兜底：固定"出口房+直线走廊"模板
                     └─(仅落点不可达)─> [ForceOpenLocalPlatform]（邻域兜底，不重投整层）
                     └─(风格不可满足)─> [StyleDowngrade]（降级链 S5→S1→S3→S2→S4，§4.10）

// R-20 探索级复位（与生成流水线分离的独立入口）
[玩家离开基地] ─> [ExpeditionBegin] ─> [③ 探索级层复位为 seed 初始态（幂等，仅限改动过的层）] ─> [Ready]
```
- 校验失败重试上限 **N=3**；仍失败则用**兜底模板**（保证 G5 永不困死）。**落点不可达**走邻域局部开平台兜底（不重投整层，见 §6.11）。
- **R-24 新增两步**：`StyleSelect`（选空间风格）与 `CarveOpenness`（先抠空腔再排房间）——**顺序不可颠倒**（开阔度是房间数的上游旋钮，§4.8.4）。

## 6. 边界与异常（Edge Cases & Anomalies）
1. **拼接失败/房间重叠**：网格法优先（降重叠）；BSP 重叠则重投。
2. **死路/出口不可达**：Validate 用 BFS 从出生点可达出口；不可达→重试或兜底。
3. **实体超限**：Populate 严格按 §4.5 上限截断，不超发。
4. **生成超时**：单步 > 阈值则降级简化（先保出口与连通）。
5. **种子冲突/非法输入**：GlobalSeed 缺失则随机生成并固化；非法字符回退默认。
6. **楼层 1（终局层）**：含**第 10 个楼内 Boss（Boss 仅为 NPC 出现条件之一，见 base-survival-npc §C.3）**；击败救出军方女科学家（**NPC#10 伊芙琳·斯特恩**）后，由基地**正式房间 R10**「末日之源召唤器」召唤末日之源至楼外广场终局地图（最大面积，末日之源复活 10 个楼内 Boss 作精英 + 本体，见 enemies-ai §5）；本层仍正常生成，**楼梯间出口替换为大门事件**；**本层 shaft cell 生成为封死井底 / 渗光通风口，禁用下行安装**（vertical-traversal §6.5）。
7. **内存/切换泄漏**：切层销毁上一级，GC 校验（CI 内存快照）。
8. **楼层 100 基地不生成**：基地为静态手工场景，永远跳过生成流程；生成器仅处理 99–1。
9. **已生成楼层固化**：再次进入已生成楼层直接加载缓存，不重新随机；缓存损坏则按原 seed 重建（同 seed 字节一致，§AC1），重建后**按三层分别处理**——① 布局层按 seed 重建；② **存档级持久层回放**（迷雾 / 绳索 / 尸体 / 门锁 / 剧情进度）；③ **探索级层按"当前探索是否已开始"决定**：若本次探索已在进行则回放本次探索的击杀/拾取记录，若为新探索则**置为 seed 初始态**。不丢失玩家进度（见 death-and-corpse §6.1）。
13. **探索级重置的边界（R-20）**：① **复位时机 = 再次离开基地时**，不是死亡时、也不是在基地内；② **只在"本次探索中被改动过的层"上写入**（幂等），未去过的层无需处理；③ **楼内 Boss 复活**但"已击败里程碑"保留（§3.1.1），**一次性奖励不重复发放**；④ **尸体与尸体内容物免疫复位**——复位只处理"地面物品与容器"，尸体容器是独立类型（death-and-corpse §6）；⑤ **玩家主动扔在地面的物品不复位也不保留**（复位时统一清除，避免垃圾堆积；⚠待拍板）；⑥ **门锁与已消耗钥匙不复位**（否则死锁）；⑦ **终局地图（楼外广场）不参与探索级复位**。
10. **跨层对齐兜底**：骨架为存档级固化；某层生成后若 shaft cell 与房间冲突，**以骨架优先**并局部重排房间（不重投整层）。
11. **落点不可达修正**：shaft cell 落点 BFS 校验失败 → 在**邻域局部强制开平台/房间**并连通主通道（保「落点 100% 可达」），不重投整层、不超性能预算（vertical-traversal §6.3）。
12. **楼层 1 与大门处理**：楼层 1 出口为**大厦大门**（非楼梯间）；shaft cell 生成封死井底 / 渗光通风口，禁用下行安装；上行仍可用。**楼层 1 固定 S4 空间风格**（§4.8.5）。
14. **空间风格不可满足（R-24）**：若某风格在当前 `ShaftCellCount` 硬约束下无法保证所有落点可达 → 走**降级链 S5→S1→S3→S2→S4**（§4.10），**先保可达性（G5）再保风格**。降级须记录 warning，不报错。
15. **空腔吞掉 shaft cell（R-24）**：`CarveOpenness` 抠空腔时**必须绕开 shaft cell**；若骨架 cell 已被空腔覆盖，则将其处理为「**空腔中的井道平台**」（可站立落点 + 可见深渊井口），不重投整层。
16. **风格重复护栏（R-24）**：**连续两层不得同风格**（抽到重复则重抽 ≤3 次）；**S4 与 S5 各自不得连续出现 >2 层**（§4.10.4）。
17. **风格与难度错配（R-24 · 最高风险项）**：§4.8.5 的「主题 × 风格」软约束**必须**保证「**豪宅层（僵尸"少而强·单挑"）偏近距风格 S1/S5**，**封锁层/底层（远程对射）偏远距风格 S3/S4**」。**若豪宅层生成 S4 大平层**，玩家可在超视距外点掉慢速僵尸 → **直接破坏 R-23 三段曲线的初期手感**。**实现护栏**：豪宅层（99–71）的 `StyleWeights` **不得给 S4 非零权重**（S5 同理只作低频）。

## 8. 验收标准（Acceptance Criteria）
- AC1：同 (GlobalSeed, floor) 两次生成字节级一致（自动化断言）。
- AC2：100 次随机生成中，出口可达率 = 100%；无死路困死。
- AC3：不同存档（不同 GlobalSeed）之间地图模板重叠率 < 40%（统计抽样）；同一存档内楼层布局跨死亡/跨 run 字节级不变。
- AC4：EnemyBudget / LootTier / 类型权重随 floor 按 §4 公式单调/分段生效（单测）。
- AC5：单楼层生成耗时中位数 < 50ms（性能打点）；峰值实体不超 §4.5 上限。
- AC6：楼层切换后上一级内存释放（无持续增长）。
- AC7：楼层 1 终局语义与 Boss 房预留正确生成。
- AC8：每层含 1 精英（§4.6）；十进制楼层含 Boss、楼层 1 含第 10 个楼内 Boss（Boss 仅为 NPC 出现条件之一，见 base-survival-npc §C.3）；经召唤器正确触发广场终局地图。
- AC9：**同一存档内，任意相邻两层的 shaft cell 坐标集合完全一致**（跨层断言，vertical-traversal AC1）。
- AC10：**每个 shaft cell 在下层的落点 100% 可达**（BFS 校验，100 次抽样，vertical-traversal AC2）。
- AC11：**垂直骨架生成 + 落点校验的耗时增量 < +10ms / 层**（性能打点，对比无骨架基线）。
- AC12（R-20 改）：**三层世界状态正确分离**——① **不可变布局层**跨探索不变；② **存档级持久层**（迷雾 / 已安装绳索 / 尸体 / 门锁 / 剧情与 Boss 击败里程碑）**跨探索与跨死亡均不重置**；③ **探索级重置层**（敌人与精英/Boss 存活击杀状态 / 物品拾取 / 容器开启）在新一次探索开始时**复位为 seed 初始态**，且复位**幂等**（只写实际改动过的楼层）。断言：**同一次探索内**清掉的敌人**不复活**；**回基地再出发后**敌人与物品**全部恢复**，而**尸体 / 迷雾 / 绳索 / 剧情进度保留**。缓存重建后三层各自回放/复位正确、玩家进度不丢失（death-and-corpse AC3/AC9）。
- AC13（R-20 新增）：**探索重置的触发边界**——① 玩家在基地内**消磨时间 / 存档 / 整理背包不触发**复位；② **死亡回基地**为一次探索的结束，**但复位要等"再次离开基地"才发生**；③ 基地（第 100 层）**永不参与复位**；④ 终局地图（楼外广场）**不参与探索级复位**。
- AC14（R-24）：**空间风格确定性且跨探索不变**——同一 `(GlobalSeed, floor)` 两次生成得到**同一 `FloorStyle`**；风格**跨探索、跨死亡不变**（属 ① 不可变布局层）。断言：连续 3 次探索后，同层的风格 ID 字节级一致。
- AC15（R-24）：**风格参数生效且可测**——① 实测各风格的**矩形房间边长**落在 `RoomSizeRange` 内；② 实测**空腔面积占比** ≈ `Openness`（±0.03）且**任何单个空腔 ≤ 全层 35%**（S5 的每个小空腔 ≤6×6 tile）；③ 实测**无直线走廊段 > `CorridorMaxStraight`**（网格法统计）。
- AC16（R-24）：**`RoomsPerFloor` 叠加风格系数**——同一 `descentDepth` 下，S4 生成的房间数 **< S1 < S3 < S5**；且 S4/S5 的实测房间数与公式（§4.8.4）误差 ≤1。
- AC17（R-24）：**风格 → 武器适配成立**（玩法验收）——① **世界内可观测的空间尺度指标**可从风格反推（S4 存在 ≥80 tile 通视走廊；S1/S5 无 >24 tile 通视走廊）**（⚠ R-44 已改：原"`automap` 之外的空间尺度指标"——小地图已移除，改中性表述）**；② **阶段 1 试玩**：玩家在 S4 层用狙击的有效交火比例显著高于 S1/S5 层，反之霰弹同理（数据可观测）；③ **不存在"无解风格"**——五种风格均存在至少一种通用解法（§4.8.6 护栏），脚本化验证"仅带霰弹也能在 S4 抵达楼梯间"。
- AC18（R-24）：**风格 × 难度不错配**——**豪宅层 99–71 不生成 S4**（`StyleWeights[S4] == 0`）；**十进制楼层与楼层 1 必为 S4/S5**；**连续两层不同风格**；**S4/S5 不连续出现 >2 层**。
- AC19（R-24）：**房间用途标签正确**——每层**至少 1 个「安保」房**（保证弹药/护甲可得）；**Boss 房仅出现在十进制楼层与楼层 1**；`RoomTag` **不改变布局拓扑与连通性**；**家具掩体等级（软/中/硬）已标注入碰撞数据**（combat §3.4 可消费）。
- AC20（R-24）：**生成范围边界**——**第 100 层不走生成器**（静态加载，零次调用 ProceduralFloorGen）；风格系统**不读取任何基地房间数据**（base-survival-npc §B.3 解耦，防伪冲突）。
