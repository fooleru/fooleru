## 1. 概述（Overview）
武器与战利品系统是 **P2（搜刮即构建）** 的执行核心。玩家强度不来自线性升级，而来自本局捡到的武器、**弹药口径/弹种**、**耐久状态**与改造附件的组合。系统覆盖：武器分级、弹药口径与类型、穿透、耐久与卡壳、改造附件、掉落表、背包与装备槽。所有数值最终注入 combat 系统结算（无死值），支撑 build 多样性。

> **R-12 范围**：**玩家侧无近战武器**（用户决策：动作/手感工作量过大，暂不做；参考对标《ZERO Sievert》玩家侧亦无近战）；**远程枪械整体对齐 ZERO Sievert 的数值轴与手感模型**（见 `reference-alignment-zero-sievert.md`）。**敌人近战保留**（由 enemies-ai 定义）。近战原本承担的"省弹/破硬直/贴身应急"由**投掷物 + 霰弹 + 翻滚**接手。

## 2. 目标（Goal）
- G1：单局可形成 ≥ 3 种可辨识 build 流派（**霰弹近距流 / 步枪控枪流 / 狙击爆发流 / 亚音速潜行流** 等）（P2 量化）。
- G2：掉落公平且**随层上移型号档位**（LootTier 上移档位 + `MinTier` 硬门槛，§4.1），平均每层产出 ≥ 2 件可用物资（concept §2 P2）。
- G3：附件改造显著影响手感曲线（**Recoil / Ergonomics / Accuracy / Damage / 弹匣**），让"改造即玩法"。
- G4：无重复/满包/附件冲突等边界 bug。
- G5（R-12）：**"选对弹"与"选对枪"同等重要**——高层变异体需 HP 弹、低层雇佣兵需 AP 弹；带错弹就是打不动（策略性备战）。

### 3.1.1 型号阶梯（R-15 立 · **R-19 改按 ZS `value` 排序**）

> **R-15 核心裁定（用户决策）**：稀有度**不代表"同一把枪的属性高低"**，而是代表**这是哪一把枪**——即**型号本身的价值与威力层级**。低稀有度 = 早期/廉价型号；高稀有度 = 后期/高端型号。**越到游戏后期（越往下），越大概率刷出高级型号**（§4.1 `MinTier` 机制）。

### 3.2 稀有度（Rarity · R-15 重定义）

`Common / Uncommon / Rare / Epic / Legendary` —— **它是"型号阶梯"的标签**，不是属性倍率轴（见 §3.1.1）。

- **影响三件事**：
  1. **掉落深度**：稀有度越高，`MinTier` 越大——**高稀有度型号只在深层出现**（§4.1）；
  2. **UI 表达**：边框颜色 + 名称前缀（art-bible §3.6）；
  3. **型号强度**：高稀有度型号的**基准属性更强**（威力/精度/工效/槽位中的一项或多项），但这是**型号表的固有差异**，**不是运行时乘区**。
- **R-19 新增 · 档位的排序依据 = ZS 源码 `value`（升序）**：档位不再凭直觉排，而是**照 ZS `value` 排**——因为 `value` 已是 ZS 对"综合价值"的定价。**副作用：伤害不再与档位单调**（高 `value` 的枪可能单发伤害更低），这是**有意保真**（§3.1.1）。族间不比较 `value`（手枪族与狙击族各自成阶梯）。
- **~~R-12 旧定义~~（已废弃）**：~~稀有度 = ①附件槽位数（0/1/2/3/4）②品质档（DurabilityMax/Ergonomics/Accuracy 微调）~~ ——**附件槽位数改为型号固有属性**（§3.1.1 表逐枪定义），**"品质档"整条删除**。
- **仍然成立的关键约束（R-12 保留）**：**伤害链中不存在"稀有度乘区"**——`WeaponDamage` 逐型号写死（§4.4），combat §4.1 只乘 `AmmoTypeMult` 与耐久倍率。**所以"稀有度决定威力"是通过"不同型号不同 `WeaponDamage`"实现的，而不是通过倍率。**
  - 收益：既满足"高稀有度枪更强"（用户 R-15 要求），又避免与"口径 + 弹药 + 穿透"形成**双重缩放**，保住 ZS 式"选对口径比选贵枪重要"。
- **同型号内部的差异**：只有**耐久初值**（`Condition ∈ 60–100`，搜刮所得随机；**工作台可用维修包修理，但修不满**——上限受维修包 `condition_max` 限制，R-19）——**不再是"品质档"**。
- **视觉**：边框颜色 + 名称前缀（art-bible §3.6；concept §6 可读性优先）。**HUD 同时显示型号名**（ux-spec §3.2）。
- **⚠ R-30 交叉引用（R9 与稀有度阶梯）**：**R9 研究室的 `ResearchBonus = Aff` 加成乘在「装备面板」上**（`武器伤害 = 面板 × (1 + Aff)`，见 base-survival-npc §B.4 ⑤ / combat §4.1）——因是**乘法，越强（越高档）的型号获益越多** → **R9 会「拉大」本节的稀有度阶梯差距**（同一 `+60%`，SCAR-H 的绝对伤害增量远大于 AK-74U）。**这与 R-15「稀有度 = 型号层级阶梯」同向**；**⚠ R9 是绑定好感度的经营加成，不是"按稀有度档乘伤害"的运行时乘区**（本节核心约束"不存在稀有度乘区"**仍然成立**，见 §3.2）。

- **唯一保留"乘"的两项（例外说明）**：① **消音器的听觉半径倍率**（`×(1−0.4)`）——它是**世界状态量**（感知半径），不是武器属性，用乘更直观；② **镜的视野 / 射程倍率**（`scope_extend_view` / `scope_mult_eff_range`）——同理。**武器自身属性（伤害 / 后坐 / 精度 / 工效 / 弹匣）一律走加减。**
- **通用件 vs 专属件（R-19 补 · 对齐 ZS）**：ZS 配件带 `weapon_all`（通用）与 `weapon_id`（限定枪型）两个字段。本作同构——**握把 / 前握把 / 激光 / 手电多为通用件**；**枪管 / 护木 / 枪托多为型号专属**（避免"一把枪的枪管装到另一把"的荒谬感）。
- **配件是"装备维护"的第二条轴**：配件也有 `value`（ZS 为 2,500–65,000 量级），**死亡丢失需重新搜刮**（§6.9），与维修包一起构成长期维护压力（P6）。

> 所有修正最终汇入 combat §4.1 ① 的 `WeaponDamage_m / WeaponRecoil_m / WeaponAccuracy_m / WeaponErgo_m / WeaponMagazine_m`（**加法**），再由 combat §4 消费进 `AdsTime / CrosshairRecover / EffRange*` 等手感量。

### 3.7 武器耐久与卡壳（R-12 新增 · 对齐 ZERO Sievert A8）

- **耐久 `Durability ∈ 0..100`**：每次开火小幅下降（`k_dura/shot` ⚠待调）。
- **耐久影响三件事**（公式见 combat §4.6）：

| 耐久 | 伤害 | 精度 | 卡壳 |
|---|---|---|---|
| ≥ 70% | 全额（0 损失） | 全额 | 无 |
| < 70% | 线性下降至 −25% | 线性下降至 −15% | **`JamChance = (10 − Durability/10) / 100`**（55% → 4.5%） |
| = 0% | −25% | −15% | 最高；**武器不销毁**（仍可用，逼回基地修） |

- **卡壳态（Jammed）**：不可射击；排障方式 **V 键（100%）/ 换弹（100%）/ 强行开火（30%）**。
- **修理（R-19 改：消耗维修包 · 按武器大类分档）**：
  - **维修包 = 搜刮得来的消耗品**（对齐 ZS `repair_weapon.json` 的 `condition_gain` / `condition_max` / `condition_min` 结构）。每次修理**消耗 ×1**，回复 `condition_gain`（⚠待调，建议 40–60）；**耐久上限受 `condition_max` 限制 → 修不满**（稀缺性得以保留）。
  - **分三档 + 护甲独立，不按口径（R-19 拍板）**：

    | 维修包 | 适用 | **重量 wg**（R-46） | 说明 |
    |---|---|---|---|
    | **轻武器维修包** | 手枪 / SMG | **0.5 ⚠待调** | 最常见、最便宜 |
    | **制式维修包** | 步枪 / 霰弹 / DMR | **0.8 ⚠待调** | 主力 |
    | **重武器维修包** | 狙击 / 高口径 | **1.2 ⚠待调** | 最稀有 |
    | **护甲维修包** | 护甲（独立品类） | **1.0 ⚠待调** | 对齐 ZS `repair_armor.json` |

  - **⚠ R-46 重量来源**：**本作自定 ⚠待调**——ZS `repair_weapon.json` / `repair_armor.json` 的 `weight` 字段真值「**待查 `ZS_vanilla/gamedata`**」（本作采集的 `reference-zero-sievert-medical-loot.md §4` 未含重量列）。备货时"带几包维修"也计入负重。

  - ~~ZS 的「按 `caliber[]` 口径限定」（6 种）~~ —— **本作不采用**：本作口径体系与 ZS 不同，且按口径限定会造成"捡到一堆用不上的维修包"的挫败。**分档保留了"备货要对路"的决策，但不惩罚到细节。**

### 3.8 弹药口径与类型（R-12 新增 · 对齐 ZERO Sievert A6/A7）

> **同口径多弹种，Damage 与 Penetration 分轴**——"选对弹"比"换更强的枪"更重要（ZS 核心）。

```
口径 Caliber（示例）：
  9×18 / 9×19      → 手枪 · SMG          （低穿透，前期主用）
  .45              → SMG
```

| 弹种 | 伤害倍率 | 穿透倍率 | 附加 | 最佳对手 |

| **PS** 标准弹 | ×1.00 | ×1.00 | — | 通用 |
| **HP** 空尖弹 | **×1.25** | **×0.50** | — | **无甲 / 变异体**（僵尸、怪物） |

- `AmmoTypeMult` 代入 combat §4.1 ①（伤害）与 ③（穿透判定）；`AmmoPen` 代入 `Pen(ammo, dist)`。
- **弹药重量（R-46 新增 · 逐「发」计，按口径分档 · ⚠待调）**：弹药**按口径给单发重量**（本作自定；ZS `ammo.json` 的 `weight` 真值「**待查 `ZS_vanilla/gamedata`**」——本作采集的 `reference-zero-sievert-ammo-armor-mod.md §2` 未含重量列）：

  | 9×18 / 9×19 / 7.62×25 / 5.7×28 / .45（手枪弹） | **0.010** | 0.6 |
  | 9×39 / 5.45×39 / 5.56×45 / 7.62×39（步枪弹） | **0.016** | 0.96 |
  | 7.62×51 / 7.62×54R / 12.7×55（狙击 / DMR 弹） | **0.025** | 1.5 |

- **✅ 弹药携带压力（R-23 埋的伏笔 · **R-46 已落地**）**：三层决策意味着玩家**可能要同时带 HP 弹 + AP 弹**，**占用背包格「与」负重**（**两套独立限制**，§3.5 / §3.15）→ 与 R-21 现金经济（空投站采购）和 R-20 跑尸（弹药消耗）联动。**⚠ R-46 已改（原：R-23 记「**须复核**：背包容量是否支撑"带两种弹下潜"，若不支撑则玩家被迫在某一层段"打不动"（bad friction）」）**——**R-46 负重系统即该伏笔的落地**：负重与格数**分别独立**限制携带 → **"带两种弹"的代价变成"少带药 / 少带材料 / 背得动就走得慢"的取舍**，而非"物理上装不下直接卡死"（**软门槛**：超重吃惩罚、但不硬禁止，见 `base-survival-npc §A.3.1`）。**该项由"须复核"转为"已落地"**，后续只需在阶段 1 实测"负重曲线 vs 两种弹下潜"的手感（**平衡实测项**）。
- **⚠ 弹药 / 特殊弹药生产来源（R-27）**：**在基地工作室（R2）工作台生产**——原「军械库」职能于 R-27 并入工作室，军械库房间与其 NPC 维罗妮卡·维加一并删除。生产仍需材料、且**只在基地进行**（同"改装 / 修理仅基地工作台"的纪律，R-12）。

### 3.9 弓弩（无声武器 · B 档 · 后置）

> **明确不属于「照搬 ZERO Sievert」范围**——ZS 无弓弩系统。这是用户指定的**后期差异化增量**，**阶段 0–3 不实现**，此处只锁定定位与字段位。

- **核心卖点**：**完全无声**——比 **Sub 亚音速弹（感知半径 −50%）** 更彻底（**不产生听觉事件**），给潜行/暗杀玩法留门。
- **数据字段（仅预留，不实现）**：`Caliber = bolt`；`Silent = true`；`BoltRecoverChance`（弩矢回收概率，⚠待调）。
- **与枪械的机制差异**：实体箭矢（有飞行时间，可选重力下坠 ⚠待定）；弩矢命中/落地按概率**回收**；无枪声/弹壳/枪口闪；**代价**＝射速极低（单发装填）、容量小、近距散布大、**穿透中低**（对高 Class 护甲劣势）。
- **Tier**：**B 档**（资源充裕再加，不影响主线）。详见 `reference-alignment-zero-sievert.md §5`。

### 3.10 药品与药物原料（R-14 立 · **R-19 改三轴**）

> **背景**：自 R-14 起**回血渠道只有两条**——① **使用药品消耗品** ② **基地双人床休息回血**（base-survival-npc §B.3.2）。**医疗室是制药工坊**（输入药物原料 → 输出药品），**本身不治疗**。因此药品既是**唯一的地图中回血手段**，也是**必须提前备货的稀缺资源**——与 P2（搜刮即构建）、P6（撤即经营）同向。
> **R-19 口径变更（用户拍板）**：药品不再只有"回血"一个作用，而是**三轴** —— **`hp`（回血）· `bleed`（止血）· 尸毒感染度（`rot`）**。**普通绷带 `hp = 0`：只止血、不回血**（对齐 ZS 真值 `bandage`：`hp = 0` / `bleed = 1`）。⚠ **`wound`（伤口）第四轴：用户已明确「取消」**——不引入。**⚠ R-34 订正（✅ 已拍板（R-47 · 2026-09-26 用户确认：当场使用并立即生效））**：原「普通绷带 `hp = 0`：只止血、不回血」**改为「绷带 `hp` = +20（小回血 + 止血）」**——用户 R-34 拍板「治疗 HP 的药分小中大三种：绷带 20 / 急救包 40 / 医疗包 60」，故绷带现为**小回血档**，**同时保留止血（bleed −1）**（ZS 风格：bandage 既止血又微量回血）；本作不再沿用 ZS「绷带 hp=0」真值。

> **🔒 口径（R-32 · 用户拍板 · 勿违）**：**药品 4 品种全部平级**——**不存在"高阶 / 低阶 / 品阶 / 药品等级"概念**；4 品种（绷带 / 急救包 / **医疗包（R-34 替原强效药剂）** / 抗尸毒剂）是**作用轴分工**（`hp` / `bleed` / `rot`），**不是强弱阶梯**。**⚠ R-34：HP 回血轴 = 3 容量档（剂量档，非品阶）**——小·绷带 +20 / 中·急救包 +40 / 大·医疗包 +60；**强效药剂已删除**（其「buff + 副作用」定位与「无玩家数值成长」精神冲突，且医疗包已填满大回血槽）；**⚠ R-36：抗尸毒剂 → 抗毒血清**（职能由「`rot` −40 解毒」改为「**恢复 MaxHP 上限 +20 / R9 研究室放大至 +40，且不解除感染**」）；**新增稀有材料「僵尸血清」**（僵尸 / 怪物稀有掉落，**抗毒血清唯一制作原料**）；抗毒血清改为**可制作稀有物品**（不再靠搜刮直接获得）。见 §3.10 表。
> - **药品治疗效果的唯一放大渠道 = NPC 好感**（R9 研究室 `ResearchBonus = Aff`；`药品回复量 = 基础 × (1 + Aff)`；统一乘区 `EffectMult(Aff) = clamp(2.5×Aff − 0.5, 0.5, 2.0)`，60% → ×1.0 基准，见 base-survival-npc §B.4 / combat §4.1）。
> - **反例断言**：不得出现"用更好 / 更高级的药品获得更强效果"这类表述；**含改名重生** —— `tier` / `grade` / `rank` / `level` 凡指**药品品阶**的用法**一律禁止**。

- **使用规则**（对齐 ZS 的"用药需时间"手感）：
  - 药品在**背包内即时使用**，走**快捷栏（键 3–8，ux-spec §3.8）**；**有用药耗时**（见上表）。期间**不可开火**，移速 ×`speed_multiplier`（`0.5` = 减速一半；`0` = **完全定住**；⚠待调）。

  - **断粮 debuff 加剧**：`<15` 时**回血效率 −50%**（药品与双人床同减，base-survival-npc §A.3）。**注意：断粮只影响 `hp` 轴，不影响 `bleed` / `rot`**——否则会出现"饿着就止血失败"的不可读规则。
- **硬约束——不存在第三个回血来源**：医疗室（制药，R4）、厨房（R3）、温室（R7）、研究室（R9）、通讯室（R6，=空投站功能）**均不提供回血**；**NPC 不提供回血**（**⚠ R-31：建筑升级系统已整体取消，故"建筑升级"已不在回血来源清单内**）。断言见 §8 AC16/AC17。
- **稀有度与药品**：药品的**稀有度由品种固定**（绷带 C / 急救包 R / **抗毒血清 R（R-36 改名）** / 医疗包 E），**不是"同种药品有多个稀有度版本"**；（⚠ R-34：强效药剂已删，由 医疗包 替大回血槽、稀有度 E）因此稀有度对药品**只作 UI 层级表达**（名称前缀 + 边框，§3.2），**不改变任何轴的数值**（与 AC11 同口径）。**⚠ R-32：本处稀有度是掉落概率 / UI 层级表达，不得被读作"药品品阶"——稀有度 ≠ 品阶**（可测断言：同配方产出的同一药品，无论以何种稀有度出现，其 `hp` / `bleed` / `rot` 数值一致）。
- **掉落权重（暂定，待调）**：容器内 `药物原料 : 绷带 : 急救包 : 医疗包 : 僵尸血清 ≈ 100 : 45 : 12 : 2 : 8`（⚠ R-36：**抗毒血清不再直接掉落**——改为医疗室制作品，其唯一原料「僵尸血清」进入掉落表；现 5 项权重）。
  - **病毒 / 怪物楼层（99–41）**：`僵尸血清` 权重 **×2**（僵尸 / 怪物集中区 = 原料主产地；⚠ R-36：原「抗尸毒剂 ×2」取消——抗毒血清改为制作品）；
  - **封锁 / 底层（40–1）**：`急救包` 权重 **×1.5**、`僵尸血清` **×0.3**（枪伤为主、僵尸稀少；⚠ R-36：原「抗尸毒剂 ×0.3」改为僵尸血清）；
  - 整体药品掉率在深层更低——强化"越往下越穷"（concept §1.2）。
- **平衡意图**：药品稀缺 × 基地无即时治疗 → 玩家必须**备足药再下潜**；而 **R-19 的三轴让"备什么药"本身成了随楼层的决策**（上层带绷带 + 抗毒血清，下层带急救包 + 护甲）。"带多少药 / 带哪种药" = "能推进几层"，这是新的撤退决策轴。与基地保底套装同步：储藏室保底含**最低药品（绷带 ×2）**（base-survival-npc §B.4 / death-and-corpse §6.4）。

| **现金 Cash** | 货币 / 贵重品 | —（**不参与稀有度体系**） | 100 / 格 | **0.01 ⚠待调**（满格 100 张 = 1.0 wg） | 搜刮（容器 / 保险箱 / 敌人尸体）+ **Boss 保底** | **通讯室（空投站功能）**买入 / 卖出（base-survival-npc §B.4） | **本作唯一货币**；**仅在交易时使用**（R6 通讯室〔空投站功能〕买入 / 卖出）；⚠ R-32：原局外货币 `Credits` 已删除 |

- **本作唯一货币 = 现金（R-32 定 · 勿违）**：**`Credits`（信用点 / 局外货币）已随 meta 解锁树整体删除**（R-32 用户拍板）——**本作不存在第二种货币**，也**不存在任何 meta 解锁**（起始物资 / 武器蓝图 / 起始附件 / 改造折扣**均无解锁路径**；**物资 / 武器 / 武器附件全靠搜刮获得**）。

  - ⚠ **墓碑（R-32）**：~~「现金」≠「Credits」双货币对照（R-21 关键区分）~~ **已作废**——`Credits` 不再是本作概念，原双货币对照表删除。

- **为什么用"物品"而非"抽象数字"**：① 让交易**承担与其它物资同等的风险**——死了钱就得回来取，强化 P3（撤退张力）；② 复用已有的**掉落 / 容器 / 尸体 / 背包**系统，**零新增存储结构**；③ 与 ZS 把 `money` 作为可搜刮物品的做法一致（`reference-zero-sievert-meta-npc.md` §3 的 `trader.json`）。
- **投放与掉落（暂定，待调）**：
  - 容器内出现率随**楼层深度上升**（深层更"富"）；`黄金 / 珠宝` 类贵重品可作**高面额变体**（⚠待定是否引入）；
  - **Boss 掉落含保底现金**（§3.4 掉落表）；**D2 式重复击杀亦给**（概率与等级档固定、具体物随机，enemies-ai §3.7/§6.16）；
  - **不占快捷栏**（非可装备消耗品）；仅占**背包格**。
- **⚠ 平衡护栏（与 R-20 探索级重置联动 · 关键）**：现金属**可被探索级复位重复搜集的物资** → 存在**通胀风险**（反复刷浅层容器换钱）。三重护栏：① **同 seed 同批**——复位恢复的是**同一份**现金分布（确定性、不增不减，与 weapons-loot §6.9 同口径）；② **深层单份面额更高、浅层极低**——刷浅层收益趋近于 0；③ **空投站标价以深层物资为锚**，使"刷浅层现金"难以兑换高价值品。**实测项**见 concept §8.9⑤ / progression §6#15。
- **不可交易清单**：**任务关键物品不得卖出**（防误卖卡关，base-survival-npc §B.6 边界 12⑤）。
- **卖出折价**：玩家卖出物品按 `value` 的**折价率**（建议 40–60%，⚠待调）；**买入价 > 卖出价**，差价即"交易税"，防止"低买高卖"套利。

### 3.12 建材 Materials（R-28 新增）

> **背景**：R-28 用户拍板——基地房间的**房内装置**要玩家**搜集材料建造**（`base-survival-npc §B.3.2/§B.4`）。原先「材料」只是**建造**的一个抽象说法；本批次把它**具体化为 8 类材料类别**。**⚠ R-31：建造（含首次）为唯一代价来源——所有建造一律仅材料；建筑升级系统已整体取消**（原「首次建造 = 仅材料 / 建筑升级 = Credits + 材料」两套代价**已合并为一套**；理由：用户拍板"建造后就是完整状态，后续不再升级"）。

**结论：统一为一个 `材料 Materials` 大类（不拆分），下分两组**
- **① 建材 Construction（8 类）**——用于**建造房间房内装置**（**含首次；⚠ R-31：所有建造一律仅材料、不耗 Credits；不存在建筑升级**）：`钢材 Steel` / `线缆 Cable` / `电子件 Electronics` / `机械件 Mech Parts` / `化学试剂 Chemicals` / `布料 Fabric` / `木材 Lumber` / `燃料 Fuel`。
- **② 专用材料 Special（用途专一）**——**不与建材混用、不计入建造**：`药物原料 Medical Material`（仅医疗室制药，§3.10）、`钢缆 Steel Cable`（仅绳索绳缆合成，§3.6）等。
- **为什么统一而非拆分（R-28 结论）**：① **复用同一背包分区 / 掉落 / 容器 / 存储系统**（零新增存储结构，与「现金」同思路）；② 「材料」的**唯一语义 = "可消耗的建造物资"**（**⚠ R-31：建筑升级已取消，"升级物资"语义删除**），拆成两套反而会造成"这类材料能不能建房"的日常困惑；③ **区别只在"用途"**（建材 vs 专用），故用**同一大类 + 子分组**表达最省认知——**"材质"这一维度不作为分类轴**。

  | **现金** | ⚠ **本作自定**（ZS `money` 待查） | §3.11 |

  | **食物 / 饮料 / 食材** | ✅ **可复用 ZS `consumable.json` 真值**（0.1–1.0） | `base §A`（**本文件不单列**，落 base / 阶段 2 补表） |

- **`weight` 只进「负重系统」，不进 combat 伤害 / 手感结算链（R-46 硬约束）**：**不得**出现"枪更重 → 伤害更高 / 后坐更大"的乘区——**重量只通过 `CurrentLoad → 超重惩罚` 影响「移动维度」**。**⚠ 与 `combat §4.2` ⑧「重量 → 移速 / 体力惩罚」的关系**：**⑧ 的实现方式 = 本负重系统**（重武器推高 `CurrentLoad` → 触发超重），**不另设"逐枪独立移速乘区"**（否则与负重**双乘**，且无法解释"同时背两把重枪"）。见 `combat §4.9`。
- **⚠ 数据源纪律（`reference-alignment-zero-sievert.md §0`）**：**凡本作自定的重量值均标 ⚠待调**；**凡 ZS 侧真值未采集者，一律写「待查 `ZS_vanilla/gamedata`」，禁止凭印象书写 ZS 侧重量**。
- **设计意图（一句话）**：**负重把"搜刮"从"能装多少装多少"变成"背得动多少、值不值得背"**——它是 **R-20 跑尸 · R-21 现金经济 · R-23 弹药三层决策 · R-28 材料搜集**共同的**取舍闸门**（P6 撤即经营的深化）。
- **与「背包格」的关系**：**两套独立限制、同时生效**（§3.5）；**超重是软门槛**（吃惩罚、不硬禁止"背起来"）。**权威见 `base-survival-npc §A.3.1`**。

### 4.4 改造数值叠加（**R-19 改纯加减**）
```
// R-19：配件 = 属性「加减」，取代原「加乘分离」
WeaponDamage_m   = WeaponDamage    + Σ(附件.damage)
WeaponRecoil_m   = WeaponRecoil    + Σ(附件.recoil)
WeaponAccuracy_m = WeaponAccuracy  + Σ(附件.acc)
WeaponErgo_m     = WeaponErgonomics+ Σ(附件.ergo)
WeaponMagazine_m = WeaponMagazine  + Σ(附件.magazine_size)

// 由此派生（combat §4.1 ① / §4.2 / §4.8）
最终 Damage     = WeaponDamage_m × AmmoTypeMult × DamageMult(Durability) × EffRangeDmgMult(dist)
最终 Recoil     = WeaponRecoil_m × EffRangeRecoilMult(dist)              // §4.8 距离后坐曲线
最终 Accuracy   = WeaponAccuracy_m
最终 Ergonomics = WeaponErgo_m
最终 Capacity   = WeaponMagazine_m
最终 CrosshairRecover / AdsTime / SwitchTime = f(ClassRecoverMult, WeaponErgo_m)   // combat §4.2
```
- **为什么改加减（R-19 理由）**：① **对齐 ZS**（`w_mod.json` 214 条全是 `acc ±N` / `damage ±N` / `recoil ±N` / `ergo ±N`）；② **可逆**——卸载附件**精确回退**（无乘区残差）；③ **不会在大后期被乘区放大**（乘区叠加是"数值爆炸"的常见来源）；④ **更好读**——玩家能直接算"这把枪还差多少后坐"。
- **唯一例外**：**消音器的听觉半径倍率** 与 **镜的视野 / 射程倍率** 仍为**乘区**——它们是**世界状态量 / 视野量**，不是武器属性（见 §3.3）。
- ~~旧「加法区 / 乘法区分离」`(1 + Σ加成型) × Π(乘区)`~~ —— **R-19 已废弃**。**AC3 同步改为"加减可逆性"断言**（见 §8）。
- **注入约定（R-12 改写 · R-15 / R-19 保持）**：`WeaponDamage` 为唯一注入点（**裸值**）；combat §4.1 负责乘 `AmmoTypeMult`、耐久倍率与**射程倍率**——**两处不重叠、无双重乘算**。

## 6. 边界与异常（Edge Cases & Anomalies）
1. **背包满**：禁止覆盖；提示腾位/丢弃/分解，不吞物品。
2. **重复武器**：可装备第二把或分解（T 档丢弃即可，M 档分解产零件）。
3. **附件冲突**：槽类型不匹配（如把瞄具装弹匣槽）→ 拒绝并提示。
4. **卸载附件**：退回附件箱，数值回退正确（无残留加成）。
5. **槽位越界（R-15 改写）**：附件数不得超过**该型号固有槽位**（上限 4）；槽类型不匹配亦拒绝（§6.3）。**不存在"升级稀有度以增加槽位"的路径**——想要更多槽位必须**换型号**（如 AK-102 3 槽 → M4A1 4 槽）。
6. **Boss 专属/传奇唯一**：标记 `unique`，不重复掉落同 ID（防刷）。
7. **数值溢出**：最终 Damage/Capacity 设上限（防极端 build 破坏平衡，combat 协同）。
8. **掉落与死亡竞态**：敌人死亡同帧多次调用 → 只掉一次（enemies-ai §6.7 协同）。
9. **死亡留尸（含装备栏，R-12 同步 · R-20 改世界状态）**：死亡时背包与装备槽（**主武器 / 副武器 / 护甲**；~~近战~~ 已移除）全部**移入死亡点「尸体」**（**不消失**，可跑尸取回，death-and-corpse §3.2）；基地储藏室安全。**世界状态（R-20）**：**地面物品拾取状态与容器开启状态属 ③ 探索级层**——**同一次探索内拾取不回位**；**回基地再出发（新一次探索）时，地面物品与容器全部恢复为 seed 初始态**（**恢复的是同一 seed 的同一批物资，确定性、不增不减**）。奔跑取回流程支撑"用储藏室装备谨慎推进、规划多脱出口"的循环；**R-20 后跑尸路径上的敌人已复活**，绳索（跨探索保留）成为首选路线。
10. **尸体作为容器**：取回尸体时按**容器**交互（受背包容量限制，§6.1 背包满规则同样适用）；取空后尸体标记清除（death-and-corpse §3.6）。
11. **卡壳与耐久（R-12 · R-19 改维修包）**：卡壳态不可射击；耐久 0 时武器**不销毁**（仍可用，逼回基地修）；修理**仅限基地工作台、且必须消耗对应大类的维修包**（§3.7）；**维修包不匹配 → 拒绝并给出可读提示**；**耐久只能被推到该维修包的 `condition_max`，修不满**。是否允许"耐久 0 即报废"为 ⚠待拍板项。
12. **弹药与弹种（R-12 新增）**：口径不匹配的弹药**不可装填**（拒绝并提示）；野外换弹种需**占用一个空背包格**承接卸出弹药（背包满则不可换，对齐 ZS）；`bolt` 弹种（弓弩，B 档）不与枪械通用。
13. **无近战（R-12）**：弹药耗尽的唯一手段是**投掷物 / 切副武器 / 撤退**——UI 需在弹药见底时明确提示"无近战手段"（见 ux-spec）。
14. **药品使用中（R-14 · R-19 改三轴 · **R-34 补绷带口径**）**：用药耗时内**不可开火**、移速 ×`speed_multiplier`；**被打断则消耗不返还、效果不生效**（⚠待定：是否给"受击不打断"宽容档）。**HP 已满时使用药品应被拒绝**（不浪费），给可读提示——**但仅针对 `hp > 0` 的药品**：**⚠ R-36：抗毒血清（`hp = 0`，恢复 MaxHP 上限类）在 HP 满时仍可使用**（恢复上限与当前 HP 是否满无关；新拒绝条件 = "MaxHP 上限已达当前可达最大值"）（"解毒"与 HP 是否满无关）；**⚠ R-34：普通绷带现 `hp`=+20，归 `hp > 0` 档，HP 满时拒绝使用**（不再"不抬 HP"）。
15. **药物原料误用（R-14）**：原料是**材料**——对其"使用"操作**被拒绝**并提示"需在医疗室加工"；**原料在背包中不与药品同栏混排**（分列材料 / 药品，避免误选）。
16. **无药可用的死锁防护（R-14 · R-19 加强）**：回血只靠药品与双人床——**双人床是永久兜底**（基地内总可回血），因此**不存在"完全无法回血"的死锁**；但**楼层内断药**是合法且被鼓励的紧张状态（应通过基地药品提示与"带药量"决策来管理，而非削弱惩罚）。**R-19 补**：**"无止血药"与"无抗毒血清"不构成死锁**（⚠ R-36：抗毒血清只是"上限回复"，感染后不立刻致命）——出血会致死（combat §6.15），但**跑尸规则保证装备可找回**，且**濒死撤离是预期玩法**（不是失败态）。
17. **出血状态（R-19 新增）**：`BleedLevel > 0` 时**按秒扣 HP**、**不自行停止**；**回到基地后仍在出血**（医疗室不治疗），**双人床休息可缓慢回 `hp`，但既不止血、也不解尸毒感染**——`bleed` 只有药品能解；**⚠ R-36：`RotInfected` 感染态无任何药品 / 睡觉可解，唯一解除 = 战胜最终 boss**（base-survival-npc §B.3.1/§B.6）；**止血药在背包内即时生效**。出血致死走正常死亡流程（combat §6.15）。
18. **尸毒感染（R-19 立 · R-21 定案 · **R-36 简化重构**）**：⚠ **R-36：由「`RotLevel` 0–100 累积计量」简化为「二值感染态 `RotInfected`」**——**变异体（僵尸 / 怪物）攻击且造成伤害时 20% 几率使 `RotInfected = true`**（幂等；雇佣兵不触发、机械免疫，可测断言）；**感染不直接致死、基地内不自动衰减**。✅ **双人床不能解感染、血包（hp 药品）不能解感染、抗毒血清也不能解感染**——**唯一解除 = 战胜最终 boss**（「英雄救美的代价」；原 R-21「双人床能否缓慢降低 rot」待定项**已作废**）（base-survival-npc §B.4 / combat §6.16）。**断言**：双人床休息任意久、使用任何药品（含抗毒血清），`RotInfected` **始终为 true**，直至最终 boss 被击败。
19. **三轴药品的栏位与提示（R-19 新增）**：快捷栏需能区分三轴——**图标角标**分别表示 `hp` / `bleed` / `rot` 轴（art-bible 待补）；**使用被拒绝时须提示原因**（"未出血" / "HP 已满"；**⚠ R-36：抗毒血清不再有"未感染"拒绝条件**——它对已感染者与未感染者均可用，只恢复 MaxHP 上限、不解毒），避免玩家误判为 bug。

20. **建材的使用与建造（R-28 新增 · R-31 改写 · R-32 收口）**：建材（§3.12）是**材料**——对其"使用"操作**被拒绝**（同药物原料口径，§6.15），**不与药品同栏混排**；**所有建造（含首次）只扣材料**（**⚠ R-31：建筑升级系统已整体取消**——不再有"升级同时扣材料"一档；**⚠ R-32：`Credits` 已删除，建造不存在任何货币扣费**）。**R1 不消耗任何材料**（开局完整）。断言：**建造只消耗材料——不存在任何货币扣费路径**；**材料不足时建造入口置灰 + 显示缺量**（不静默）。
21. **（R-29 · R-32 改写）专属赠礼的边界**：① **不可卖出 / 不可被空投站收购**——卖出被拒并给出可读原因（"专属赠礼不可交易"）；**卡关风险已因"非唯一"消除**（R-32）；② **来源 = 稀少可重复、非唯一**（不参与常规掉落权重表，单列来源，但**可多次获得**）；③ **交付幂等**——同一 NPC 的赠礼**首次交付后不再加好感**；④ **送错人不加好感且物品消耗**（R-32 用户拍板，仅给不剧透的通用反馈）；⑤ **物品描述 / 工具提示 / 交付 UI 不得显示归属**（游戏内不提示该送给谁）；⑥ 赠礼**可存放于储藏室**（占背包格、不占快捷栏）。见 §3.13。
22. **负重与携带（R-46 新增）**：① **全类别物品有 `weight`**（§3.15 汇总表），**`CurrentLoad = Σ(物品 weight × 数量)`**（统计范围 = 背包格 + 装备栏；储藏室 / 暂存槽不计）；② **背包格（20）与负重（`CarryCapacity`）为两套独立限制、同时生效**（§3.5）；③ **超重是软门槛**（`LoadRatio > 1.0` 触发移速 / 冲刺 / 体力惩罚，**不硬禁止携带**）——**权威见 `base-survival-npc §A.3.1` / `combat §4.9`**；④ **取回尸体（§6.10）时若超重则惩罚生效**（跑尸取舍的来源）；⑤ **`weight` 不进 combat 伤害 / 手感结算链**（§3.15 硬约束）。
