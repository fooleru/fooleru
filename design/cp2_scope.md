## 0. CP2 定性（一句话）

**把 cp1 的「单张手工房」推进成「程序化生成的单层 + 能一层层往下走的下降循环 + 多武器切换」，验证「越往下走越险」的下行张力与「生成 → 可玩 → 下降」的闭环，迷雾已提前进入（R-70）、零风格系统、零垂直骨架、零存档、零 Boss。**

**做什么**：**房间 + 走廊程序化布局**（种子确定性单层，网格雕刻 + 贪心合墙）、**大地图（单层 2048×1376 = 128×86 tile）+ 摄像机跟随滚动 + 右键瞄准偏移**、下降循环（走到出口 → 下一层，保留 HP/武器）、多武器（手枪 + 霰弹，切换 + 补弹）、多敌人（僵尸近战 + 雇佣兵远程）。
**不做什么**：完整 S1–S5 空间风格系统、垂直骨架 / 绳索、NPC / 基地、存档、Boss / 精英、时间系统——一律推迟（**迷雾已提前进入 cp2（R-70）**，见 §2.11）。

> **一句话的边界**：cp2 验证的是**「能不能一路往下走」这件事本身**——生成是否可复现、下降是否不崩、换枪是否成立、越深是否越险。至于「下楼该不该回血」「楼层该长什么样」，属完整版 GDD 的课题，cp2 有意只取简化子集（见 §5）。

## 1. CP2 验证目标（可观测、可手测）

| # | 验证项 | 通过门槛 | 依据 / 落地 |
|---|--------|----------|-------------|
| G1 | **生成确定性** | 同 `seed + floor` 两次生成**逐要素一致**（掩体数/敌人数/出口点/拾取点）；不同 floor 布局不同 | `FloorGenerator.gd` `_mix(seed, floor)`；`--verify-gen` 逐层打印 |
| G2 | **下降循环零崩溃** | 走到出口 → 楼层 +1 → 重生成本层，**保留 HP 与武器**；收敛路径**零引擎崩溃 / 零解析错误 / 零运行时错误** | `Main.gd` `_descend()`；`--verify` 无头 bot |
| G3 | **多武器弹丸数与切换** | 手枪 = **1 弹丸/发**；霰弹 = **≥6 弹丸/发**；`1/2/Q` 切换正确、HUD 显示武器名 + 弹量 | `Player.gd` 武器表；`--verify-wep` |
| G4 | **多敌人（近/远双压力）** | 生成器**第 3 层起**产出雇佣兵（封顶 4）；**敌弹命中扣玩家血、友弹不误伤**；雇佣兵保持对射距离且开火受掩体 LOS 遮断 | `Mercenary.gd`；`--verify-enemy` |

**G1 量化门槛**：掩体数 `clamp(2 + floor, 2, 8)`、敌人数 `clamp(3 + floor, 3, 12)`（超限只到上限）；出口必落在**世界右 2/3 区域**且远离出生点；拾取点落在**合法空位**（远离出生/出口/掩体）。
**G2 量化门槛**：`--verify` 无头 bot **在任意深度阵亡或跑完均视为收敛**，只要 harness 进程干净退出（见 §6）。
**G3 量化门槛**：`pistol_pellets == 1` 且 `shotgun_pellets >= SHOTGUN_PELLETS(=6)`；切换后 `weapon_index` 正确。

任一 G 不达标 → **调参或修回归，不扩范围**。

## 2. 做清单（cp2 必交付）

### 2.1 程序化布局：两级 BSP（走廊街区 + 沿走廊小房间）（`scripts/gen/FloorGenerator.gd`，R-58 重构）
- **单层、种子确定性**：`generate(seed, floor) → { walls, floor_rects, rooms, spawn, exit, path, enemies, mercenaries, pickup, cols, rows, grid }`；`_mix(seed, floor) = (seed × 2654435761) ^ (floor × 40503)`。
- **世界尺寸（R-53）**：**2048×1376 px**（128×86 tile）；尺寸单一权威源 = `GameConstants.WORLD_W/H`。
- **布局算法（R-58 · 两级，贴近现实户型图）**：
  1. **一级 = 街区**：BSP 递归分割整层，**分割缝全部做成走廊**（3 tile，`corridor_chance = 1.0`）→ 把整层切成若干**街区**（`BLOCK_MIN=16 / BLOCK_MAX=34` tile）。
  2. **二级 = 房间**：每个街区**内缩 1 tile**（这圈实心就是「房间 ↔ 走廊」之间的墙），再用 BSP 切成**小房间**（`ROOM_MIN=6 / ROOM_MAX≈13` tile，越深略小），房间之间是 1 tile 薄墙 + **门**（2–3 tile），偶发内部过道（`ROOM_CORRIDOR_CHANCE=0.15`）。
  3. **街区开门**：每个街区在环上开 **1–2 个通往走廊的门**（`_punch_ring_door`：只选「内侧是房间地面 + 外侧是走廊地面」的位置）。
  4. 墙带（紧邻地面的实心格）**贪心合并**成少量墙矩形。
  - **结果**：**房间 93→108 个**（小房间 6–13 tile ≈ 96–208px）；墙 188→232 矩形；**地面 77–78%**（实心 22–23%，且全是 1 tile 薄隔墙，无大块实心）。
  - **为什么像户型图**：主走廊贯通 + 房间沿走廊双侧排布 + 房间之间用墙+门分隔 + 房间与走廊之间也有墙+门。
- **连通 / 寻路**：一级走廊缝连通所有街区；二级门连通街区内房间；街区门连通房间与走廊 → 全层连通。**BFS 求 spawn→exit 路径**（`path`）→ 保证出口 100% 可达（G5）+ 给无头 bot 导航。路径**保持原始 4 连通 BFS 路径**（曾试做"视线简化"，但 Bresenham 直线会**切墙角**——格子级通过、物理上过不去 → bot 卡死，已回退）。**出生 = 最靠左房间中心**；**出口 = 远端候选地面格随机选**（每层不同）。
- **无头 bot 已知局限（R-58）**：布局变密后（≈100 个小房间 + 2–3 tile 门），朴素"逐路点走位"的 bot 会在门框/墙角落**卡住来回摆动** → `--verify` 下降常在第 1 层 `TIMEOUT`。**这是内部验证工具的局限，不是游戏缺陷**（生成器 / 连通性 / 可达性由 `--verify-gen` 全绿覆盖；DoD 为「零崩溃」，TIMEOUT 亦判通过）。`Player.speed_mult` 为验证专用倍速（默认 1.0，验证时 >1），不影响正常游戏。
- **内容放置**：僵尸 `clamp(8 + floor × 3, 8, 40)`、雇佣兵 `clamp(floor × 2 − 4, 0, 16)`（第 3 层起）——**全部落在雕刻出的地面格上**（不卡墙），距出生/出口留净空；武器拾取点落在合法地面格。
  - **成群生成（R-62）**：`_sample_clustered()` —— 先随机选「**簇心**」（离出生/出口够远），再在簇心附近 `radius` tile 内的地面格里取 `cluster_size` 个点 → **同类型敌人聚成一簇**。参数：僵尸 `radius=3 / size=4`，雇佣兵 `radius=2 / size=3`。验证指标：12 层佣兵「最近同类邻居平均距离」= **37.3px ≈ 2.3 tile**（随机散布会是 150–300px）。
- **无风格系统**：不实现 `procedural-gen §4.8` 的 S1–S5 风格参数化；cp2 只做「走廊 + 相邻小房间、铺满、可战斗」的最小形态。
- **调参入口**：房间大小 → `ROOM_MIN` / `ROOM_MAX_BASE`；房间密度 → `BLOCK_MAX`（越小街区越碎 → 走廊越多）；走廊宽 → `CORRIDOR_W`；内部过道比例 → `ROOM_CORRIDOR_CHANCE`。
- **不变式**：地面（走廊/房间矩形）与墙（合并矩形）均由生成器给出、`Main._build_floor` 代码构建（`Main.tscn` 不写死尺寸）。

### 2.2 下降循环（`scripts/main/Main.gd`）
- 走到出口（`EXIT_RADIUS = 14 px`）→ `_descend()`：`_floor += 1` → `_build_floor(false)` 重新生成该层 → **保留玩家 HP 与当前武器**（`reset_hp = false`，仅复位位置/速度/状态，不回血）。**R-60：直接下降，无「撤离成功」对话框**（GUI 与无头验证两条路径一致）。
- **零存档**：`_floor` 为 `static`（跨 `reload_current_scene` 保留）；死亡重开 → `_floor = 1` 从头开始。
- **HUD**：`hud.set_floor(_floor)` 显示当前层数。
- **不做**：走楼梯间 UI、上楼回撤、楼层风格预告、电梯井。

### 2.3 多武器（手枪 + 霰弹 + 冲锋枪）
- **武器表**：`Player.gd` 用 `Dictionary` 存武器（`id` / `label` / `damage` / `pellets` / `spread` / `mag_size` / `reload_time` / `fire_cooldown` / **`auto`**）。
- **手枪**（index 0）：单发 1 弹丸，`damage 18` / `mag 12` / `reload 1.8 s`（沿用 cp1_scope Q3 拍板值）；**射击模式 = 单发（`auto=false`）**。
- **霰弹**（index 1）：`pellets 6` / 每弹丸 `damage 7` / 总散射角 22° / `mag 6` / `reload 2.2 s`（**手感占位值，待实测校准**）；**射击模式 = 单发**。
- **冲锋枪 MP5**（R-71 新增，**以背包物品形式开局携带**，见 §2.12）：**参考 ZS `mp5` 真值** —— `damage 13`（= ZS 13）/ `mag 30`（= ZS 30）/ `weight 2.3`（= ZS 2.3）/ 9×19 / 模式 AUTO；**射速**由 ZS `rof 4`（ZS 中**越小越快**）换算为 `fire_cooldown 0.075 s`（≈13.3 rps，落在 GDD §4.3「SMG 射速高」档）；连发加 3° 散布体现 ZS 后坐 85 偏高。**射击模式 = 连发（`auto=true`）**。
- **射击模式（R-71 关键手感规则）**：`auto=false` → **每按一次左键打一发**（**按下边沿**触发，按住不放**不会**连发）；`auto=true` → **按住左键持续射击**（受 `fire_cooldown` 限频）。
  - 实现要点：**不再用 `Input.is_mouse_button_pressed()` 轮询**（那等于把半自动变成全自动）；改由 `Player._input` 维护 `_trigger_held`（按住）与 `_trigger_edge`（本帧刚按下，消费后清零）。
- **切换**：`1/2/Q` 键 → `_switch_to(0/1)` / 循环切换；`give_weapon(id)` 新获得（首把自动选中）、`refill_weapon(id)` 补满弹。
- **HUD（R-74 紧凑化）**：**只保留楼层文字 + 一组色条** —— HP / 体力 / 负重 / **弹匣** / **备弹**。所有数字文字（HP / 体力 / 负重 / 弹药 / 超重提示）**已移除**（超重只剩「斜纹 + 红色底块」两档视觉）。
- **弹药 / 备弹（R-74，见 §2.13）**：装填与**上膛**都从「当前武器口径」的备弹池扣；备弹池里没有子弹 → 装填失败（弹药不凭空出现）。
- **不做**：稀有度轴、配件、耐久、射程曲线、弹药类型分流（cp2 只做「弹丸数差异 + 射击模式」这两条可观测手感差）。

### 2.4 无头验证入口（工程交付，供 QA 复跑）
- `--verify`：下降循环 bot（始终朝出口走、顺路打最近僵尸、到出口即下降）。
- `--verify-gen N`：纯逻辑生成 N 层，逐层断言「有敌人 + 出口/拾取在界内」。
- `--verify-wep`：断言手枪 1 弹丸 / 霰弹 ≥6 弹丸 / 切换正确；**R-71 追加**：三种武器的 `auto` 标志 + **射击模式行为**（真实输入链路按下并保持 24 物理帧 → **手枪只出 1 发**、**冲锋枪 ≥3 发**）+ 冲锋枪数值 = ZS MP5 真值（dmg 13 / mag 30 / weight 2.3）。
- `--verify-move`：断言 `Player.dir_from_keys()` 的 W/A/S/D 方向符号约定（W=上=-y ｜ S=下=+y ｜ A=左=-x ｜ D=右=+x ｜ 全不按=零向量）——**锁定移动方向，防止再次回归**（W 键曾被误写为 `+y`，导致无法上移）。
- `--verify-enemy`：断言**多敌人**——雇佣兵生成曲线（第 3 层起出现、封顶 4）+ **敌我子弹分层**（友弹 mask=5 打 enemies ／ 敌弹 mask=3 打 player）+ 伤害路径（敌弹扣玩家血、友弹不误伤玩家、友弹扣敌人血、敌弹不误伤敌人）+ 雇佣兵可开火。
- `--verify-map [floor]`：导出该层 **ASCII 地图**（`#` 墙 / `.` 地面 / `S` 出生 / `E` 出口），供人工肉眼核对布局。
- `--verify-mapui`：断言**楼层地图 UI**——默认隐藏 → `M` 显示 → 再 `M` 隐藏 → **`Esc` 关闭（含"已关闭时按 Esc 无副作用"）** + 贴图尺寸 = `128×86`。
- `--verify-wallblock`：断言**子弹不得穿墙**——清空墙体构受控空间后：① 隔墙射向玩家的敌弹**玩家不掉血 + 子弹被墙吃掉**；② 生成在**墙体内**的子弹**立刻消失**；③ 雇佣兵隔墙 `_has_los() == false`。
- `--verify-nav`：断言**敌人寻路流场**——在 128×86 网格上抽样 80 个地面格：可达率（连通性）、每个可达格的 `flow_dir` 非零、沿距离场下坡走**必达目标格**。
- `--verify-faction`：断言**阵营系统**——僵尸/佣兵 faction 不同（1/2）+ 分层（4/8）+ 掩码（友 13 / 敌 7）+ 受控空间下**敌弹穿过同阵营佣兵不扣血**、**命中敌对阵营僵尸扣血**。
- `--verify-pause`：断言**暂停功能**——初始未暂停 → `Esc` 打开暂停页并 `get_tree().paused=true` → 再按 `Esc` 恢复；两个按钮存在；**并用 `can_process()` 验「世界真的停」（玩家/敌人），而不只看暂停标志位**（R-68）。

### 2.5 多敌人（近战僵尸 + 远程雇佣兵）
- **僵尸 Zombie**（既有）：近战直冲（`CHASE → ATTACK`），威胁来自**贴身缠斗**。**R-61**：追人走 **NavGrid 流场**（会绕墙/穿门），不再是直线撞墙。**R-73**：双轴感知（视觉 60 / 听觉 180，**听觉主导**）+ Alert/搜索/脱战。**R-76**：攻击前摇 `ZOMBIE_ATTACK_WINDUP` **0.4s → 0.2s**，即「**进入攻击距离（16px）→ 掉血**」的总延迟 = **0.2s**（语义由用户拍板：不是"接触后 0.2s 才起手"，而是"被贴身后只等 0.2s 就挨打"）→ 僵尸变凶，拉开距离的窗口变窄。
- **雇佣兵 Mercenary**（R-52 新增）：**远程对射**，与僵尸形成「近 / 远」两种压力：
  - **保持距离**：死区 `PREFERRED_DIST ± RANGE_TOLERANCE`（78 ± 14 px）内原地开火；太远推进、太近后撤 → **不能靠站桩风筝**。**R-61**：推进走 **NavGrid 流场**（绕墙），后撤仍直线。
  - **LOS 门控（R-57 修正）**：**身体中心**→玩家射线若被墙挡住则**不开火**，先走位找角度 → **掩体第一次有了战术意义**。（原从「枪口」起算：枪口 8px 前伸可能戳进墙里，而射线起点在墙内时 `hit_from_inside` 默认 false 会**漏判** → 隔墙开火。改为**身体中心**起算 + `hit_from_inside = true`。）
  - **子弹不穿墙（R-57）**：`Bullet._sweep()` 射线加 `hit_from_inside = true` → **生成在墙体内的子弹立即消失**，不再「从墙里飞出去」；配合上面的 LOS 修正，**敌弹无法穿墙**。
  - **慢速可躲子弹**（420 vs 玩家 1200）：给走位/翻滚闪避窗口；命中扣血 9。**R-62：射速提高**（`MERC_FIRE_COOLDOWN` 1.15 → **0.60**，前摇 0.45 → 0.35）。
  - **更脆**（HP 45 vs 僵尸 70）：远程的代价。
  - **R-75：佣兵战术（点射 / 换位 / 掩体 / 避墙后撤）** —— 死区内**不再站桩连射**，改为真人佣兵的三段节奏：
    - **① 点射（burst）**：每组 `randi_range(MERC_BURST_MIN 3, MERC_BURST_MAX 5)` 发；**组内**用 `MERC_BURST_GAP = 0.16s` 短间隔，**一组打完**进入 `MERC_BURST_PAUSE = 1.1s` 停火窗口（口径全部集中在 `GameConstants`，脚本不写魔法数）。
    - **② 停火就换位**：停火窗口里不再原地不动 —— 优先移动到 `_find_cover()` 选出的**掩体点**（速度 `MERC_REPOSITION_MULT`），周围没掩体就**侧移**（`MERC_STRAFE_MULT = 0.75`），且**每组换一次侧移方向**（`_strafe_side` 取反）→ 打破玩家预瞄，配合 GDD「不能靠站桩风筝」。
    - **③ 掩体判定（不变量）**：`_find_cover()` 在自身周围 **16 方向 × 2 半径**（`MERC_COVER_RADIUS = 40px`）采样，候选点必须同时满足 **是地面**（`NavGrid.is_floor`）+ **离玩家 ≥ `MERC_COVER_MIN_DIST = 40px`**（太近的"掩体"没意义）+ **站上去看不到玩家**（`LosUtil.has_los_world() == false`）→ 得分取「离理想距离最近」。选不出就返回 `Vector2.ZERO` 走侧移分支（**不是失败**）。
    - **④ 后撤避墙**：`_retreat_dir()` 依次试 **0° / ±45° / ±90°**，取第一个「前进 24px 仍是地面」的方向；**墙边不再原地磨**（原实现只有单一远离方向，贴墙时会被墙吃光位移）。
    - **⑤ 状态复位**：`_enter_alert()` 调 `_reset_burst()`，重新交战时点射/掩体状态归零；`WINDUP` 结束后 `shots_fired += 1` 并按「组内 / 组间」设 `fire_cd`。
    - **不做**：协同包抄、真正的掩体寻路（沿墙走位）、换弹 / 弹药经济、压制射击。
- **敌我双向子弹**（`Bullet.hostile`）：同一 `Bullet.tscn` 承担双方弹药，靠 `collision_mask` 分层（友弹 5 = 墙\|敌 ／ 敌弹 3 = 墙\|玩家）**天然互不误伤**；敌弹染红橙以区分玩家黄弹。
- **生成**：`FloorGenerator` 的 `mercenaries` 列表——**第 3 层起出现**，数量 `clamp(floor × 2 − 4, 0, 16)`，落在**雕刻出的地面格**上、距出生 ≥ 240 px。**成群生成**（见 §2.1 R-62 簇）。
- **阵营与互相攻击（R-62）**：**僵尸 = 「亡灵」`FACTION_UNDEAD`／雇佣兵 = 「雇佣兵」`FACTION_MERC`／玩家自成一营**。每个敌人的**目标 = 感知半径内最近的敌对单位**（玩家，或其他阵营的敌人）→ **僵尸与雇佣兵见面会互相攻击**；**同阵营不互打**。
  - **碰撞分层**：`1=墙 ｜ 2=玩家 ｜ 4=亡灵 ｜ 8=雇佣兵`（僵尸 `layer=4`、雇佣兵 `layer=8`、双方 `mask=15`）。
  - **子弹掩码**：敌弹 `mask=7`（墙\|玩家\|亡灵）→ 打玩家与敌对阵营、**天然不打同阵营佣兵**（层 8 不在掩码内）；友弹 `mask=13`（墙\|亡灵\|佣兵）→ 打两个阵营的敌人。
  - **寻路**：目标是玩家时走 NavGrid 流场（绕墙）；敌对阵营目标用直线 + 滑动（流场是玩家为源的单一场，不做多目标）。
- **不做**：怪物 / 机械、**真正的掩体寻路**（沿墙走位 / 掩体间转移；R-75 只做到「就近采样一个掩体点并走过去」）、协同包抄、换弹 / 弹药经济。

### 2.6 视图：大地图 + 摄像机（R-53 / R-54）
- **世界远大于视口**（2048×1376 vs 320×180）→ **`Camera2D` 跟随玩家**（`Main._update_camera`），limits 锁世界矩形防露空白。
- **瞄准偏移（ZS 式，R-54）**：**右键瞄准**时摄像机朝**准星方向**偏移（最多 `AIM_LOOKAHEAD = 90 px`）→ 玩家因此**偏离屏幕中心**、能看到更多前方；松开右键（`position_smoothing`）**平滑回中**。
- **准星**：仍在 `CanvasLayer`（屏幕空间），不随摄像机移动。**R-56**：光标用 `MOUSE_MODE_CONFINED_HIDDEN` **锁在窗口内** + 准星 `position` **clamp 到视口矩形**（双保险）→ 不会跑到屏幕外。
- 摄像机挂 **`Main`**（非 `Player`）——避免玩家瞄准转头时带着画面一起旋转。

### 2.7 楼层地图（R-56 · 按 M 显示/隐藏）
- **`M` 键**切换**楼层地图叠加层**（`scenes/ui/FloorMap.gd`，CanvasLayer `layer=15`，位于 HUD 之上、死亡画面之下）；**`Esc` 键**在**地图打开时**关闭它（地图已关闭时按 `Esc` 无副作用，不占用 Esc 的其他潜在用途）。

- **每层生成后由 `Main._build_floor` 重新 `set_floor`**（网格 / cols / rows / 出口 / 玩家引用）；显示时每帧重绘玩家点。
- headless 下**不建 GPU 贴图**（避免无渲染报错），尺寸断言走 CPU 侧 `Image`。
- **不做**：迷雾（探索进度可视化）、房间名 / 图例、缩放 / 拖动。

### 2.8 敌人寻路：NavGrid 流场（R-61 新增）
- **问题**：房间布局变密后，敌人"直线追人"会一直撞墙（`Zombie.CHASE` 与 `Mercenary` 的推进原本都是 `to_p.normalized()`）。
- **方案**：新增 **`NavGrid`（`scripts/nav/NavGrid.gd`）** —— **`preload` + `static`（非 autoload）**，**流场（flow field）**：
  1. 以**玩家所在地面格**为源，在整层网格（128×86）上跑一次 **BFS** 得到**距离场** `dist`（-1 = 不可达）；
  2. 任何敌人只需读自己所在格的 `dist`，朝「`dist` 更小的邻格」走 → **天然绕墙 / 穿门**；
  3. **一次 BFS 服务全部敌人**（远低于逐敌人 A*）；**玩家换格才重算**（`update_field` 内部早退），每帧只调一次。
- **寻路距离**：`MAX_DIST_TILES = 200`（tile，3200px）—— **覆盖整层**（比改动前的"只能直线"是质的提升；该常量即「寻路最大距离」旋钮）。BFS 传播超过该距离的格记为不可达。
- **防切墙角**：允许 8 邻域，但**对角步要求两颗正交邻格都是地面**；`flow_dir` 无路时返回 `ZERO`，敌人退化为直冲（不卡死）。
- **接线**：调用方 `const NavGrid := preload("res://scripts/nav/NavGrid.gd")`（`Main` / `Zombie` / `Mercenary` 各一份）；`Main._build_floor` → `NavGrid.set_grid(...)`；`Main._process` → `NavGrid.update_field(player.global_position)`；`Zombie.CHASE` / `Mercenary._advance_dir()` 改用 `NavGrid.flow_dir()`。
  - **⚠ 不用 autoload 的原因（R-63）**：autoload 要在 `project.godot` 注册，而**外部改动 `project.godot` 时编辑器若不重读项目设置**（只重扫文件系统），就会报 `Identifier "NavGrid" not declared`。`preload` 在**解析期**即可解析、不依赖项目设置 → 无此脆弱点（与本项目 `FloorGeneratorScript` / `PlayerScript` 的既有模式一致）。
- **验证**：`--verify-nav` —— 网格 128×86，抽样 80 个地面格中 **78 可达（97.5% 连通）**、**全部可达格均有方向**、**12/12 次「沿距离场下坡走」都到达目标格**。
- **不做**：障碍代价（家具 / 软掩体）、多目标、动态障碍（其他敌人不参与避让）、路点平滑。

### 2.10 暂停（R-64 新增）
- **按 `Esc` 打开暂停页面**（楼层地图开着时，`Esc` **先关地图**，再按才暂停）；再按 `Esc` 或点「继续游戏」恢复。
- 暂停页：`PauseScreen`（CanvasLayer `layer=30`）—— 半透明黑底 + 标题「已暂停」+ **「继续游戏」** / **「退出游戏」** 两个按钮。
- **实现要点**：
  - 暂停用 **`get_tree().paused = true`**（玩家 / 敌人 / 子弹全停），而不是只置标志。
  - `Main` 设 **`process_mode = PROCESS_MODE_ALWAYS(3)`** —— 否则暂停后连 `Esc` 都收不到（输入同样会停）。
  - **⚠ `process_mode` 会被子节点继承**（R-68 实机 bug）：`Main = ALWAYS` 会让 `TestRoom`（玩家 / 敌人 / 子弹）**一起变成 ALWAYS** → `get_tree().paused` 只停了 `Main._process`，**世界照跑**。所以必须**显式指定每个子节点**：`TestRoom / Camera / HUD / DeathScreen / MapLayer / HintLayer / CrosshairLayer = PAUSABLE(1)`、`BackpackLayer / PauseScreen = WHEN_PAUSED(2)`。验证也用 `can_process()` 而不是只看 `get_tree().paused`。
  - 暂停页设 **`process_mode = PROCESS_MODE_WHEN_PAUSED(2)`** —— 保证按钮在暂停时仍可点。
  - `Main._process` 在 `get_tree().paused` 时**早退**，不再跑摄像机 / 流场 / 撤离判定。
  - 暂停时 `Input.set_mouse_mode(VISIBLE)` 显示系统光标以便点按钮；恢复后准星脚本会重新隐藏光标。
  - 死亡画面（`_game_over`）时不允许暂停。
- **退出游戏**：先 `get_tree().paused = false`，再 `get_tree().quit()`。
- **验证**：`--verify-pause`（初始未暂停 → Esc 暂停并显示 → 再 Esc 恢复 + 按钮存在）→ **PASSED**。

### 2.11 战争迷雾（R-70 新增）

> **来源**：用户本次要求「为地图生成战争迷雾」；经主理人**四轮问询冻结口径**（下 ①–⑤ 逐字登记，**不得自行修改或"优化"**）。设计侧权威规格见 `design/gdd/fog-of-war.md`（v0.6；本节为 **R-70 落地口径**，对应 `fog-of-war.md` 的 **R-70 落地附注**）；视觉规格见 `art-bible §6`（三态遮罩，A-03）。**cp2 为原型级实现，不落完整版**（不引入光照、不落 shader）。

**① 范围 = 双载体**
- **世界主视角**：做**三态**（未探索 / 已探索 / 可见）。
- **`M` 键地图界面**（**复用既有 `FloorMap`**，§2.7）：**复用同一份迷雾栅格**渲染「**已探索亮 / 未探索黑**」——**仅地形**，不透视敌人。

**② 三态语义（对齐 `fog-of-war §3.1` / `art-bible §6`）**

| 状态 | 世界主视角 | `M` 键地图 |
|---|---|---|
| **未探索** | **全黑**（不透明、无信息） | 黑 |
| **已探索** | **压暗去饱和**（**仅地形**，**无动态物体**） | **亮** |
| **可见** | **全彩**（含敌人 / 容器 / 掉落） | —（地图不分可见，已探索即亮） |

**③ 视野与 LOS**
- **视野半径 = 10 格（= 160px @ tile 16px）**——**R-70 锁定**（GDD 的「8–10 格 ⚠待调」取上界 10；**正式值仍待阶段 1 试玩校准**）。
- **LOS = 墙体 / 关闭的门阻断**；**半高家具 / 箱子不阻挡视线**（对齐 `fog-of-war §3.2 / §6#1`；cp2 中「箱子」= `Crate`，见 §2.9）。

**④ 不可见区完全隐藏**
- **敌人 / 雇佣兵 / 箱子 / 地面掉落 / 出口标记**仅在**「可见」格**上呈现。
- **已探索但不可见** → **不呈现任何动态物体**（只留压暗地形）。

**⑤ 本次为 cp2 原型级实现**
- **允许不用 shader**（**同层覆盖绘制**即可，如世界层上叠一张迷雾覆盖层）。
- **不引入光照系统**——`art-bible §6` 的「世界 → **光照** → 迷雾 → HUD」次序中，**「光照」一环本次为空**（只保留其位次语义，不实现）。

### 2.12 物品占格 + 右键菜单（使用 / 装备）（R-71 新增）

> **来源**：用户三条要求——① 手枪改为单发射击；② 背包里加一把冲锋枪、**占 6 格**（参数参考 ZS 的 MP5）；③ 在物品图标上**按右键弹菜单**，含「使用（消耗品）」「装备（武器、护甲）」。①②的武器数值见 §2.3。

#### 2.12.1 物品占格（`w × h`）
- 物品字典新增 **`w` / `h`**（占用格数，缺省 `1×1`）与 **`gx` / `gy`**（在网格中的**格子坐标**）；`kind` 区分 `consumable / misc / weapon / armor`。
- **MP5 冲锋枪 = `3×2` = 6 格**（用户指定"占 6 格"）；手枪 `2×2`、霰弹枪 `3×2`、防弹背心 `2×2`、消耗品与杂物 `1×1`。
- **放置 = 行优先找空位**（`Backpack.find_free(occ, w, h)`）：从 (0,0) 起按行扫描第一块能放下 `w×h` 的空位。
- **放不下就拒绝**：跨栏搬运前先 `try_place` 试放，**目标栏没有 `w×h` 空位则取消搬运**（物品留在原栏）——**不允许叠放**。
- **命中测试按物品矩形**（不是单格）：`inv_item_rect(it)` / `cont_item_rect(it)`；3×2 物品的**左上角格与右下角格**都命中同一件物品（`--verify-item` 断言）。
- 绘制：物品按真实占格画成一块矩形（占格 ≥4 再画一条内框，让"大件"一眼可读）；**不画格线切割**，避免图标被割裂。
- 初始化：打开背包时对两栏做一次 `ensure_placement()`，给"还没有坐标"的物品补位置（列表顺序 = 放置顺序）。

#### 2.12.2 右键上下文菜单（`scenes/ui/ItemMenu.gd` · `MenuLayer` layer=14）
- **触发**：在背包 / 箱子里的**物品图标上按右键** → 在鼠标附近弹出菜单（面板夹在 320×180 视口内）。
- **菜单项按物品类别给**：
  | 物品类别 | 菜单项 |
  |---|---|
  | 消耗品（医疗包 / 罐头 / 饮用水） | **使用** |
  | 武器 / 护甲 | **装备** |
  | 箱子里的任意物品 | 额外给 **移入背包** |
  | 杂物（弹药盒 / 零件 / 布料） | 仅显示「（不可使用）」灰项 |
- **使用（消耗品）**：按 `use` 载荷生效 —— 医疗包 `+40 HP`、罐头 `+10 HP / +10 体力`、饮用水 `+30 体力`；随后**移除该物品**（在背包里则同时**减负重**）。
- **装备（武器）**：`Player.equip_weapon(id)` **替换当前武器槽**，被换下的武器**变回背包物品** → **物品数量守恒、不凭空消失**；负重同步（-新+旧）。
- **装备（护甲）**：`Player.equip_armor(item)` 装上护甲，`take_damage()` 按 `reduction` **减伤**；换下的护甲同样变回物品。**原型最小护甲 = 防弹背心（2×2 · 减伤 15%）**。
- **关闭**：点菜单项 / 点菜单外 / 按 `Esc` / 关背包 —— 全部关闭。`Esc` 优先级更新为 **菜单 → 背包 → 地图 → 暂停**。
- **交互层次**：菜单挂在**独立 `CanvasLayer`（layer=14，高于 Backpack 12、低于地图 15）**，`process_mode=WHEN_PAUSED`；鼠标事件仍走 `Main._input`（R-68 的铁律：**不能**用 `_unhandled_input`，会被 GUI 吞掉）。
- **不做**：拖拽移动消耗品到快捷栏、物品堆叠、右键菜单里的"丢弃 / 拆分"、护甲耐久与部位、武器附件。

#### 2.12.3 验证（`--verify-item`）
断言 8 组：开局 MP5 占 6 格（`free_slots` 与负重同步）→ 占格命中（两角同一件）→ 行优先空位（3×2 后 1×1 落 (3,0)）→ **满栏必拒绝**（`find_free` 返回 (-1,-1)）→ **真实右键链路**开菜单 / 点「装备」/ 武器换成 MP5 且**旧武器回到背包（数量守恒）**/ 菜单自动关闭 → **使用医疗包**（+40 HP / 物品 -1 / 负重 -3.0）→ **装备护甲**（减伤 0.15；20 点伤害只掉 17）→ 界面正常关闭。→ **PASSED**。

### 2.13 弹药与备弹（R-74 新增）

> **来源**：用户「手枪和mp5装填时要消耗弹药。每个弹药箱的容量为50发」；口径存储方式由用户拍板为 **按口径分池**。

- **备弹池**：`Player.reserve: Dictionary`，**口径 → 发数**。**手枪与 MP5 同为 9×19 → 共用一池**；霰弹枪 12×70 → 独立一池。
- **消耗点**：装填（`start_reload`）与**上膛**（`_build_loadout` / `equip_weapon`）都从对应口径池扣，**能装多少装多少**；**池空 → 装填失败**（弹药不凭空出现）。开火只扣弹匣，不直接扣备弹。
- **弹药盒物品**：`AMMO_BOX_ROUNDS = 50`（每盒 50 发），带 `caliber` 字段；右键菜单归到 **使用** 项（标签「补充备弹」）→ 并入对应口径池并**移除该物品**（在背包里则同时减负重）。
- **拾取**：`WeaponPickup` 若玩家已拥有该武器 → **补备弹（+50，按该枪口径）**，不再是"弹匣凭空虚满"。
- **跨层**：备弹只在 `reset_full`（重开 / 死亡）时重置 → **下降时弹药带下楼**（搜打撤的资源压力成立）。
- **HUD 表达（配合 §2.3 紧凑化）**：弹药从文字改为**两条色条** —— 上条 = 弹匣余量，下条 = 当前口径备弹（满格参考 `RESERVE_BAR_MAX = 200`）。左上角**不再出现任何数字**。
- **验证**：`--verify-ammo` 六组断言（见 §2.4）→ **PASSED**。
- **不做**：按弹种分池之外的细分（空尖/穿甲）、弹匣内剩余弹的保留（换弹即弃）、弹药重量随弹种变化、消音/亚音速对听觉的影响（属感知批次）。

### 2.14 饥饿与口渴（R-77 新增）

> **来源**：用户「给玩家加入饥饿和口渴两种状态值，并且可以用食物和饮料恢复。」；两条决策由用户拍板：**归零惩罚 = 缓慢持续掉血**、**HUD = 常驻再加 2 条色条**。

- **两条独立的 0..100 生存条**：`Player.hunger` / `Player.thirst`，**随时间自然下降**（`_update_survival(delta)`，与体力/负重同在 `_physics_process` 里驱动）。
- **衰减速率（口径集中在 `GameConstants`）**：饥饿 `0.225/s`（满→空 ≈ 444s ≈ 7.4 分钟）、口渴 `0.325/s`（≈ 308s ≈ 5.1 分钟，**口渴更快→ 水更稀缺**）。刻意偏慢：原型目的是给"搜刮"一个**除了弹药之外的第二理由**，但不能让生存压力盖过「搜打撤」的核心战斗循环。
  - ⚠ **R-92 已把两者各减半**（原 `0.45/s` / `0.65/s`）。比值 `0.325 / 0.225 ≈ 1.444` —— **口渴相对更急的性质不变**，只是整体压力下调。
- **归零惩罚 = 缓慢持续掉血**：饥饿 `STARVE_DPS = 0.5/s`、口渴 `DEHYDRATE_DPS = 0.75/s`（两条同时归零 = 1.25/s）。
  - ⚠ **R-92 已把两者各减半**（原 `1.0/s` / `1.5/s`），比值 `1.5` 不变。
  - ⚠ **这条伤害绕过护甲减伤**（`Player._survival_damage()`，与 `take_damage()` 的唯一区别）—— **防弹背心挡子弹，不挡饿**；`armor_reduction()` 只应作用于战斗伤害。已做成断言（见 `--verify-survival` ④）。
- **恢复（食物 / 饮料）**：消耗品 `use` 字典新增 `hunger` / `thirst` 字段，走**与右键菜单同一个 `_use_item()`** 通路：
  - 罐头（食物）：`hunger +35`、`heal +10`、`stamina +10`
  - 军用口粮（食物，R-77 新增）：`hunger +75`、`heal +5`
  - 饮用水（饮料）：`thirst +45`、`stamina +30`
  - 右键菜单动词随内容变化：**食物 → 「食用」／饮料 → 「饮用」**（不再一律「使用」）。
- **上限钳制**：恢复到 `HUNGER_MAX / THIRST_MAX` 即停，**不溢出**（90 + 口粮 75 → 100）。
- **开局**：背包给 **MP5 + 罐头 + 饮用水**（生存值可立刻验证，也避免"想测却没东西吃"）。
- **HUD（配合 §2.3 紧凑化：只留楼层文字 + 色条，无数字）**：在「HP / 体力 / 负重」之后、**弹药之前**插入**饥饿（橙棕）+ 口渴（浅蓝）**两条常驻色条，共 7 条。见底时该条**染成警示红**，作为"该吃东西了"的视觉信号。
- **不做**：烹饪 / 食物腐败、体温 / 疲劳等其它生存条、饥饿影响移速或体力上限（本次惩罚只走掉血）、食物重量随种类影响负重以外的效果。

### 2.15 暂停页：玩家信息 + 显示地图（R-78 新增）

> **来源**：用户「在暂停界面显示玩家信息：生命/生命上限、体力/体力上限、饥饿/饥饿上限、口渴/口渴上限，再添加显示地图的按钮。」

- **四项状态（`生命 / 体力 / 饥饿 / 口渴`，各「当前 / 上限」）**：`Main._refresh_pause_stats()` 在**每次进入暂停页时**刷新（不是每帧刷），数值直接取 `player.hp / stamina / hunger / thirst` 与各自上限，四条各有配色（生命绿 / 体力蓝 / 饥饿橙 / 口渴浅蓝），与 HUD 色条同一套语义。
  - **刻意用文字而不是 HUD 那套色条**：暂停是"停下来读信息"的时刻，色条要靠比较，**数字是直接可读的**。这与 R-74「HUD 去掉所有数字」是**两种不同的读数场景**，不冲突。
- **「显示地图」按钮**：点击后**隐藏暂停页、由地图接管**，并记 `_map_from_pause` 标记。
  - ⚠ **层级问题**：`MapLayer` 在 layer **15**、`PauseScreen` 在 layer **30** 且盖着 0.75 黑遮罩。若只是"把地图显示出来"，地图会被遮罩压暗、玩家也点不到关闭它 → 所以走**隐藏暂停页**而非调层级（调层级会连 M 键的地图一起顶到暂停页之上，是更差的副作用）。
  - **世界保持暂停**（`get_tree().paused` 不动）→ 看地图时不会被打。
  - **Esc 的优先级分岔**：地图若从按钮进来 → Esc **回暂停页**（并刷新数值）；若从 M 键进来 → Esc 直接关地图。**否则玩家只想看一眼地图却把游戏给跑了**。
- **暂停时 M 键被守卫**（`_toggle_map` 开头 `if _paused: return`）—— 暂停页已有按钮入口，两条入口语义打架没好处。
- **布局修正**：`Center` VBox 从 84px 高（原 2 按钮）加到 **168px**（6→174）。加了 4 行状态 + 第 3 个按钮后内容总高约 164px，**原先的 140px 容器会溢出、把「退出游戏」挤出**。
- **不做**：暂停页里直接放背包 / 装备栏、暂停页改设置（音量 / 灵敏度）、暂停页显示任务或楼层信息。

### 2.16 宝箱：数量加大 + 必须靠墙（R-79 新增）

> **来源**：用户「加大宝箱的生成率。宝箱生成的位置要靠墙」。

- **数量口径**：`clampi(3 + floor/2, 3, 8)`（旧：第 1 层 3 个、封顶 8）→ **`clampi(5 + floor, 5, 20)`**（新：第 1 层 **6** 个、封顶 **20**），约 **2–2.5 倍**。取值集中在 `FloorGenerator` 的「宝箱（R-79）」常量段（`CRATE_MIN 5` / `CRATE_PER_FLOOR 1` / `CRATE_MAX 20`），脚本内不写魔法数。
- **只贴墙放**：候选池由「全部地面格」改为 **`_wall_adjacent_floor_cells()`** —— **4 邻域里至少有一个非地面格**的地面格（`BORDER=1` 保证所有地面格都在 `[1, cols-2]` 内，故不必额外判界）。设计理由有两条，**都是玩法而不只是几何**：
  1. 走廊中央不再摊箱子 → **不会顶死门、不会卡 bot**；
  2. 想拿 loot 必须先「走到墙角」→ **天然制造探索动线**，而不是箱子摊在路过的地方被白捡。
- **采样方式改为 swap-remove（用完即弃）**：不再"纯随机重试"，避免候选池靠前的格子被反复抽中而权重虚高。
- **可达性兜底口径升级**：原兜底只保证「出生 → 出口可达」；宝箱数量翻倍后会漏掉「**某个房间被堵住 → 玩家进不去、那间 loot 白生成**」。现改为保证「**所有房间 + 出口**都仍能从出生点走到」（逐个丢弃箱子直到全连通）。
- **其它约束不变**：不在「出生→出口」主路径的格子上、彼此间距 ≥ `CRATE_SPACING 60px`、离出生 ≥ 80px、离出口 ≥ 40px。
- **兜底**：若某层理论上没找到任何贴墙格，退回全部地面格，保证数量达标（当前 6 层实测从未触发）。
- **不做**：宝箱开口朝向贴墙侧（贴墙的箱子其实天然"背面朝墙"，未做朝向微调）、宝箱按 loot tier 分级摆放、多个箱子拼成"宝箱堆"。

### 2.17 备弹：携带上限 + 暂停页显示（R-80 新增）

> **来源**：用户「暂停画面显示备弹数量。各类备弹要有数量上限。」
> **用户拍板**：上限 **9×19 = 300 / 12×70 = 120**；暂停页**两个口径各占一行**（不只显示当前武器口径）。

- **每口径真实上限**（`GameConstants`）：`RESERVE_CAP_9X19 := 300`（≈6 盒）／`RESERVE_CAP_12X70 := 120`（≈2.4 盒），经 `RESERVE_CAP` 字典按口径查。
  - ⚠ **与旧的 `RESERVE_BAR_MAX := 200` 是两回事**，已在常量处钉死注释：后者只是 HUD 色条的画长参考，**不参与任何逻辑**。R-80 已让 HUD 改用真实上限。
- **`Player.add_reserve()` 改为返回「实际装入量」**：内部 `mini(rounds, cap - 当前)` 做 clamp，超出部分**直接丢弃**。返回值让调用方能判断"这一盒到底吃掉了多少"。
- **「偷玩家物资」的三条防线**（这是引入上限后最容易踩、也最难自己发现的坑，全部已固化成断言）：
  1. **背包里的弹药盒装不下 → 完全不消耗**（`Main._use_item`）：剩余空间 < 一盒（50 发）时 `return false`，盒子**留在背包里**、负重不变，并给瞬时 toast「备弹已满（290 / 300），装不下整盒」。不做"塞得下多少算多少"。
  2. **地上补给装不下 → 留在地上**（`WeaponPickup._try_take`）：同样先判**剩余空间够不够整盒**，不够就一颗不装。
  3. **整盒语义**：剩余 49 发、盒子 50 发 → 拒绝。**不能只塞 45 发然后把整盒消耗掉** —— 那和白白吃掉补给等价。
- **`WeaponPickup` 由「一次性」改为「范围内每帧重试」**：原实现只在 `body_entered`（首次进入）时尝试一次。加上限后，"站在补给上但装不下"成为常态 → 玩家原地把弹打空后再也捡不起，**补给等于永久消失**。现改为只要玩家还在范围内就重试，拿到即 `queue_free`（每帧成本 = 一次上限比较）。
- **顺带修掉的既有缺陷（R-80 期间发现）**：`WeaponPickup.tscn` 的 Area2D **没设 `collision_mask`**（缺省 1 = 只检测墙层）→ 它根本看不到 layer=2 的玩家，**地上的武器/补给在原实现里就永远捡不到**。已设为 `collision_layer = 0 / collision_mask = 2`。
- **HUD 备弹条满格参考**：改为**当前口径的真实上限**（`Main._sync_hud_reserve_cap()` 经 `weapon_changed` 转发给 `HUD.player_cap_hint`）。两个口径上限**不同**（300 / 120），所以规则是「已知真实上限 → 用它；未知 → 退回旧常量兜底」，**不能取两者较大值**（否则 12×70 灌满时条只到 60%，读起来像"还能再装"）。
- **暂停页**：在 R-78 的 `StatsBox` 追加**两行**（`Reserve9Label` / `Reserve12Label`），格式 `9×19  77 / 300`，斜杠右侧即**该口径携带上限**。⚠ 加行后实测内容总高 **194px > 视口 180px**（R-78 那个"加行挤爆视口"的坑复发）→ 一度靠压缩字号 9→8、separation 3→2、按钮高 20→18、容器改 0..178 满高，收敛到 **y=74..177**。**该压缩在 R-81 被两列布局取代（见 §2.18）**，字号已回到 9。
- **瞬时提示通道**：`hint` 节点是**每帧被 `_update_hint()` 覆写**的常驻提示，不能直接写 `hint.text` 承载一次性反馈。新增 `_toast(msg)` + `_toast_t` 倒计时（1.8s），倒计时期间压过常驻提示、到期自动交还。
- **不做**：按口径分别设置负重惩罚（备弹目前不占负重）、备弹上限随楼层/难度浮动、暂停页里直接点弹药盒做「丢弃以腾空间」、备弹上限的 UI 自定义设置。

### 2.18 暂停页状态区：两列布局（R-81 新增）

> **来源**：用户「暂停窗口的状态信息改为两列，左侧为HP等状态，右侧是弹药，并且右侧上方显示"备弹"两字」

- **动机（不是为了"好看"，是为了修R-80 的挤压）**：R-80 把状态区做成**单列 6 行**（生命/体力/饥饿/口渴 + 两条备弹），实测内容总高 **194px > 视口 180px**，底部「退出游戏」被挤出屏幕。R-80 当时的解法是**压缩字号**（9→8）硬塞——那是妥协，不是解决。**两列把行数 6→4，纵向压力直接消失**，于是可以把横向还回去。
- **实现**：`StatsBox` 从 `VBoxContainer` 改为 **`GridContainer`（`columns = 2`）**，`h_separation = 8 / v_separation = 1`。子节点**按声明顺序先填满一行再换行**，所以排列是：
  | 行 | 左列 | 右列 |
  |----|------|------|
  | 1 | 生命 | **备弹**（表头 `ReserveTitleLabel`） |
  | 2 | 体力 | 9×19 |
  | 3 | 饥饿 | 12×70 |
  | 4 | 口渴 | （空） |
- **容器加宽**：128px（96..224）→ **208px（56..264）**，每列 ~104px，`h_separation 8px` 让两列一眼分得开。**状态行字号 8 → 9 恢复可读**（R-80 压到 8 是被迫的）。
- **表头为什么必须有**：`9×19` / `12×70` 这两行**不写"备弹"读者不知道是什么**（状态区其余四行都是人物属性）。`ReserveTitleLabel` 只占右列第一格，**与「生命」同行**，下方紧跟两条口径行。
- **实测（R-81 后）**：左列 y = 22/36/50/64（间距 14px）、右列 y = 22/36/50，**列间左列右边缘 118 / 右列左边缘 126 = 8px 留白**；内容整体 **y=36..155**，比 R-80 的 194px **少占 75px**，R-78/R-80 那个"加行挤爆视口"的坑**从结构上消除了**（不是靠压缩躲开的）。
- **不做**：暂停页做更宽的三列 / 折叠分组（把备弹折进二级菜单）、暂停页显示武器名与弹药盒存量、暂停页里做可点击的数值调节（回血/丢弃备弹）。

### 2.19 箱子战利品池：+7 件搜刮材料（R-82 新增）

> **来源**：用户「箱子中生成的物品添加：火药、废金属、塑料、电子元件、蔬菜、肉类、燃料。箱子每次生成的物品总数不变。」
> **用户拍板**：① 7 件与旧物品**全部等概率**抽取（不加权表）；② 7 件**全部纯战利品**（`kind:"misc"`、**无 `use` 字段**）。

- **新增 7 件**（全部进 `GameConstants.ITEM_TYPES`，`w:1 h:1`）：

  | id | 名称 | 重量 | 显示色 | kind |
  |----|------|------|--------|------|
  | `powder` | 火药 | 1.5 | 深炭灰 | misc |
  | `scrap` | 废金属 | 2.5 | 灰褐 | misc |
  | `plastic` | 塑料 | 0.8 | 浅青白 | misc |
  | `circuit` | 电子元件 | 0.6 | 墨绿 | misc |
  | `vegetable` | 蔬菜 | 1.2 | 草绿 | misc |
  | `meat` | 肉类 | 1.5 | 砖红 | misc |
  | `fuel` | 燃料 | 2.8 | 暗黄 | misc |

- **「总数不变」的实现依据**：`Main._roll_container_items()` 的件数是 `randi_range(CRATE_ITEMS_MIN, CRATE_ITEMS_MAX)` = **randi_range(4, 10)**，**与池子大小无关**。所以池子 8→15 **不影响每箱件数** —— 这是结构性保证，不是巧合。已固化成断言（跑 2000 箱样本，平均 **6.94**、理论 7.0、全部落 4~10）。
- **⚠ 明确的取舍（用户已知情拍板，不是疏漏）**：等概率意味着池子 8→15 后，**每件旧物品出现率从 1/8（12.5%）降到 1/15（6.7%）**，实测 6.3%~6.9% 均匀分布。副作用是**纯材料占池子 7/15 ≈ 47%** —— 开箱「近半数是当前用不上的东西」是**已知且接受**的体感。
  - 将来若加制作 / 交易 / 兑换系统，**正确做法是在这里加 `use` 或另开权重表**，而**不是回改本批的等概率口径**（回改会让"当初为什么这么定"丢失）。
- **纯战利品语义**（用户拍板②）：7 件一律 `kind:"misc"`、**没有 `use` 字段**。cp2 无制作 / 兑换系统，材料只表达"搜刮到了什么"。
  - ⚠ **不做的后果要钉死**：若误给材料加 `use`，`_menu_entries_for()` 会冒出「使用 / 食用」菜单项，玩家点了**什么也不会发生**（纯 frustrating）。已加断言走**真实菜单路径**确认 7 件都不产生 `use` 项。
- **验证**：`--verify-loot`（R-82 新增）→ **PASSED**。五条断言：① 池子 15 件 + **id 唯一**（重复 id 会让 `_proto_by_id` 永远命中第一个，是静默 bug）；② 7 件 `kind==misc` / **无 `use`** / 中文标签与用户指定逐字一致；③ **总数守恒**（2000 箱：平均 6.94、全部落 4~10、分布 4~10 七个值全覆盖）；④ **覆盖率 15/15**（"每类都抽得到"不能只靠查表断言——要防"某类永远抽不到"）；⑤ **走真实 `_menu_entries_for()` 确认无「使用」项**。
  - 之所以**不用"期望出现率"做断言**：等概率 15 类抽 k 件是多项分布，精确概率断言难写且易flaky。改用**样本计数 + 覆盖率 + 总量守恒**。
- **不做**：战利品分级（`LootTier` / `MinTier`）、按楼层调整权重、材料制作配方、材料兑换货币、材料在箱子里的堆叠数量（当前与旧物品一致，每格 1 件）、箱子物品的重量档位设计。

## 4. 难度裁定（下行张力 = 刻意设计意图）

> **裁定来源**：用户 2026-09-30 拍板「**维持现状**」——保留「越深越险」的下行张力，**不加下楼回血、不降僵尸曲线**。本节把该决定固化为**刻意的设计意图**，避免后续被当成 bug 或平衡疏漏而「顺手修掉」。

### 4.1 三条刻意规则（cp2 现状）
| # | 规则 | 现状值 | 设计意图 |
|---|------|--------|----------|
| D1 | **跨层不回血** | `_descend()` 走 `_build_floor(reset_hp = false)`，仅复位位置/速度/状态，HP **原样带入下一层** | 让「再往下走一层」始终是一次**有代价的押注**——下行不是免费的，深度本身就是风险累积 |
| D2 | **僵尸逐层 +1，封顶 12** | `enemy_count = clamp(3 + floor, 3, 12)` | 每深一层，清算压力单调上升 → 形成「越深越险」的可感曲线；封顶 12 防同屏过载 |
| D3 | **受伤跨层累计** | HP 无层内回补 → 累计伤害只增不减，直到死亡 | 「搜-打-撤」的「撤」有存在意义：**撤不出去 = 代价滚雪球**；呼应 `procedural-gen §3.1` 探索级/存档级世界状态的「惩罚不止是消耗」立意 |

### 4.2 有意不做（原型阶段的明确取舍）
- **有意不加「下楼回血」**：回血会抹平 D3 的累计压力、把下行从「押注」降级为「续命」，直接消解 cp2 要验证的**下行张力**。
- **有意不加「缓僵尸曲线」**：D2 的单调上升正是「越深越险」的量化载体；缓曲线会让深度失去意义。
- **有意不加「深度补偿」（越深越强 / 越深越快回血）**：cp2 不引入任何针对深度的「反向补偿」，避免与 D1–D3 对冲而产生**支柱漂移**。

> ⚠ **红线标注（供后续评审）**：后续若有人提议「下楼回血」，**须先推翻本节裁定**（属设计意图变更，不是 bugfix）。若实测证明 D1–D3 让「正常玩家在个位数层必死、无法体验下降循环」，处理顺序应为：**① 先调 D2 的封顶/起始值微调**，② 再评估是否引入**受限**的深度补偿（如「每 N 层回一次上限的一部分」），**而非直接加裸回血**。

### 4.3 与 `procedural-gen.md §4` 完整版难度递进的关系（简化子集）
cp2 的 D1–D3 是**完整版难度递进的一个极简切片**，只保留了「**惩罚随深度累积**」这一条**主线立意**，**剥离了全部配套系统**：

| 维度 | cp2 原型（本文件） | 完整版（`procedural-gen.md §4`） | 关系 |
|---|---|---|---|
| 敌人数量 | `clamp(3 + floor, 3, 12)` 线性 +1 | `EnemyBudget = clamp(round(8 + depth×0.55), 8, 40)` + **类型 cost 分配**（僵尸1/怪物2/雇佣兵3） | cp2 = 只取「数量随深度上升」的**骨架**，去掉类型池与预算模型 |
| 敌人种类 | **仅僵尸** | 僵尸/怪物/雇佣兵/机械四类 + **区段权重翻转**（§4.3 玩法翻转核心） | cp2 **不做**权重表，P3「前慢后快」不验 |
| 战利品 | 1 个固定霰弹拾取点；**箱子战利品池R-82 扩到 15 件**（8 旧 +火药/废金属/塑料/电子元件/蔬菜/肉类/燃料，**等概率**、7 件纯战利品无使用效果、**每箱件数仍 4~10 不变**） | `LootTier` 5 档 + `MinTier` 硬门槛 + 容器/掉落表 | cp2 **不做**战利品等级 |
| 空间风格 | **无**（单一矩形房间 + 随机掩体） | S1–S5 五风格 × 4 主题 = 20 种观感，房间数叠加 `StyleRoomCountK` | cp2 **不做**风格系统（§4.8 全略） |
| 垂直维度 | 无（单层平铺） | 垂直骨架 + 井道 + 绳索（§3.1.2 / §4.7） | cp2 **不做**垂直 |
| 持久化 | 零存档（`static _floor`，死亡归 1） | 三层世界状态（①布局/②持久/③探索级，§3.1） | cp2 **不做**存档 |
| 精英/Boss | 无 | 每层必出 1 精英 + 十进制 Boss（§4.6） | cp2 **不做** |

- **保留的内核**：`descentDepth` 的单调性 = 「越深 → 压力越大 → 玩家越要想清楚「还要不要往下」」——这是 cp2 唯一要守住的设计轴。
- **刻意省略的原因**：cp2 是**闭环原型**（验证「能不能一路往下走」），不是**内容原型**（验证「每一层好不好玩」）。把所有配套系统都搬进来会**摊薄验证焦点**、放大工程量，违背「最小可玩闭环」的范围纪律（与 cp1 的精神一致）。
- **不被省略的部分**：`FloorGenerator` 的**确定性契约**（同 seed+floor 逐要素一致）是完整版 `AC1`（同 seed 字节级一致）的前置形态——cp2 先把「确定性可复现」跑通，完整版再叠加风格/骨架/持久化。

## 5. 与 `procedural-gen.md §4` 的呼应说明

> 本节是 §4.3 的**上位视角**：说明「cp2 为什么是完整版的简化子集」，并给出**升级路径**，使 cp2 的取舍在阶段 1 可平滑接续，而非推翻重做。

1. **定位关系**：`procedural-gen.md` 定义**完整游戏（99–1 层）**的生成与难度系统；本文件定义**cp2 原型**的生成与难度切片。二者是**目标态 vs 中间态**的关系，**并非两套并行规则**。
2. **同构处（cp2 已落地的骨架）**：
   - `FloorSeed = Hash(GlobalSeed, floor)` 的**确定性思想** → cp2 用 `_mix(seed, floor)` 实现同构雏形（cp2 的 `_GLOBAL_SEED = 1337` 为固定主种子，完整版为每存档 1 个 `GlobalSeed`）。
   - **「惩罚随深度累积」** → cp2 的 D1–D3 是 §4「难度与内容随 descentDepth 平滑递进」（`G3`）的极简投影。
   - **单层生成 → 换图 → 下一层** → cp2 的 `_descend()` 是 §5 生成流水线 `[PlaceExit] → [Ready]` 与 §4.5「单层常驻 + 按需生成」的**一次性最小实现**（cp2 即用即弃，不做缓存/持久化）。
3. **差异处（cp2 有意低于完整版）**：见 §4.3 对照表。核心差异 = cp2 **没有**：风格系统（§4.8–4.10）、主题区段（§3.2 / §4.3）、垂直骨架（§3.1.2 / §4.7）、精英/Boss（§4.6）、三层存档（§3.1）、容器/掉落表（§4.4）。
4. **升级路径（阶段 1 接续时的落点）**：
   - `FloorGenerator.gd` 的 `generate()` 是**可扩展接口**——完整版在其内部依次插入 `StyleSelect → CarveOpenness → Layout → CorridorConnect → TagRooms → BuildShafts → PlaceAnchorTiles → PlaceExit → Populate → Validate`（§5 流水线）；cp2 现有实现相当于「固定单风格 + 无骨架 + 无标签」的**特例**。
   - cp2 的 D2（僵尸线性 +1）→ 升级为 §4.2 的 `EnemyBudget` + §4.3 类型权重（僵尸 cost 1 → **R-23 后上调为 2 ⚠待调**，`procedural-gen §4.3` 补注）。
   - cp2 的「不回血 + 累计伤害」→ 在完整版中由**探索级/存档级世界状态**（§3.1）承接：死亡 = 一次探索结束，而非本层重置。
5. **可追溯性**：本文件全部数值与术语**带文档锚点**；与 `cp1_scope.md` 沿用同一套玩家/武器/僵尸常量（`GameConstants.gd` 为工程单一权威常量源）。

## 6. 验证 DoD（重定义 · 零崩溃即通过）

> **重定义来源**：用户 2026-09-30 拍板——**把 cp2 验证 DoD 从「跑满 10 层」改为「零崩溃即通过」**。原判据要求无头 bot 走满 10 层，但在 §4 刻意保留的下行张力（D1–D3）下，**bot 必然在某个深度阵亡**（现状：**第 6 层阵亡**）——该阵亡是**设计意图的正确表现**，**不构成失败**。

### 6.1 cp2 通过判据（可执行）
cp2 判定为**通过**，当且仅当**同时满足**：

1. **harness 跑完**：`--verify` / `--verify-gen` / `--verify-wep` 三个无头入口**均执行到自身结束**（打印各自的收尾行，如 `=== FloorGenerator test PASSED ===`）。
2. **零引擎崩溃**：进程**干净退出**（`exit code == 0`），无 segfault / 无未捕获异常终止。
3. **零解析错误**：日志中**不含 `SCRIPT ERROR` / `Parse Error`**（证明全部 `.gd` 可加载）。
4. **零运行时错误**：运行期日志中**不含脚本产生的 `ERROR:` 行**（见 6.3 白名单口径）。

> ⚠ **原「跑满 10 层」判据作废**：`_verify_step` 中「阵亡 → 打印 `FAILED (died)`」的**措辞**与「满 10 层 → `ALL 10 FLOORS DONE`」的**成功措辞**，需由工程侧改造为**中性收敛语义**（见 `CP2-ENG-01`）；本文档只裁定**判据本身**，不改代码。

### 6.2 无头 bot 阵亡 = 预期信号（不判失败）
- 无头 bot 在任意深度阵亡时，**记录「到达深度 N」**（`FLOOR N DIED` / 等价的中性日志），**不判失败**。
- 「到达深度 N」是**可观测的验证产出**（衡量下行张力的强度），而非错误。
- 只有在 **6.1 的 2/3/4 任一被违反**时，才判 cp2 **失败**。
- **推论**：bot 跑得越深，只说明张力越缓；bot 早早阵亡，只说明张力越陡——**两者都是有效信号**，都不改变「通过 / 不通过」。

### 6.3 判据口径的白名单（防止误判 · 需工程侧确认）
Godot 在**退出期**会输出一批**引擎级清理噪声**，**不属于本作运行期错误**，**不计入 6.1 判据 4**：
- `ERROR: BUG: Unreferenced static string to 0: ...`（`core/string/string_name.cpp`）
- `ERROR: N RID allocations of type '...' were leaked at exit.`（资源泄漏清理提示）
- `ERROR: Pages in use exist at exit in PagedAllocator: ...`（分配器退出提示）
- `WARNING: A Thread object is being destroyed without its completion ...`

> **建议实现**：工程侧在 `CP2-ENG-01` 中把判定逻辑写成「**只扫描运行期日志区段**（以首个 `SCRIPT ERROR` / `ERROR:` 为准，退出期噪声之前）+ **显式白名单正则**（上面四类）」，避免把引擎退出噪声误判为失败。**⚠ 该白名单口径以 `engineering-lead` 最终实现为准**；本文档给出建议口径，二者如有出入以工程实现为工程判定，设计侧同步。

### 6.4 DoD 清单（cp2 完成条件）
- [ ] `--verify-gen N` 逐层断言通过（每层有敌人 + 出口/拾取在界内），**零崩溃**
- [ ] `--verify` 下降循环 bot **收敛**（阵亡或跑完均可），**进程 exit=0 且满足 §6.1 判据 2/3/4**
- [ ] `--verify-wep` 断言 `pistol_pellets == 1` 且 `shotgun_pellets >= 6`，**零崩溃**
- [ ] `--verify-enemy` 断言雇佣兵生成曲线 + 敌我子弹分层 + 伤害路径，**零崩溃**
- [ ] 三个入口的日志中**无 `SCRIPT ERROR` / 无脚本 `ERROR:`**
- [ ] 手测：走到出口 → 下降一层 → HP 与武器保留、HUD 层数 +1（G2）
- [ ] 手测：`1/2/Q` 切换武器，HUD 武器名 + 弹量随之更新（G3）
- [ ] 设计文档依据可追溯（每个数值带文档锚点）

### 6.5 分支覆盖矩阵（R-50 参数化后 · 已闭合）
参数化前，三条终止横幅仅「阵亡」一条可动态触发（固定 `seed=1337` 必死第 6 层）；R-50 引入 `--verify-floors` / `--verify-timeout` / `--verify-seed` 后，三条**全部可动态覆盖**：

| 终止分支 | 触发方式 | 实测证据（log 横幅） |
|---|---|---|
| 阵亡 → PASSED | `--verify`（默认 seed 1337） | `bot reached depth 6` |
| 阵亡 → PASSED（异种子） | `--verify --verify-seed 2026` | `bot reached depth 9` |
| 跑满目标层 → PASSED | `--verify --verify-floors 1` | `survived all 1 floors` |
| TIMEOUT → PASSED | `--verify --verify-timeout 0`（或自然超时 `--verify --verify-seed 424242`） | `reached depth 1 (timeout)` ／ `reached depth 6 (timeout)` |

- 上述运行均 `exit=0`，stdout 无 `SCRIPT ERROR` / `Parse Error` / 运行期 `ERROR:`。
- **残余说明**：三条分支在**默认参数**（`seed=1337`、目标 10 层、超时 13s）下仍只命中「阵亡」——因无头 bot 的朴素走位在「不回血 + 僵尸递增」（§4 刻意张力）下定在第 6 层阵亡。**分支可达性**由参数化保证；**默认参数下的自然收敛**仍以「阵亡」为主。

## 7. 技术约束（cp2 硬门槛）

- Godot 4.7.2 stable · GDScript · 内部分辨率 320×180（窗口可放大，禁用 smoothing 验证像素硬度）

### P2-04 裁定：屏外威胁预警 —— **不做**（2026-10-05，用户实机验证后拍板）

**原风险登记**：玩家视野（`FOG_VISION_RADIUS_TILES 10` ≈ **160px**）小于佣兵**视觉**（`MERC_VISUAL_RANGE` **260px**）⇒ 曾登记为「佣兵能在玩家视野外先发现并开火」的公平性风险（`docs/review/cp2-perception-eng-v1.md:140`）。

**用户裁定**：「P2-04 屏外威胁预警，『他看得见你、你看不见他』目前看没什么问题，先这样。」

**复核结论：原风险陈述不准确，当前实现下该风险实际上不成立。** 依据（`Mercenary._combat_step()` + `GameConstants`）：

| 项 | 数值 | 含义 |
|---|---|---|
| 玩家视野 | 160px | `FOG_VISION_RADIUS_TILES 10 × 16` |
| 佣兵**发现**距离 | 260px | `MERC_VISUAL_RANGE` —— 只决定「**从哪里开始警觉**」 |
| 佣兵**开火**距离 | **78 ± 14px**（即 64–92px） | `MERC_PREFERRED_DIST` / `MERC_RANGE_TOLERANCE` |
| 开火前摇 | 0.35s | `MERC_WINDUP` |

**关键**：视觉 260px 只控制「**何时进入战斗**」，而开火被 `_combat_step()` 的死区逻辑锁在 **64–92px** —— 这个距离**远小于**玩家 160px 视野。代码路径（`Mercenary.gd:143-164`）是 `dist > 92` → **只推进、不开火**；`dist > 160` 的远距离段必然先被推进进 92px 内。**所以佣兵永远不可能在玩家视野外开火**；玩家被击中时，佣兵必然已在 92px 内 = **在玩家视野内**。260 vs 160 的差值只意味着「它比你早 100px 开始警觉」，不构成"看不见的致命打击"。

**因此**：GDD `enemies-ai §3.4` / `fog-of-war §3.2` 要求的「**首次开火前必须先发出可听/可见的 tell**」在 cp2 阶段**由距离约束天然满足**（推进过程本身可见 + `windup 0.35s` 反应窗口 + `MERC_BURST_PAUSE 1.1s` 组间停火换位），**无需额外做 HUD 边缘预警指示器或音效 tell**。原「必须做屏外预警」的推导前提有误（把「发现距离」当成了「开火距离」）。

**若将来改动上表任一数值，需重新评估** —— 尤其若把 `MERC_PREFERRED_DIST` 提到 160px 以上、或给精英/Boss 加「超视距点射」，届时屏外预警就变成真需求。

- **§0 同步（评审后）**：把 §0 定性 L15「零迷雾」改为「迷雾已提前进入（R-70）」、L18「不做什么」首项「迷雾」从"一律推迟"中摘出并标「已提前进入 cp2（R-70）」，**其余项全部保留**。

### v0.20（R-68 批次 2026-10-01 · 实机 bug 修复：点击到不了 Main + 暂停其实没停住）
用户实机反馈：「1.箱子内的物品可以通过拖拽放入背包…背包中的物品也可以移入箱子。3.操作箱子和背包时游戏暂停。」**这两条在实机上没生效**（`--verify-inv` 却是 PASSED —— 因为它直接调函数，绕过了输入分发与进程模式）。
- **Bug 1：鼠标点击被 GUI 吃掉 → 拖拽 / Ctrl 快速移动全部无效**
  - 根因：`HUD` 的 Control 默认 `mouse_filter = STOP`，且 `Margin/VBox`（x4–316 / y4–86）**正好压住背包网格上半与箱子面板上半**；点击在 GUI 命中阶段被消费，`Main._unhandled_input` 根本收不到。
  - 修：① 鼠标交互从 `_unhandled_input` 移到 **`_input`**（`_input` 早于 GUI 命中，谁也吃不到），并用**事件自带 `event.position`**（经 `_ui_to_local()` 转 Backpack 局部坐标）而不是轮询鼠标位置；② `HUD._ready()` 递归把全部 Control 设为 `MOUSE_FILTER_IGNORE`（HUD 是纯显示层）。
- **Bug 2：`get_tree().paused = true` 并没有让世界停下**
  - 根因：**`process_mode` 会被子节点继承**。`Main = PROCESS_MODE_ALWAYS(3)` → 子节点 `TestRoom`（玩家 / 敌人 / 子弹）也成了 ALWAYS → 暂停只停了 `Main._process`，**世界照样跑**（准星还在每帧 `CONFINED_HIDDEN` 隐藏光标，等于操作界面时光标都看不见）。
  - 修：在 `Main.tscn` / `HUD.tscn` 里**显式指定每个子节点的 process_mode**：`TestRoom / Camera / HUD / DeathScreen / MapLayer / HintLayer / CrosshairLayer = 1(PAUSABLE)`；`BackpackLayer / PauseScreen = 2(WHEN_PAUSED)`。撤下暂停页 → 用 `Esc` 即可（`Esc` 优先级：背包 → 地图 → 暂停页）。
- **新增 `--verify-ui`（真实输入链路 E2E）**：用 `Viewport.push_input(ev, true)` 送**真事件**（F 开箱 / Tab 开背包 / 鼠标按下松开 / Esc），并断言：
  - `open(real F): visible=true container=true paused=true world_stopped=true`
  - `ctrl+click real at (120,31): inv 0→1 cont 6→5`（该点在 HUD 重叠区内，过去必被吞）
  - `drag real cont->inv: dragging=true`、`drag real inv->cont: dragging=true`
  - `close(real Esc): paused=false … player_can_process=true`、`open(real Tab): paused=true player_can_process=false`
- **`--verify-pause` 补真断言**：`get_tree().paused` 只是标志位，改用 **`can_process()`** 验「玩家 / 敌人真的停」→ `pause-real: player_stopped=true enemy_stopped=true resumed_runs=true`。
- **回归**：13 个入口（新增 `-ui`）全 EXIT=0、零错误、全 PASSED；`--verify` 下降 depth 6。
