## 0. 口径与边界

> **⚠ 两级口径（R-18 · 用户决策 2026-09-22）** —— 本节是全文的**总纲**：
> | 阶段 | ZS 的角色 | 做法 |
> |---|---|---|
> | **阶段 0–1（原型 / 垂直切片）** | ✅ **参考基准，可直接照用** | 数值、属性轴、射程曲线、掉落权重、敌人参数**可直接采用 ZS 真值**，快速验证手感与节奏 |
> | **阶段 2+（正式内容）** | ⚠ **仅作对照，必须原创** | 数值按本作「100 层垂直大厦」难度曲线**重标定**；**命名 / 资产 / UI / 文案全部原创**；**不得出现 ZS 的化名、资产、原文案** |
>
> **理由**：① **法律**——ZS 的数值表与化名体系是 IP，照抄有风险（尤其上架 Steam）；② **设计**——ZS 是"多地图 + 撤离点"，本作是"100 层垂直大厦、按存档固化"，节奏与难度曲线不同；③ **产品**——终版必须有自己的辨识度。
> **一句话**：**ZS 是加速器，不是终稿。** 详细纪律见 `reference-zero-sievert-data-index.md` §0–§1。

- **参考范围 ＝「远程枪械的手感模型与数值轴」**，不含：Zs 的 Bunker 藏身处经济、任务系统、地图/关卡内容、NPC 阵营声望、辐射/异象等环境系统。
- **不照搬的部分**（本作独有、刻意保留）：按存档永久固化的程序化楼层、垂直骨架/逃生绳索、**D2 式战争迷雾三态模型**（⚠ **R-44 已改**：原写"**D2 式 automap 战争迷雾**"——**本作已移除 HUD 小地图（automap）**，迷雾三态**在主视角世界呈现**；**本条仅指探索三态模型，不得读作本作有 HUD 常驻小地图**，见裁决 ㉑。**⚠ R-45 补**：**HUD 仍无常驻小地图**，但**新增 `M` 键独立全屏「地图界面」承载全局信息与持久标记**（只列**已探索楼层**，数据源 `ExploredFloors`；**≠** HUD 小地图、**≠** R-43 的"小地图放大态"））、D2 式捡尸惩罚、生存（食水）、基地建造、NPC 好感/关键物品。
- **❌ 明确不采纳：玩家技能 / 熟练度的数值成长（R-30 用户拍板）**——**武器熟练度不做成游戏内数值**，改为**「武器手感差异化 + 玩家本人熟练」**（用户原话：「不同的武器要做出不同的手感，让玩家本人去熟练各个武器，否则所有武器熟练度都到顶以后会产生同质化的手感」）。**本作不设任何玩家级 / 武器级熟练度字段**（含改名重生），**无"越用越准"的隐性成长**；差异一律落在**手感参数层**（`combat §4.2`）。**注**：本决策**不以"ZS 侧有无同类系统"为条件**——无论参考对象怎么做，**本作不采纳任何玩家技能数值成长**；本文件其余条目（武器数值轴 / 射程曲线 / 后坐与工效 / 卡壳）**不受影响，继续对齐**。
- **❌ 明确不采纳：局外货币（meta 货币）与 meta 解锁树（R-32 用户拍板）**——**本作删除 `Credits`（信用点 / 局外货币）与整个 meta 解锁树**（用户原话：「Credits 被现金取代，仅在交易时使用」；追问后拍板「**物资 / 武器 / 武器附件 全靠搜刮获得，meta 解锁树玩法删除**」）。**本作唯一货币 = 现金 Cash**（普通可搜刮物品，**仅在三处交易时使用** = R6 通讯室〔空投站功能〕买入 / 卖出）；**不存在任何 meta 解锁**（无起始物资 / 无武器蓝图 / 无起始附件 / 无改造折扣解锁），**也不设任何"局外结算产出货币"机制**。**注**：ZS 侧**本就无 meta 解锁树**——故本条的"不采纳对象"是**本作自己在 R-21～R-31 期间曾自建的双货币 / 解锁树设计**（该设计**已整体作废**），**并非**对 ZS 某机制的否决；ZS 的 `money`（可搜刮物品）与本作现金**继续对齐**。
- **❌ 明确不采纳：专属赠礼"全世界唯一"设定（R-32 用户拍板）**——**赠礼不再是唯一一件，仅"稀少"（可重复获得）**；**游戏内不提示该送给谁**；**送错人不加好感且物品消耗**（用户原话：「提升好感度的物品不是游戏中唯一一件的，仅仅是稀少，而且游戏内并不提示应该送给谁，且送错人了不会增加好感」）。
- **✅ R-42 新增参考范围：时间系统 + 双人床（用户拍板）** —— **参考范围扩至"游戏时间系统与双人床功能"**（原 §0 的"参考范围 = 远程枪械的手感模型与数值轴"扩项）。用户原话：「将"一局=一天"这个逻辑取消，变更为游戏内时间和现实时间成比例，具体比例先参考 ZS。双人床的功能也和 ZS 统一」「Fatigue 暂时不实装」。**采用 = 对齐 ZS 的"1 游戏日 = 6 现实分钟 / 6 时段"**（见裁决 ⑲）**+ 双人床与 ZS 统一但含 4 项必要偏离**（见裁决 ⑳）；**⚠ 明确不采纳 = ZS 的"昼夜光照 / 夜间行动受限"**（本作是室内垂直空间）。
- **⚠ 明确不采纳：昼夜光照 / 夜间行动受限（R-42 用户拍板口径）**——**本作不引入昼夜光照玩法**：6 时段**仅作时间刻度 / UI 显示、不影响能见度**。理由：本作是**室内垂直空间**（100 层高楼），硬套昼夜会产生"地下 100 层哪来的白天"的自相矛盾。**注**：本条"不采纳"针对的是 **ZS 的"夜间行动受限"**（不是时间系统本身——时间系统本身**已采纳**，见上条）。
- **⚠ 明确不采纳：疲劳（Fatigue）系统（R-42 用户拍板"暂时不实装"）**——**本作暂不实装 Fatigue**；双人床**留"恢复疲劳"的预留位**，但 UI / 数值 / 美术**本批次零命中**。故 **ZS 床的核心功能（恢复疲劳）在本作缺席**，床的定位转为"推进时间 + 兜底回血"（见裁决 ⑳ 偏离 1）。

## 2. 与既有设计的差异裁决（**21 条** · 必须改口径）

### ① 玩家近战 → 移出 T 档（降为 B 档「不实现」）
- **理由**：用户明确（手感/武器/动作工作量过大）；且 ZS 玩家侧本就无近战系统，与"照搬 ZS"同向。
- **范围**：
  - **装备槽「近战 ×1」删除**；`CorpseCarrySnapshot`、储藏室保底、HUD、输入映射同步（保底套装由「近战 + 最低弹药」改为「**起始手枪 + 最低弹药**」）。
  - **序章教学**由「近战击退」改为「**用手边武器射击**」（序章初始武器＝老旧手枪，教学过程不变：移动→交互→首次战斗→救援）。
  - **敌人近战不受影响**：僵尸扑咬、怪物爪击/突进仍为敌人主要攻击方式（enemies-ai 不变）。
  - **替代职能**：近战原本承担的「省弹 / 破硬直 / 贴身应急」由 **投掷物 + 霰弹 + 翻滚** 接手（见 §4 风险）。
- **Tier**：玩家近战 = **B 档（不在阶段 0–3 排期）**，仅在 concept §3.2 保留一行"待定"。

### ② hitscan → 投射物（⚠ 原型验证项）
- **ZS 侧**：子弹为**实体投射物**（可见曳光，存在飞行时间）。
- **本作改动**：`combat §3.1` 由「默认 hitscan」改为「**默认投射物（`ProjectileSpeed` ⚠待调，可见曳光）**」，L2 层 `fx_bullet_tracer` 继续承担视觉。
- **风险与护栏**：俯视角 16 px 尺度下，投射物飞行时间若过长会让"打不中"变得不可读。**阶段 0 必须实测**：若投射物导致手感钝、命中反馈模糊，**允许回退为 hitscan**（`ProjectileSpeed = ∞` 即退化为 hitscan，架构上同一套代码）。→ 见 §6 原型清单 #1。

### ③ 暴击（CritMult）→ 移除
- **ZS 侧**：无暴击系统（无爆头伤害轴）。
- **本作改动**：`combat §4.1` 删除 `CritMult / CritChance`。**伤害差异改由「口径 + 弹药类型 + 穿透 + 配件 + 距离」制造**。
- **理由**：保留暴击会与新的穿透轴叠加出双重随机，破坏 ZS 式"可预测、可按套路优化"的手感。

### ④ 固定护甲吸收 `ArmorAbsorb = 0.50` → 穿透/Class 判定
- **ZS 侧**：护甲分 **Class 1–6**，决定能挡下的口径阈值；有**吸收（Absorption，判定成功则完全抵消）**，被 **Penetration 克制**；护甲**耐久**随吸收下降，Class 效果随耐久衰减。
- **本作改动**：`Armor(0–100)` 保留为 **`ArmorDurability`（0–100）**，**新增 `ArmorClass(1–6)`**，以穿透判定取代固定百分比吸收。公式见 §3。
- **兼容性**：R-11 刚建立的「护甲 ×1 装备槽 + 尸体快照含护甲 + HUD 护甲条」**全部保留**，只是把"吸收规则"换轴——返工最小。

### ⑤ 稀有度 C/U/R/E/L → **重定义为「型号阶梯」**（R-12 立轴 · R-15 重新定案）
- **ZS 侧**：无稀有度系统；**但武器确实按具体型号分档**——AK 系 / M4 系 / SCAR 系在威力、后坐、精度、可用配件上各不相同，"型号本身就是分档"。
- **本作改动（R-15，用户决策）**：**保留稀有度**，但**含义改为「这是哪一把枪」**：
  - ~~旧①：`最终伤害 = BaseDamage × 稀有度倍率`（1.0/1.10/1.22/1.38/1.60）~~ **R-12 已废弃**；
  - ~~旧②：稀有度 = ①附件槽位数（0/1/2/3/4）②品质档~~ **R-15 已废弃**；
  - **新（R-15）：`稀有度 = 型号的价值/威力层级`**——范例（自动步枪族，定案）：`AK-47(C) → AK-74U(U) → AK-102(R) → M4A1(E) → SCAR-H(L)`。**附件槽位数改为型号固有属性**；**掉落加 `MinTier` 硬门槛：越深的层越只出高级型号**。详见 weapons-loot §3.1.1/§4.1/§4.3。
- **为什么"不冲突"（关键）**：R-12 的结论是"**不要稀有度乘区**"（避免与口径/弹种/穿透双重缩放）；R-15 要求的是"**高稀有度枪更强**"。两者**同时满足**的办法是：**强度差异写进"不同型号各自的 `WeaponDamage`"**，而不是写成一个乘区。
  - 断言：`WeaponDamage(SCAR-H) = 32 > WeaponDamage(AK-47) = 26`，但**伤害链中不存在 `RarityMult`**（combat §4.1）。
- **收益**：
  - **保留 ZS 的"选对口径比选贵枪重要"**——AK-47 的 7.62×39 在特定场合仍优于 M4A1 的 5.56×45；
  - **丢掉"数值堆叠"感**——从 AK-47 换到 M4A1 是**换平台**（换口径、换后坐、换槽位），不是喂数值；
  - **loot 兴奋度回来了**——"掉了把 SCAR-H"比"掉了把 4 槽的普通步枪"更让人兴奋（R-12 当时的代价，R-15 解决）。
- **代价与护栏**：
  - 代价：需要**逐型号维护数值表**（型号越多，平衡面越大）→ 护栏：**每族先只做 5 档**（T 档仅自动步枪族完整五档，其余族 3 档起步）；
  - 风险：高稀有度型号若**综合无短板**会杀死 build 多样性 → 护栏：**每把枪必须留一个明确短板**（§3.1.1 的"取舍"列是硬要求，不是备注）。

### ⑥ 改造地点 → 仅基地工作台
- **ZS 侧**：只能在 Bunker 工作台改装，探险中不可改。
- **本作改动**：`weapons-loot §5` 的「改造台/即时」改为「**仅基地工作台（R2）**」；野外仅允许**换弹 / 切枪 / 用消耗品**。
- **副作用**：提升了工作台（NPC#2 蕾娜）与"撤回基地"的价值 —— **与 P6「撤即经营」同向，属正向副作用**。

### ⑦ 回血 → 只用药品 + 双人床；基地医疗室改制药工坊（R-14 立 · **R-16 事实修正** · **R-42 更新 ZS 床口径**）
- **ZS 侧（R-16 更正 · 此前写反了）**：ZS **并非"没有回血途径"**，准确口径是**三条**：
  1. **药品道具**（绷带 / 医疗包 / 夹板等）：野外与基地皆可，**用药有使用动作**（期间无法射击）；
  2. **Bunker 内的 Doctor NPC**：**收费**治疗，同时清除辐射 / 止血 / **修护甲**；官方明说"**通常比烧药和维修包更划算**"——**这就是 ZS 实质上的"回血站"**；
  3. **Bunker 内的床**：**恢复 Fatigue（疲劳）** + **推进时间（"睡到早晨"）** + **睡满 +25% 体力恢复** + **消耗饥渴**——**⚠ R-42 口径订正**：ZS 床的**核心职能是"恢复疲劳 / 推进时间"**，**并非直接回 HP**；~~旧表述"恢复 Energy（精力）并跳过到早晨"~~ 属**术语误记**（把"Fatigue 疲劳"错记成"Energy 精力"；两者在 ZS 里不是同一状态轴）——**R-42 已订正为"Fatigue"**。**本作 Fatigue 不实装（用户拍板），故床的核心职能由"恢复疲劳"转为"推进时间 + 兜底回血"**（详见裁决 ⑳）。
  - ~~ZS 侧：**没有回血站/治疗 NPC**~~ —— **R-16 废弃**（说反了；Doctor 就是收费治疗点）。同理，基地**也不是纯粹的存储/改装点**，它是"**赛后整备站**"（治疗 + 修甲 + 补给 + 接任务）。
- **本作改动（属「主动差异化」，不是「照搬」—— R-16 更正标签）**：
  - **回血渠道收拢为两条（硬约束）**：① 使用药品消耗品 ② 基地双人床休息回血。**砍掉 Doctor 式收费治疗点**（本作无货币化治疗 NPC）。
  - **医疗室不再是治疗点（R-27 由 R5 迁至 R4）**，改为**制药工坊**：输入**药物原料**（搜刮所得）→ 输出**药品消耗品**（**R-19 扩为三轴，现 4 品种（⚠ R-34：消毒绷带已删）**：绷带 / 急救包 / 医疗包 / 抗毒血清，weapons-loot §3.10）。它是"生产设施"，与厨房（食材→食物）同构。**⚠ R-34：本作「强效药剂」已删，由「医疗包」替大回血槽（HP 回血轴 = 3 容量档：绷带 +20 / 急救包 +40 / 医疗包 +60）；原「消毒绷带」（hp+15/bleed−1/rot−5）亦已删，现 4 品种：绷带 / 急救包 / 医疗包 / 抗毒血清。**
  - **用药耗时**：绷带 1.5s / 急救包 3.0s / 医疗包 2.5s；期间**不可开火**（对齐 ZS 的"用药有代价"手感）。**⚠ R-34：本作「强效药剂」已删，由「医疗包」替（耗时 2.5s 沿用原强效药剂档）。**
  - **双人床的定位（对比 ZS 的床 · ⚠ R-42 更新）**：本作双人床 = **推进时间 + 兜底回血 + 存档（唯一存档点）**；**ZS 的床核心职能是"恢复 Fatigue（疲劳）/ 推进时间"**（~~旧表述"本作双人床恢复 HP、而 ZS 的床只回 Energy"~~ 属**术语误记**，已订正——ZS 的床主作用在 **Fatigue / 时间推进**，不在 HP）。本作 **Fatigue 不实装**（用户拍板"暂时不实装"），故床的定位**从"恢复疲劳"转为"推进时间 + 兜底回血"**——这是**有意加强**，用来补偿"砍掉 Doctor"后的兜底缺口、守住"无药死锁"（详见裁决 ⑳）。⚠ **若阶段 0 实测"双人床回血过强、撤退压力消失"，回退方案 = 向 ZS 靠拢：床只回精力 + 加速自然回血**（**该备注仍有效、保留**；但**背景已变**——ZS 的床本身即"恢复疲劳 + 推进时间"，本作是**不实装 Fatigue 后直接给全额回血**作兜底，故"回血过强"的风险**主要在回血强度一项、而非时间推进**）。
- **理由**：ZS 的紧张感来自"**血量不能免费恢复**"——想回血就必须消耗稀缺药品、或**付钱找 Doctor**，并承担用药中的风险窗口。本作砍掉 Doctor 后，把"**付费**"换成"**回基地 + 时间**"，保留稀缺性、去掉货币门槛。~~（本作前中期 Credits 更紧缺）~~ **⚠ R-32 订正：括号内的货币理由已删除**——`Credits`（局外货币）**已整体删除**，本作唯一货币 = 现金（仅交易时使用），"前中期货币紧缺"这一**附加理由不再成立**；**但主理由（去掉可反复使用的回血点 → 不削弱 P3 / P6）不受影响**。**关系支柱 P3（撤退张力）/ P6（经营动机）——去掉"可反复使用的回血点"，正是为了让这两个支柱不被削弱。**
- **代价与补偿**：
  - 代价：玩家更难恢复 → 挫败风险上升；**无药 + 无基地**时只能撤退。
  - 补偿：① 基地**双人床**是永久兜底（不存在"完全无法回血"的死锁）；② **药物原料可加工**，让"搜刮 → 制药 → 下水"形成正循环；③ 储藏室保底套装含**最低药品（绷带 ×2）**（death-and-corpse §6.4）。
  - **待验证**：阶段 0 需实测"药品稀缺度是否过苛"（并入 §6 原型清单 #4）。

### ⑧ 基地建筑呈现方式 → 保留「平面图 + 房间图标」（不照搬 ZS 的槽位网格）（R-16 新增）
- **ZS 侧**：基地是**物理避难所场景**（玩家在里面走动）；装 module 的流程 = **`J` 开 Device → 点房子图标 → 左侧空槽位网格 + 右侧 module 列表 → 长按 `Hold Here to Install`**。共 **6 个槽位、12 种 module**（Bedroom / Infirmary / Workshop / Ammo / Storage / Gym / Shooting Range / Garden / Forge / Recycling / Scavenger / Kitchen）。另需**先在工作台做出 Building Kit，再回背包 `Use` 安装**；**Storage 不可卸载**，其余可卸载但**不退材料**。
- **本作**：**保留既有设计，不改为槽位网格**——基地为**俯视平面图**（R1 常亮 + R2–R10 上锁），房间以**图标 + 名称**辨识（三处复用 A-19），进入后开**房间卡片**（ux-spec §3.5）。
- **理由**：① 本作基地是**叙事上的"安全屋"**（摩天大楼顶层、NPC 聚集、有人物关系），不是 ZS 的"功能槽位集合"；② 本作房间**有 NPC、有救援解锁**（**⚠ R-31 订正：房间不再有"等级（Lv1–3）"——建成即为完整状态**），属**内容载体**，槽位网格承载不了；③ **平面图与"百层垂直大厦"的空间叙事同构**（大厦 → 层 → 房）。
- **但从 ZS 借鉴的两点（R-16 已落地）**：① **图标/槽位的视觉语法**——同一套规格、随宿主变色（**A13**）；② **tooltip 惯例**——深色小面板 + 延迟出现/淡出 + 定位避让（**A14**）。
- ⚠ **可考虑借鉴（未决，R-16 挂起）**：ZS 的 **「长按确认安装」**（`Hold Here to Install`）——用于本作**高风险操作**（如"召唤末日之源"二次确认）比"点击 + 弹窗"更贴 ZS 手感。**待用户决定是否采用。**

### ⑨ 固定伤害链 → **加入射程曲线**（R-19 采纳 · **影响最大的一项**）
- **ZS 侧**：`weapon_glance_stat.json` 给**每类武器两条折线**——「距离 → **伤害倍率**」+「距离 → **后坐倍率**」。例：**霰弹 0–64 距离内 ×2.0**（贴脸爆发）、**步枪 0–70 只有 ×0.3、90–180 才 ×1.0**、**狙击 90 距离内伤害为 0**。同文件还有**类级基准参数**（准星回正 `recover_from_mouse_movement`：手枪 1.4 最快 → 狙击 0.65 最慢；`mouse_dis` 范围；ADS 射程倍率）。
- **本作改动**：`combat` 新增 **§4.8 射程曲线**（本作此前**完全没有距离维度**）——
  - 伤害链加入 `EffRangeDmgMult(dist, class)`；
  - 后坐加入 `EffRangeRecoilMult(dist, class)`；
  - 穿透衰减的 `RangeFalloff` 改名 **`FalloffEnd`**，取值 = 射程曲线**满倍率区间的远端锚点**（步枪 180 / 手枪 150 / SMG 90 / 霰弹 96 / DMR 250 / 狙击 500）→ **两个"距离"轴终于对齐**；
  - **准星回正修正为两层**：`ClassRecoverMult(类级基准) × (1 + WeaponErgo_m × k)`——**修正一处误记**（原写法把"手枪级回正快"错记为单枪 `Ergonomics` 属性）。
- **⚠ 本作特有风险（必须阶段 0 实测）**：**本作是 100 层楼内作战，玩家视野仅 128–160 px，绝大多数交火在 40–160 px**。ZS 的「步枪 0–70 只有 ×0.3」与「狙击 <90 归零」是**为开阔地图设计的**，**照抄会让步枪在本作最常见的距离上只有 30% 伤害、狙击整族废掉**。
  - **护栏 1**：步枪近距低谷从 `0.3` 抬到 **`0.6–0.7`**（保留曲线形状）；
  - **护栏 2**：狙击近距从 `0` 抬到 **`0.25–0.4`**（"打不出优势"而非"完全打不了"）；
  - **霰弹的「0–64 = ×2.0」非常适合本作**，可直接照用。
- **设计价值**：同一把枪在不同距离成为两把枪 → 逼出**位置意识**；且**"楼内环境"本身成了本作的差异化平衡杠杆**（ZS 做不到这一点）。

### ⑩ 单一「回血」轴 → **药品三轴（hp / bleed / 尸毒感染度）**（R-19 采纳）
- **ZS 侧**：药品是**四轴**——`hp`（回血）/ `bleed`（止血等级）/ `wound`（治伤等级）/ `radiation`（抗辐射）；关键事实：**`bandage` 的 `hp = 0`，只止血、不回血**，**只有 medikit 系列回血**；另有 `speed_multiplier` 控制用药时移速（0.5 = 减速一半，0 = **完全定住**）。
- **本作改动（用户拍板）**：
  - **改三轴**：`hp` / `bleed` / **尸毒感染度（`rot`）**——**第三轴由「辐射」改为本作原创的「尸毒感染度」**（僵尸 / 怪物的撕咬与抓伤累积，更贴合末日主题）；新增 `BleedLevel` 与 `RotLevel` 两条状态轴（combat §6.13；**⚠ R-36：`RotLevel` 计量简化为二值感染态 `RotInfected`**——变异体攻击且造成伤害时 **20% 几率**感染，不可药解、**仅战胜最终 boss 可解**）；
  - **`wound`（伤口）轴 —— 用户明确「取消」**：不引入 ZS 的第四轴（`med_wound_*` 只治伤不回血、且用药期间定住）。理由：三轴已足够构成分层伤情管理，第四轴对单人开发是净成本；
  - **普通绷带 `hp = 0`、只止血**（采纳 ZS 口径）；新增**消毒绷带**（hp +15 / bleed −1 / rot −5，⚠ R-34：已删，现 4 品种）与**抗尸毒剂**（rot −40，但**用药期间完全定住**）两个品种（**⚠ R-36：抗尸毒剂 → 抗毒血清**——职能由「`rot` −40 解毒」改为「**恢复 MaxHP 上限 +20 / R9 放大 +40，且不解除感染**」；改为**可制作稀有物品**，原料 = 僵尸血清 ×1 + 药物原料 ×1）（⚠ R-34：消毒绷带已删，原"两新增品种"现仅剩抗尸毒剂一新增品；全库三轴药品现共 4 品种：绷带 / 急救包 / 医疗包 / 抗毒血清）。
- **为什么这样分（设计增益）**：① **止血与回血分轴** → **出血不自行停止**（必须用药）→ **绷带从"劣质回血品"升级为"必需品"**；② **只有变异体造成感染**（⚠ R-36：改为**二值感染态 `RotInfected`**，攻击且造成伤害时 **20% 几率**，非 0–100 累积）→ 上层带**绷带 + 抗毒血清**、下层带**急救包 + 护甲**，**备战清单随楼层翻转**（P3 深化）；③ 回血成为最贵的职能 → 廉价药不再是万金油。
- **护栏**：⚠ 阶段 0 实测"三轴是否过苛"（关键指标：单层推进中"因无止血药 / 无抗尸毒剂被迫撤退"的比例）；**若过苛，上调掉率，而非合并轴**（合并轴会丢掉分层的设计价值）。**`RotLevel` 满值不直接致死**（避免“必然死亡”的挫败）。**⚠ R-35：**⚠ R-36：尸毒改为二值感染态 `RotInfected`**（变异体攻击且造成伤害时 **20% 几率**，不可药解、**仅战胜最终 boss 可解**）；**`RotInfected = true` 时每日结算 `MaxHP 上限 −5`**（持久 debuff；rot 清零后停降、已降部分默认不回复，⚠待调）——强化 `rot` 紧迫感、使“带抗尸毒剂下潜”成为硬约束；上限下降走 art-bible §7.1 上限刻度通道（损害档 ◀ 三角 + 数字文本 `当前/上限`），不靠变红（combat §6.13 / base-survival-npc §B.4 每日结算 / §B.8 AC51）。**避免"必然死亡"的挫败）。 **⚠ R-37 更新（★ ZS 无对应模型 · 本作独创）**——**取消 `MaxHP` 上限下限钳制**：**归零即触发「尸变终局 `RotEnding`」（Game Over · 可读档 / 开新档）**，与 `Victory` 并列**两条终局分支**。**这是对 R-35/R-36「`rot` 满值不直接致死」的有意升级**：**未感染路径**仍永不因尸毒归零（"避免必然死亡"对未感染者仍成立），但**一旦感染 + 不打赢 boss，最终必然走向尸变**——即**感染 = 硬倒计时 `ceil(上限/5)` 天**（唯一翻盘 = **好感度挽救线**：第一次尸变时 `Aff=100` 的 NPC〔**排除 NPC#1 艾拉**、多个取编号最小〕赠一支既有普通「抗毒血清」〔`antiserum`；⚠ R-47：不新增"珍藏版"独立物品〕并当场使用、续命一次，`SerumRescueTriggered` 存档级仅一次）。**ZS 无"归零即终局"的失败结局、也无"感情线救命"机制——此二者为本作独创设计**（见 progression §5 / base-survival-npc §B.8 AC52–AC53 / combat §6.13）。

### ⑪ 配件「加乘分离」→ **纯加减**（R-19 采纳）
- **ZS 侧**：`w_mod.json` **214 条全部是属性加减**（`acc +25` / `damage −2` / `recoil −22` / `ergo +6` / `magazine_size 30`），并有 `weapon_all`（通用件）与 `weapon_id`（专属件）两个限定字段。
- **本作改动**：`WeaponDamage_m = WeaponDamage + Σ(附件.damage)`（其余四条同构），**结算链中不再有 `Π(乘区)`**。
- **理由**：① 对齐 ZS；② **可逆**——卸载后精确回退（无乘区残差）；③ **不被大后期放大**（乘区叠加是数值爆炸的常见来源）；④ **可读**——玩家能直接算差多少后坐。
- **唯一例外（两处保留乘区）**：**消音器的听觉感知半径**（`×(1−0.4)`）与**镜的视野 / 射程倍率**（`scope_extend_view` / `scope_mult_eff_range`）——它们是**世界状态量 / 视野量**，不是武器属性。
- **连带待决**：⚠ 本作属性轴当前是**相对倍率**；若采纳 R-17 方案 A（改 ZS 的 **0–100 绝对值**轴），**附件数值须同步换算**（±25 量级）。

### ⑫ 「工作台修满耐久」→ **消耗维修包**（R-19 采纳）
- **ZS 侧**：修理要**消耗维修包道具**（`repair_weapon.json` 6 条 / `repair_armor.json` 2 条，结构 `condition_gain / condition_max / condition_min`），且**按 `caliber[]` 口径限定**能用在哪把枪上。
- **本作改动**：
  - **改消耗维修包**：每次修理消耗 ×1，回复 `condition_gain`（⚠建议 40–60）；**耐久上限受 `condition_max` 限制 → 修不满**（稀缺性保留）；
  - **取消按口径限定**（用户采纳）：改按**武器大类分三档**——`轻武器`（手枪 / SMG）· `制式`（步枪 / 霰弹 / DMR）· `重武器`（狙击 / 高口径），**护甲维修包独立**。
- **为什么取消口径限定**：本作**口径体系与 ZS 不同**，且按口径限定会造成"捡到一堆用不上的维修包"的挫败。**分档保留了"备货要对路"的决策，但不惩罚到细节。**
- **地点不变**：仍**只能在基地工作台**修理（野外不可修，裁决 ⑥ 保持）。
- **设计价值**：修理从"免费但麻烦"变成"要花资源" → 与**药品稀缺、弹药稀缺**共同构成"撤回基地经营"的**三重动机**（P6）。

### ⑬ 固定视野 → **敌人双轴感知（视觉 / 听觉）**（R-19 采纳）
- **ZS 侧**：`npc_preset.json` 有**两个独立字段**——`alert_visual_distance`（**视觉**：人类 220 / 250 / 300，变异体 60 / 110 / 170 / 220）与 `alert_radius`（**听觉**：人类 40 / 60 / 120）→ 即 **变异体靠听觉、人类靠视觉**。另有 `npc_recoil_value_multiplier = 0.02`（**NPC 后坐力只有玩家的 2%**）。
- **本作改动**：`enemies-ai §4.1` 由**单一 `SenseRange` 改双轴**：
  - **僵尸**：视觉 ≈60 / 听觉 ≈180（**听觉主导**——"绕开视线"不够，得**安静**）；
  - **怪物**：视觉 ≈110–170 / 听觉 ≈200（双轴并重）；
  - **雇佣兵**：视觉 ≈240–300 / 听觉 ≈60（**视觉主导**）；
  - **听觉触发不要求 LOS**（隔墙可闻）；**只被听觉触发的目标 `LoseTargetTime` 减半**（防"隔墙永久锁敌"）。
- **为什么这是"补上被浪费的一半价值"（关键动机）**：在固定视野下，**`Sub` 亚音速弹（听觉 −50%）与消音器对雇佣兵完全无效**——而双轴之后，它们**只作用于听觉轴**，于是"潜行 build"第一次真正成立：**压低听觉 + 用掩体切断 LOS**，而不是"隐身"。
- **与 P3 的关系**：**高层（僵尸）通关闭方式是"安静"**（听觉压力）；**低层（雇佣兵）是"掩体与枪法"**（视觉压力）——**同一套系统在楼上下产生完全不同的玩法**。
- **另记（未采纳但存档）**：`npc_recoil` 仅玩家 2% 说明"敌人几乎无后坐"是 **ZS 的刻意设定**——本作若要"敌人也会飘"，属**主动差异化**，需在 enemies-ai 明写（当前未定义，⚠待拍板）。

### ⑯ 敌人护甲与难度三段曲线 → 本作新增「机械敌人 + 敌我对称护甲判定」（R-23 新增）

**ZS 事实（实测 gamedata）**：
- `armor.json` **37 件护甲**：字段 `class`（1–6）、`pierce`（穿透阈值 0.10–0.60）、`dur_damage`（2–40）、`anomaly`/`radiation`（异常与辐射抗性）。
- `ammo.json` **39 种弹药**：字段 `pen`（穿透值 **7–71**）、`damage`。
- **判定 = 双轴交叉**：`pen ≥ pierce` → 全额伤害；否则大幅衰减。**这是"阈值判定"而非"百分比减伤"** —— 玩家必须换对弹种。
- **HP 弹 / AP 弹双轨**：HP 弹伤害 +15~+80 但 `pen` 低；AP 弹 `pen` 35–71 但伤害 −5~−15。**逼出弹种取舍**。
- ⚠ **ZS 的两处缺陷（本作须规避）**：① `class` 与 `pierce` **非严格单调**（`armor_killa` class 6 但 pierce 仅 0.25，"看着是重甲实际好穿"）；② `firearm__UNUSED` 字段**已废弃但数据残留**（0.13–0.53），属历史包袱。

**本作落地**：
1. **敌人持有护甲**（`ArmorClass` / `ArmorDurability`），**走与玩家完全相同的判定公式**（combat §4.1 ④）。**这是 R-23 新增的口径**——此前文档只写了玩家护甲的消费路径，**未明确敌人侧**。
2. **护甲分档**（本作原创重标定，strictly monotonic）：僵尸 Class 1 / 怪物 2 / 雇佣兵 3–4 / **机械 5–6**。见 enemies-ai §4.5。
3. **双路线战术**：① **AP 弹流**（一次穿甲，快但贵）② **磨甲流**（用普通弹耗 `dur_damage` 直至 `ClassEffective` 降为 1，慢但省弹种）。**两条路都对**——这是护甲机制带来的战术自由度。
4. **难度三段曲线**（R-23 用户拍板）落地见 **concept §4.1.1**：初期「打不死」（血厚数少·单挑） → 中期「被拉扯」（远程协同·地形） → 后期「打不穿」（护甲阈值·换弹种）。
5. **新增敌人：机械 Machine**（底层 10–1 专属）——**免疫尸毒 / 弱点头部核心 / 不受消音器影响**。见 enemies-ai §3.2.1。

**对齐与差异**：
| 维度 | ZS | 本作 | 理由 |
|---|---|---|---|
| 判定机制 | class + pierce × pen | **相同**（沿用） | 机制成熟、策略深度好 |
| class/pierce 单调性 | ❌ 非严格单调 | ✅ **严格单调** | 避免玩家困惑，可读性优先（P5） |
| 废弃字段 | `firearm__UNUSED` 残留 | ✅ **不引入** | 不背历史包袱（全新项目） |
| 护甲持有者 | 玩家 + NPC 均有 | **玩家 + 敌人对称** | 省一套系统；AP 弹价值可直觉推导 |
| 敌人类型 | 人类 / 变异 / 机械 均有 | **新增机械为第四类**（底层专属） | 服务"后期考验反应与战术"的曲线要求 |

**护栏**：
- ⚠ **对称护甲的生存压力**：玩家护甲在底层同样会被 Class 5–6 火力穿透 → **"升级装备"与"被穿透"同时发生**，生存曲线可能过陡 → **阶段 0 实测项**。
- ⚠ **反馈可归因**：被挡下必须有**火花/弹开音 + 护甲等级提示**，否则玩家会误判为"枪法不行"而非"弹种不对"，**破坏 R-22「以死为师」的学习回路**（combat §4.1 / ux-spec §3）。
- ⚠ **数值全部 ⚠待调**：ZS 的 1–6 档与 pen 7–71 跨度**不可直接套用**（ZS 无"100 层垂直递进"结构），须按本作曲线重标定（reference-alignment § 定位行）。

### ⑰ 商场地图空间语法 → 本作 5 种空间风格「S1–S5」（R-24 新增）

**ZS 事实（基于用户提供的商场地图）**：
- 该图（用户说明：**已缩小**，ZS 实机精度更高）是一张**商业综合体室内平面**，呈现六项可复用的空间语法：
  1. **网格状正交路网**——走廊成直角网格，非自由曲线；
  2. **房间沿街两侧排布**——店铺面向走廊开门，形成"街道"；
  3. **店内功能分区 / 货架岛**——家具成**岛状**布置（货架阵列、餐桌阵列），而非全部贴墙；
  4. **大型中庭**——图中央偏上有一个**大面积开敞空腔 + 环形廊道**；
  5. **多尺度房间**——从几 tile 的储藏间到数十 tile 的卖场，**尺度刻意跳跃**；
  6. **中央大堂 + 多出口**——多条路径交汇，非单线走廊结构。
- **关键观察**：ZS 这张图的价值**不在"某一种布局"，而在"同一张图内空间尺度的高度多变"**——它同时提供了窄过道（霰弹距离）与开阔中庭（远距对枪），而这**恰好对应本作"不同楼层适合不同武器"的需求**。

**本作落地**：
1. **抽象为 5 种空间风格（S1–S5）**，而非照抄一张图（见 procedural-gen §4.8.3）：
   | 风格 | 对应 ZS 特征 | `RoomSizeRange` | `Openness` | `CorridorMaxStraight` |
   |---|---|---|---|---|
   | **S1 蜂窝格状** | ①②（网格 + 沿街小房间） | 16–24 t | 0.15 | ≤24 t |
   | **S2 中庭环廊** | ④⑥（中庭 + 环廊 + 多出口） | 20–40 t | 0.35 | ≤40 t |
   | **S3 走廊鱼骨** | ②（沿街长走廊 + 单侧房间） | 12–20 t | 0.20 | **≤48 t** |
   | **S4 大平层** | ⑤（多尺度中的"最大尺度"） | 32–64 t | 0.30 | ≤32 t |
   | **S5 竖向迷宫** | ⑤（多尺度中的"最小尺度"密集化） | 10–16 t | 0.45 ⚠（多小空腔） | **≤16 t** |
2. **按楼层切分（用户原话）**："**对 ZERO Sievert 的这张地图按风格分割成不同的楼层**"——即**同一张图的六项语法，被拆散到 100 层的不同楼层**，每层强调其中一两种 → **楼层风格 → 适合武器**。
3. **玩法落点**：**S1/S5 → 霰弹枪**（贴脸遭遇）；**S3/S4 → 对狙**（长走廊 / 超视距）；**S2 → 步枪/SMG**（中距环廊）。玩家**下潜前看风格预告 → 换枪**（ux-spec §3.6）。**把 R-23 的"换弹种"推进到"换武器类型"**。
4. **`RoomTag`（房间用途）**：从 ZS 的"店铺类型"抽象为 5 类 + 1 通用（住宅/安保/餐厅/医疗/Boss 房/通用），决定家具/掩体/战利品倾向（procedural-gen §4.9）。

**对齐与差异**：
| 维度 | ZS 商场图 | 本作 | 理由 |
|---|---|---|---|
| 空间组织 | 单张图，一次性手工 | **参数化 5 风格，程序生成到 100 层** | 本作是 roguelite，需可重玩（P4） |
| 空间尺度 | 图内多变（窄过道 ↔ 大中庭） | **拆到不同楼层**（每层一个主尺度） | **让尺度成为"备战决策"**（用户核心意图） |
| 玩家视野 | ZS 视野较宽（可见大半个房间） | **受限 8–10 tile**（迷雾 + 拐角探头） | 本作是独立设计选择（**P1 逃生感 / P5 手感**） |
| 开阔度上限 | 中庭可占很大比例 | **≤0.35**（S5 用多小空腔替代大空腔） | 受限视野下大空腔会**摧毁迷雾张力** |
| 布局自由度 | 手工设计，可任意形状 | **受垂直骨架硬约束**（shaft cell 必须同 (x,y) 对齐） | 本作独有（vertical-traversal）：跨层绳索需结构对齐 |
| 房间用途 | 店铺类型（服装/餐饮/超市…） | **5 类 + 通用**（与基地 R3 厨房 / R4 医疗室 **无关系**） | 适配本作的家具/掩体/战利品体系 |

**护栏（本作相对 ZS 的三处必要偏离）**：
- ⚠ **视野差 = 迷雾张力**：ZS 的宽阔视野让它能容纳大中庭而不失紧张感；**本作视野仅 8–10 tile**，故 `Openness` **必须卡 0.35**，否则玩家站中庭一眼看掉 1/3 层，**P1（逃生感）与 P5（手感）双损**。
- ⚠ **风格 × 难度的耦合最易出错**：**豪宅层（僵尸"少而强·单挑"）绝不可生成 S4/S5 之外的远距风格**（S4 会让玩家在超视距外点掉慢速僵尸 → **直接摧毁 R-23 三段曲线的初期手感**）。见 procedural-gen §6.17。
- ⚠ **不得制造"无解风格"**：ZS 是**手工设计**，每张图都保证可玩；本作是**程序生成**，必须有脚本化验证"**仅带霰弹也能在 S4 层抵达楼梯间**"（P1 逃生感底线：打不过能跑）。
- ⚠ **骨架硬约束不可因风格让步**：若某风格与 shaft cell 布局冲突，**降级风格而非移动骨架**（骨架是存档级固化，跨层一致性优先，§4.10）。

### ⑱ 基地电梯井枢纽 → 参考 **Diablo II 小站（Waypoint）**（R-25 新增）

> **⚠ 本条不是 ZS 对齐**——它是**本作首次显式引入"非 ZS"的外部参考**，故在此登记并说明边界。用户 R-25 原话：「可以通过指定从某一层楼层开始探索等方式减少重复探索高楼层的时间（**类似 D2 的小站**）」。

**D2 小站事实（参考语义）**：
- **小站（Waypoint）** 分布在若干固定章节节点；**已激活的小站**可在**任意两个已激活小站之间双向传送**；
- **激活方式** = 玩家**亲自走到该小站**（一次性、永久）；
- **核心作用** = **跳过已探索区域**，把"重复跑图"的时间压缩为零，让玩家把时间花在**新区域**；
- **未激活的小站不可用**（必须先走到）——这防止玩家"未玩先跳"。

**本作落地（`BaseElevatorHub` · vertical-traversal §3.9）**：
| 维度 | D2 小站 | 本作基地电梯井 | 差异理由 |
|---|---|---|---|
| **节点位置** | 每个章节若干小站 | **只在基地（第 100 层）设一个控制台** | 本作是"单栋楼垂直下潜"，基地是唯一的"家"；多设控制台会让"撤"失去方向感 |
| **激活方式** | 走到该小站 | **抵达该层电梯井锚点**（`ExploredFloors`） | **同构**——都是"亲自到达才解锁"，且本作用电梯井锚点作点位（已有生成基础） |
| **传送方向** | 小站 ↔ 小站（**双向**） | **⚠ 非对称**：**基地端**可指定目的层速降；**楼层端只能脱出回基地**（**不能跳到其他楼层**） | ⚠ **本作最大的偏离**：D2 是"任意两站互传"，本作是**星形拓扑**（基地 ⟷ 已解锁层）。理由：楼层间直传会**架空 R-20 的"回基地 = 重开敌情"取舍**（vertical-traversal §3.9.7） |
| **激活持久性** | 存档级（永续） | 存档级（`ExploredFloors` / `HubOpen`，永续） | **同构** |
| **开设成本** | 无（仅需走到） | **需先制作逃生绳索 + 在基地安装（`RopeCable ×1`）** | 本作**把"解锁传送能力"本身做成了一个前置目标**（"制作出逃生绳索"= 用户点名的条件）——这是相对 D2 的**额外一层进度感** |
| **传送成本** | 无（免费） | **无（免费，R-25 用户拍板）** | **同构**——D2 小站也是免费的 |
| **未激活点可否前往** | ❌ 不可（不存在） | ✅ **可前往，仅给非阻塞警告** | ⚠ **本作的显式偏离**，理由见下 |
| **地图载入** | D2 为**分区场景**，传送 = 换场景 | **单层常驻 + 按需生成**：传送 = 换图触发器 | **同构**——本质都是"关卡流切换"，非空间连贯（本作 §3.9.0） |

**⚠ 本作相对 D2 的唯一显式偏离（记录）**：
- D2 中**未激活的小站根本不存在**（无"未探索目标"这一概念）；本作中**未探索楼层是"存在但危险"**的——玩家**可以看到、可以前往**，只是给警告「该楼层未经探索，贸然前往太过危险！」。
- **理由**：本作是 **roguelite + 搜打撤**，核心快感包含"**明知危险仍要下潜**"的赌徒式决策（P1 紧迫感）。若把未探索层**隐藏**，玩家会失去"我知道下面有好东西，但我准备好了吗"的**选择张力**；且会与 R-22「以死为师」（允许玩家因自己的选择而死）冲突。
- **硬约束**：该警告**必须是"警告"而非"门禁"**（ux-spec AC29 / vertical-traversal §3.9.5）——**玩家必须能真的选择前往**。这是本条第 1 优先级。

**落点**：vertical-traversal §3.9 · concept §7.1 / §P1 · ux-spec §3.6 · progression §4.1.1 / §5 · base-survival-npc §B.4 · death-and-corpse §3.3 · art-bible §10.2 / §10.2.1 · asset-spec §1.3.1


### ⑲ 时间系统 → **对齐 ZS**（R-42 新增 · 用户拍板「比例先参考 ZS」）

- **ZS 实测规格（查证 · 来源 = Steam 社区实测讨论）**：
  - **1 游戏日 = 6 现实分钟**；
  - 分 **6 时段**：`Dawn → Morning → Midday → Afternoon → Dusk → Night`，**每时段 1 分钟**。
- **本作采用方式（取消旧换算）**：
  - **❌ 取消「1 天 = 1 局」的换算**（旧口径**作废**）；
  - **楼层内（99–1 层）：时间按现实时间比例流逝**（**1 游戏日 = 6 现实分钟**）；
  - **基地内（第 100 层）：时间静止**（安全区，与 ZS 地堡一致）；
  - **双人床 = 唯一在基地主动推进时间的手段**（见裁决 ⑳）；
  - **结算口径**：原"按局"结算 → **按已流逝的游戏日**驱动——**回到基地时**按本趟经历的游戏日数结算；**基地内静止不结算**。
- **⚠ 必要偏离（本作相对 ZS 的显式偏离 · 记录）**：**本作不引入昼夜光照玩法**——6 时段**仅作时间刻度 / UI 显示**，**不影响能见度**（**ZS 的"夜间行动受限"不采纳**）。**理由**：本作是**室内垂直空间**（100 层高楼）——硬套昼夜会产生"地下 100 层哪来的白天"的**自相矛盾**。
- **落点**：ux-spec §3.2（HUD 时间读数）/ §3.5（双人床面板）/ §6.42 · art-bible §7.2（时间读数视觉规格）/ 禁忌 39 · base-survival-npc §A（饥渴按游戏内时间衰减）/ §B.3.1（双人床）。

### ⑳ 双人床 → **与 ZS 统一 + 必要偏离清单**（R-42 新增 · 用户拍板「和 ZS 统一」）

- **ZS 的床功能（多来源交叉 · gamerdigest · tryhardguides · shunshelter · mejores）**：
  - **恢复 Fatigue（疲劳）**（床的**核心职能**）；
  - **推进时间**（"睡到早晨"）；
  - **睡满 → +25% 体力恢复**；
  - **消耗饥渴**（睡醒后按流逝时间消耗饥渴）；
  - **卧室模块（Bedroom）**：**治疗小伤** + **加速技能升级**；
  - **不存档**（ZS 的床不承担存档职能）。
- **本作落地（与 ZS 统一 + 偏离）**：
  - **双人床 = 基地内唯一主动推进时间的手段**（基地时间静止，见裁决 ⑲）；
  - **交互 = 两个动作（不得合并、不得增删）**：**「休息」= 推进时间 + 按时间比例回 HP + 按时间比例消耗饥渴（同一动作）**；**「存档」= 独立交互**。
- **⚠ 本作相对 ZS 的 4 项必要偏离（逐条记录）**：
  1. **偏离 1 —— Fatigue 不实装**（用户拍板"暂时不实装"）：**ZS 床的核心功能（恢复疲劳）在本作缺席**，故床的定位从"恢复疲劳"转为"**推进时间 + 兜底回血**"；**留预留位**（未来实装时可加"恢复疲劳"动作）。**"睡满 +25% 体力恢复"随 Fatigue 一同缺席**。
  2. **偏离 2 —— 床保留存档**（ZS 的床**不存档**）：本作**双人床是唯一存档点**（基地内时间静止下的**纯进度快照**，不触发任何结算）。
  3. **偏离 3 —— 床保留全额回血**（ZS 的卧室模块**只治疗小伤**）：本作**靠床做"无药死锁"的永久兜底**（**HP 全额回**），**而非仅治小伤**。
  4. **偏离 4 —— 不引入昼夜光照 / 夜间受限**：本作是**室内垂直空间**（见裁决 ⑲），ZS 的"夜间行动受限"**不采纳**。
- **⚠ 附带（技能升级项不适用）**：ZS 的卧室模块"**加速技能升级**"在本作**不适用**——**本作熟练度 / 技能数值轨已整体删除（R-30 用户拍板，见 §0「明确不采纳」条）**。
- **⚠ R1 效率（好感度）× 双人床（R-42 修订）**：R1 效率作用由"**缩短休息回血耗时**"**改为"推进时间时的饥渴消耗折扣"**（`饥渴消耗 = 基础 ÷ EffectMult`，归入既有「消耗类 ÷ EffectMult」口诀）；**休息回血速率恒定、不受好感度影响**（守住"永久兜底"）。原 `BaseRestTime` 空占位符 → **`BaseRestRate`**（双人床回血速率，**数值由 base GDD 定**，本文件不自定义）。
- **落点**：ux-spec §3.5（双人床交互面板）/ §6.42 · art-bible §3.4（双人床 prop 语义注）/ §7.2 · base-survival-npc §B.3.1（双人床）/ §B.4（R1 效率）。

```
Recoil         // 后坐力（越大越差）：决定每次开火的准星漂移量
Ergonomics     // 工效（越大越好）：决定 ADS 时间、准星回正速度、切枪时间
FireRate       // 转速（RPM）
Magazine       // 弹匣容量
Caliber        // 口径（决定可用弹药）
Durability     // 耐久 0–100

// ── ADS 与收敛（对齐 A2/A4/A5）──────────────
AdsTime        = AdsBase / (1 + Ergonomics × k_erg)          // 工效越高，举镜越快
CrosshairRecover= RecoverBase × (1 + Ergonomics × k_erg2)     // 准星回正速度
StillTime      = 0.35 s（暂定）                                // 静止多久开始收敛
SettleBonus    = 最高 ×0.55（暂定）                            // 静止 + 持续 ADS 的收敛上限

// ── 后坐力 = 准星漂移（对齐 A3）──────────────
每次开火：  RecoilAccum += Recoil_effective
每帧：      CrosshairOffset 按 RecoilAccum 向"漂移方向"移动（非直接改散布角）
            RecoilAccum 以 CrosshairRecover 速率回落
移动中开火：额外 ×MoveRecoilMult（暂定 1.35）

// ── 耐久与卡壳（对齐 A8）──────────────────
DamageMult(Durability) = 0.75 + 0.25 × (Durability/100)      // 0% → 伤害 −25%
JamChance(Durability)  = 0；仅当 Durability < 70% 时：
                       = (10 − Durability/10) / 100          // 55% → 4.5%（对齐 ZS 量级）
排障：V 键 100% / 换弹 100% / 强行开火 30%（暂定）

// ── 护甲与穿透（对齐 A7）────────────────────
ArmorClass     ∈ 1..6（护甲自带）
ArmorDurability∈ 0..100（吸收时下降；Class 效果随耐久按比例衰减）
ClassThreshold(C) = 10 + (C − 1) × 8                         // C1→10 … C6→50
Pen(ammo, dist)   = AmmoPen × (1 − 0.40 × clamp(dist / RangeFalloff, 0, 1))
if Pen ≥ ClassThreshold:  减免 = 0                            // 穿透，直接打 HP
else:                     减免 = clamp(1 − Pen / ClassThreshold, 0, 0.80)   // 最多减 80%
DamageToHP = ceil(DamageDealt × (1 − 减免))
ArmorDurability −= k_armor × DamageDealt                       // 吸收即掉耐久

// ── 弹药类型（对齐 A6）────────────────────
PS  标准弹   ：伤害 ×1.00、穿透 ×1.00           // 通用
HP  空尖弹   ：伤害 ×1.25、穿透 ×0.50           // 对无甲/变异体最优，对护甲几乎无效
BP/AP 穿甲弹 ：伤害 ×0.85、穿透 ×1.60           // 对雇佣兵/护甲最优
Sub 亚音速   ：伤害 ×0.75、穿透 ×0.70、后坐 ×0.75、**感知半径 −50%**   // 静音向

// ── 射程曲线（对齐 A18 · R-19 新增，本作此前完全没有）──────
EffRangeDmgMult(dist, class)     // 距离 → 伤害倍率「折线」，线性插值（combat §4.8.2）
EffRangeRecoilMult(dist, class)  // 距离 → 后坐倍率「折线」，线性插值（combat §4.8.3）
FalloffEnd(class)                // 满倍率远端锚点：手枪150 / SMG90 / 霰弹96 / 步枪180 / DMR250 / 狙击500
ClassRecoverMult(class)          // 准星回正「类级基准」：手枪1.4 / SMG1.2 / 霰弹1.2 / 步枪1.0 / DMR0.8 / 狙击0.65

// ── 配件（对齐 A20 · R-19 改纯加减）──────────
WeaponDamage_m = WeaponDamage + Σ(附件.damage)      // 其余四条同构；无 Π(乘区)
// 例外（仍为乘区）：消音器听觉半径 ×(1−0.4) · 镜 scope_extend_view / scope_mult_eff_range
```

> **⚠ 射程曲线的本作护栏（R-19 · 最重要的一条）**：ZS 的曲线是**为开阔地图**设计的；本作是**楼内作战（视野 128–160 px，交战多在 40–160 px）**。因此：
> - **步枪近距低谷 `0.3` → 建议 `0.6–0.7`**；
> - **狙击近距 `0` → 建议 `0.25–0.4`**；
> - **霰弹 `0–64 = ×2.0` 可直接照用**。
> 阶段 0 必须实测（§6 #7）。

## 5. 弓弩（无声武器）— 后置定位（B 档）

> **明确不属于「照搬 ZS」范围**——ZS 无弓弩系统。这是用户指定的**后期差异化增量**，此处只锁定定位与机制边界，**阶段 0–3 不实现**。

- **核心卖点**：**完全无声**——比 ZS 系的「Sub 亚音速弹（感知半径 −50%）」更彻底（**不产生听觉事件**），给潜行/暗杀玩法留门。
- **机制边界（与枪械的区别）**：
  - 弹道为**实体箭矢**：有飞行时间，可选重力下坠（⚠待定，俯视角下可能过难）；
  - **弩矢可回收**：命中/落地后按概率回收（`BoltRecoverChance` ⚠待调），形成"省弹但慢"的经济循环；
  - **无枪声、无弹壳、无枪口闪**（视觉与音频代理需另做）；
  - **代价**：射速极低（单发装填）、箭匣/容量小、近距离散布大、**穿透中低**（对高 Class 护甲劣势）。
- **数据落位**：仅需在 weapons-loot 保留**分类位与字段**（`Caliber = bolt`、`Silent = true`），不实现具体武器。见 weapons-loot §3.9。
- **Tier**：**B 档**（资源充裕再加，不影响主线）。

## 6. 阶段 0 原型验证清单（「照搬 ZS」必须实测的 **9 项**）

1. **投射物 vs hitscan**：飞行时间在 16 px 尺度下是否可读？命中反馈是否模糊？→ 不通过则回退 hitscan（② 的护栏）。
2. **准星漂移手感**：Recoil 驱动的准星漂移 + Ergonomics 回正，是否比"固定散布角"更有"可控感"？（A3/A4 的成败关键）
3. **静止 + 持续瞄准收敛**：收敛幅度是否足以形成"站定点射 vs 移动泼洒"的清晰策略分层？（A5）
4. **弹药稀缺 × 无近战**：弹药掉落率是否需要上调？（§4 风险）
5. **卡壳节奏**：卡壳频率与排障时长是否"有压力但不烦躁"？（A8）
6. **药品稀缺度 × 无回血站（R-14 新增）**：回血只靠"药品 + 双人床"时，**药品掉率与用药耗时**是否造成"过苛"？关键指标：单层推进中"因无药被迫撤退"的比例。→ 若过苛，上调药物原料/绷带掉率，**而非增设回血点**（增设回血点会破坏 ⑦ 的张力来源）。
7. **射程曲线 × 楼内交战距离（R-19 新增 · 最需要实测的一项）**：本作交战集中在 40–160 px，而 ZS 步枪在此区间只有 `0.3–1.0` 倍。**关键问题：步枪在楼内是否"打不动"？狙击是否"完全不能用"？**
   - 若"软" → 按护栏抬高低谷（步枪 → `0.6–0.7`；狙击 → `0.25–0.4`），**保留曲线形状**；
   - 若"曲线感很强、位置意识成立" → 直接进入阶段 1；
   - **关键指标**：同一把步枪在 40 px / 90 px / 160 px 三点的击杀所需弹数差异（目标：≥ 2 倍差异，否则曲线没被感知到）。
8. **药品三轴的可理解性（R-19 新增）**：玩家能否在**不看说明书**的情况下理解"绷带不止血之外的用途、抗毒血清治什么（**⚠ R-36：抗毒血清已"不解毒"，只恢复 MaxHP 上限——"治什么"的答案变成"续命"而非"治愈"**）"？
   - **关键指标**：试玩中"带着出血状态继续下潜"与"带错药"的发生率。**过高 → 是 UI 问题（角标/提示），不是机制问题**（不要退回单轴）。
9. **双轴感知的可利用性（R-19 新增）**：**"消音器 + 切 LOS" 是否真的能让玩家躲过雇佣兵？**
   - **关键指标**：装配消音器后"首次被发现的平均距离"是否显著下降；僵尸是否会被"隔墙的枪声"有效吸引（听觉轴要有存在感）。
   - 若"听觉太强"→ 上层被迫全程摸行、节奏拖沓；若"太弱"→ 消音器与 Sub 弹的 value 归零。
